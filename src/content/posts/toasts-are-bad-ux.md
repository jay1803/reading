Just in some case toast might not be the best indictor for response user's actions.

The examples are:
1. when you archive an email in Gmail, there's a toast tell user the email has been archived.
   Consider this is a duplicated indicator since the email has been removed from inbox, which is a indicator that user's action is execuated, so there's no reason a toast tell user about it.

   In material design, sometimes the toast might contains a [undo] button, in Gmail case, which might be useful. BUt it's undo, I perfer user cmd+z for this action, better than a button.

-----

So toast is not that bad, only designer used badly.
