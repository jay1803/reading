ENIAC 没有 BIOS，但要解释这个答案，必须区分基本输入输出功能、启动机器的引导程序，以及后来被称为 BIOS 的软硬件层。Alan Kay 认为，ENIAC 连存储程序计算机都算不上，尽管它能用一些技巧模拟相关能力；他同时提出，判断一个程序是否承担 BIOS 的作用，不应只看它是否固化在 ROM 中，还要看它实际完成什么功能。

直到 1960 年代，许多计算机冷启动时仍没有任何可执行代码，需要操作员先用拨动开关输入几条指令，让机器读取纸带，再由纸带载入更多程序。早期 DEC 计算机普遍采用这种方式，1964—1965 年前后的 CDC 6600 则配有专门的冷启动开关面板。评论者 Paul McQuesten 指出，CDC 6X00 面板上十二行、每行十二位的开关，本身就定义了它的 **deadstart 程序**。这类机器已经具备逐级装入代码的启动链，只是链条的起点需要人手设置。

不过，手动输入引导程序并不意味着每次开机都要重新拨开关。Hacker News 讨论补充，PDP-11 等采用磁芯存储器的机器能在断电后保留程序，已经输入的 loader 通常可以跨越多次电源开关继续使用；后来用 RAM 替代磁芯的方案，也曾通过电池供电维持这种持久性。Scott Welch 回忆自己在 1985 年仍为 PDP-11/70 手动输入约三十条引导指令，说明这种操作延续了很久，却不能据此推断它是所有机器日常启动的必经步骤。

把最初的启动代码预先固定在硬件中的做法，同样远早于 IBM PC。讨论者 retrac 举出 1949 年的 EDSAC：其 "initial orders" 由一组旋转选择开关设定各存储字的八进制数值，相当于启动 ROM。David Wheeler 把有限容量用于纸带加载器和微型汇编器，让机器从纸带继续加载程序。DEC 后来也为 UNIBUS 提供可选的引导 ROM 卡，早期 BM792 使用 32×16 位二极管矩阵，靠手工移除二极管设定代码；后来的 M9312 使用容量为 512 字的 PROM，并加入基本 CPU 诊断功能。这些例子表明，启动功能可以由开关、二极管矩阵或 ROM 承载，BIOS 这个名称出现的时间无法代表相关功能的起源。

Kay 援引 Wikipedia，把 BIOS 的正式命名追溯到 1975 年的 CP/M，把现代常见含义追溯到约 1981 年的 IBM PC，并称两者都基于 ROM；评论区对 CP/M 的部分作出了关键纠正。CP/M 的 BIOS 是操作系统中面向具体硬件的基本输入输出层，通常保存在启动软盘的前几个扇区，启动时读入内存。ROM 中可能只有负责最初磁盘读取的小型 boot loader，部分机器还带有找不到磁盘时进入的调试 monitor。评论者也指出，一些运行 MS-DOS 的机器会从磁盘把 BIOS 装入 RAM，因此更新可以通过更换启动盘完成，无须重新烧录芯片。**BIOS 作为硬件适配层，与存放在 ROM 中、负责启动机器的固件，在历史上并不完全重合**；随着术语含义漂移，两者才越来越容易被混为一谈。

ENIAC 是否属于存储程序计算机，也存在需要按时期和定义拆开的争议。Hacker News 评论者指出，它在 1948 年改造后、直至 1955 年的使用期间，已能以某种存储程序方式工作，因此反对 Kay 对整台机器的一概判断。另一位讨论者进一步限定：改造后的指令通过 function table 的旋钮设置，省去了原先大量接线工作，却仍属于人工配置；穿孔卡负责数据输入输出，并不用于装入程序。其基本 I/O 路径也很直接：卡片数据先进入 constant transmitter，再复制到二十个累加器之一，输出则反向进行。这样的结构没有后来围绕磁盘控制器和操作系统加载形成的 BIOS 层。

围绕存储程序概念的争论，还牵涉技术归属与专利利益。讨论中有人重述 Eckert 和 Mauchly 的主张：他们认为存储程序思想由自己提出，von Neumann 的《First Draft of a Report on the EDVAC》使相关贡献被归到他名下，报告的公开也妨碍了他们申请存储程序专利。这与 ENIAC 的分类问题相互关联，却不能代替对其实际编程方式的判断。整场讨论最终揭示的是三个需要分别追踪的历史问题：机器怎样获得第一批指令、程序如何表示和保存，以及操作系统怎样隔离硬件差异；用今天的 "BIOS" 一词统称它们，会掩盖早期计算机之间真正重要的结构差别。
