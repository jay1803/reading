## TL;DR
微软这次被市场重罚，表面上是 Azure 增速不及预期、AI 资本开支过猛，深层上是 AI 正在同时改写软件的供给、定价和使用方式，直接冲击微软最赚钱的两套逻辑：按席位收费的生产力套件，以及把算力优先卖给外部客户的云业务。作者判断，微软大概率仍会是幸存者，但前提是主动牺牲一部分 Azure 的短期增长，把稀缺 GPU 优先投向自家 Copilot、代理层和新软件扩张。

## 关键洞察
AI 写代码之所以危险，在于它高度贴合“概率生成 + 确定执行”的结构：代码能运行、能测试、能调试，所以软件生产本身极可能被 AI 大幅压缩成本。可这不等于企业会大规模自己写软件，因为大多数公司的核心能力并不在软件，真正麻烦的也从来不只是首版代码，而是后续维护、安全、合规、集成和支持。因此，短期内先受益的往往不是买方，而是软件公司自己：它们可以用 AI 更快、更便宜地造出更多软件。

真正的冲击来自相对供给，而非绝对替代。当每家软件公司都能更低成本地生产更多功能，过去十年靠“找一个业务环节、做一个 SaaS、切出一个垂直市场”就能成立的增长叙事会失效。企业未必愿意买更多软件，反而可能要压缩软件预算，把钱留给模型调用和 token。结果是行业从“做大蛋糕”切到“争夺现有预算”，厂商会更积极地打相邻市场、捆绑更多功能、提高客单价，而模型提供方则像军火商，向所有参战者卖武器。

代理会把这场竞争再推深一层。每个 SaaS 都会做自己的 agent，但单应用 agent 天然受限于产品边界；真正有机会成为上层协调者的是那些能跨应用理解组织、权限、历史和工作上下文的水平层。微软把 Work IQ 建在 Microsoft 365 的身份、角色、文档、通信和权限之上，这一步很合理，因为 Active Directory 长期就是微软捆住企业栈的关键锚点。

但这个锚点也在被 AI 削弱。若组织内真正需要付费的人类席位减少，围绕身份和 seat 的商业模式就会被侵蚀。于是微软必须更快地吃进更多业务场景：覆盖面越大，agent 能调用的上下文越丰富，产品越难被替代，微软越能抬高定价，也越能迫使其他软件厂商围绕它的 agent 接口协作。

这正解释了微软这季度为什么宁可让 Azure 增速失手，也要把 GPU 先分给 M365 Copilot、GitHub Copilot 和内部研发。对华尔街来说，这是增长失速；对微软自己来说，这是把稀缺算力投向更高毛利、更高生命周期价值、也更具防御意义的位置。连研发本身都已开始依赖大规模算力，因为扩张产品边界越来越需要用 AI 来写新软件。作者因此认为，微软的资源分配在战略上是对的，只是市场先按季度指标惩罚了它。

这也暴露出两个更大的结构性问题：第一，GPU 供给不足已经足以让一家巨头单日蒸发数千亿美元市值，未来 AI 需求继续扩张后，芯片约束只会更硬；第二，超大云厂商会优先满足自家产品，再轮到外部客户，这让“纯代工式 token 产能”比作者此前想象得更有价值。换句话说，AI 时代的云不再只是中立基础设施，也会是与客户直接竞争的参与者。

## 一句话总结
AI 不会先杀死微软，但会先杀死过去十年那套靠席位收费、功能孤岛和无限扩张支撑起来的软件增长叙事；微软能否穿越，取决于它能否把身份层优势和算力优先权变成代理时代的新控制点。
