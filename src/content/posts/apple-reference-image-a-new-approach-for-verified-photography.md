Apple Reference Image 把照片的真实性证明延伸到传感器采集、计算摄影处理和最终签名的完整链路，让一张照片能够证明：它确实来自 iPhone 摄像头在某个可验证时间区间内捕获的光学信号，同时不公开摄影者身份。这个可选拍摄模式首发于 iPhone 18 Pro 和 iPhone 18 Pro Max 的主摄，通过设备端生成受硬件保护的数字底片，再交给 Private Cloud Compute（PCC）显影，最终输出可验证、可撤销的参考图像。

这套设计回应的是生成式 AI 与计算摄影共同带来的信任难题：逼真的画面已经无法证明事件发生过，而摄像头输出的原始像素又必须经过 demosaicing、镜头阴影校正等处理才能成为可观看的照片。仅给原始像素签名，无法保证后续处理忠实；等处理完成后再签名，则给传感器总线上的数据注入和操作系统篡改留下空间。Apple 指出，基于 C2PA 的现有方案主要在采集后附加来源元数据、认证后续编辑历史，链路中任一环节被攻破，都可能产生观看者无法识别的伪造认证；将照片绑定到设备或个人的公开凭证，还会增加冲突地区摄影者的身份暴露风险。因此，系统必须同时满足**语义真实性、抗攻破能力与隐私保护**。

真实性链路从传感器本身开始。用户进入 Reference mode 后，传感器重新安全启动到专用采集模式，在光信号数字化后立即用内部私钥对像素和嵌入的元数据摘要签名，并禁止传感器固件修改采集数据。操作系统在这个模式下只能提供一个放在固定元数据位置的 SHA-256 摘要，其中绑定最近的可信时间戳、设备硬件 manifest 和 secure boot manifest。传感器生成的元数据与像素一起签名；来自摄像头系统的数字变焦、曝光和镜头参数，则由 Secure Enclave Processor（SEP）连同传感器签名的承诺值再次签名。这些外部元数据不能改写像素本身，使操作系统即使被攻破，也无法任意替换底片内容并通过后续验证。

拍摄时间通过**可信区间**表达，避开对操作系统时钟的依赖。设备借助 Apple Push Notification Service（APNs）的连接心跳持续收集 Apple 时间戳服务提供的 RFC 3161 token，全球平均间隔约为 15 分钟，实际受网络条件影响；拍摄前收到的最新 token 被绑定进传感器签名，提供时间下界。拍摄后，设备将 SEP 签名的 SHA-256 承诺值交给时间戳服务，取得证明照片已存在的时间上界。离线时，后台进程会持续尝试补取上界，因此断网可能扩大可证明的时间区间。像素、两层签名、时间戳、元数据和两个 manifest 一并保存在 DNG 格式的安全数字底片中，与常规摄影流程生成的照片关联；底片可以长期留存，也可以在尚未显影时分享。

硬件身份验证进一步防范拆卸传感器等攻击。制造阶段，传感器自行生成 ECDSA P-256 密钥对，私钥始终不离开传感器，工厂只取得公钥并由工厂 CA 签发证书。SEP 独立生成由 Basic Attestation Authority（BAA）认证的密钥，第三个 CA 再签署设备 manifest，将传感器与 SEP 的身份绑定为同一台 iPhone。显影时，PCC 验证传感器、SEP 和设备 manifest 的签名及证书链，重算像素内嵌的摘要，并检查传感器与 SEP 是否属于同一设备；所有检查通过后才继续处理。这让传感器签名的可信性同时依赖其合法来源与合法设备配对。

从底片到可观看照片的处理在 PCC 内完成，包括 demosaicing、tone mapping、相关校正和 JPEG 压缩。PCC 的每个生产软件版本都记录在仅可追加、以密码学防篡改的 transparency log 中，二进制文件公开供检查；设备只向能够证明自己运行日志内版本的节点上传底片，使外部专家能够审查显影算法是否忠实于采集数据。时间戳也在此阶段验证：下界无效时，系统采用功能尚未存在之前的 2026 年 3 月 31 日作为下界；上界缺失或无效时，采用 PCC 当前显影时间作为上界。因此，时间证明在凭证不完整时会退化为更宽的区间，并不一律拒绝显影。处理成功后，底片自动进入已删除照片文件夹，用户可恢复保存或立即删除，否则 30 天后清除。

系统还为硬件与密码学防线失效准备了检测和撤销机制。PCC 使用权重不公开的 neural network，评估底片是否具有 Apple 传感器原始输出应有的物理特征，生成 confidence score；显影后的 JPEG 被哈希，其哈希既构成待签名的承诺值，也提供 photo GUID 的生成位。PCC 将 GUID、raw hash、confidence score 和 sensor ID 发送给配套服务，记录照片与传感器的对应关系、更新该传感器的累计评分，并检查撤销状态。系统可以撤销单张照片，也可以撤销某个传感器产生的全部照片；传感器一旦被撤销，PCC 就不再为其图像签名。这里，公开可审查的显影代码与权重隐藏的异常检测模型承担不同职责，后者是额外的真实性筛查防线。

通过验证的 JPEG 最终由 Apple 签名服务使用 MLDSA87-RSA-3072-PSS-SHA512 混合方案签名，将 RSA-3072 与 ML-DSA-87 组合，保护公开参考图像的长期完整性。Apple 强调，2026 年发布的认证照片可能在多年后仍需验证，因此最终资产的签名需要抵抗未来量子攻击；传感器和时间戳环节仍使用 ECDSA P-256，后量子保护的重点是公开分发的参考图像。客户端每次展示参考图像时，都会验证 JPEG 的最终签名，并检查 photo GUID 是否出现在当前撤销列表中，使后来发现的伪造照片能够被追溯标记。

隐私保护通过分离公开证明与内部追责实现。最终图像携带 Apple 服务的签名，不公开摄影者或传感器凭证，外部观察者无法据此判断两张照片是否来自同一设备。PCC 的架构限制使 Apple 也无法访问处理中的图像像素；撤销服务保留 GUID 与传感器的私有对应记录，但无法取得图像内容，也不公开这份记录。观看者在设备端使用定期更新的撤销列表检查有效性，不必向服务报告正在查看哪张照片；时间戳请求经过 Oblivious HTTP，时间戳服务无法得知请求设备的 IP 地址，签名与撤销服务的调用则由 PCC 发起，只携带运行所需的最少信息。

这套机制把真实性的依据从照片外观推进到可核验的采集与处理过程，并让匿名发布和事后撤销能够共存。它证明的是特定传感器在可信时间区间内捕获了哪些光学信号，以及最终图像如何由这些信号生成；画面中事件的背景、是否摆拍或现场是否具有误导性，仍超出这条技术证明链的范围。其核心价值，是为“这张图像确实来自一次摄像头采集”建立可审查、可长期验证、也可在发现攻破后纠正的信任基础。
