## 嘉宾背景
Alex Cornell 是 Meta 的设计director,主导消费级 AI agent Muse 的设计工作。他有长期软件产品设计背景,曾任创业公司创始人,过去一年主要负责打造 Muse 的 agent 界面——包括自定义头像、三层状态展示、个性化 Ideas 入口与生成式 Feed。他在 Threads 上持续公开分享这些设计决策背后的思考。访谈主持人为 Claire Vo。

## TL;DR
Muse 的设计围绕一个变化展开:当 AI 能主动发消息、在后台持续工作时,产品就不再只是一个等待提问的聊天框。Alex Cornell 介绍了团队如何用熟悉的通信模式和稳定的界面结构承载这些能力,以及他如何让 Muse 把个人收藏、旧记录和爱好数据重新组织成值得浏览、能够使用的内容。

## 把 Agent 视为持续交往的对象,而非一次性问答工具
Alex 说,团队反复使用的设计参照,不是其他 AI 应用,而是"如果正在与另一个人交流,这件事应该怎样发生"。Agent 可以在一天中的不同时刻主动联系用户,因此 Muse 保留了消息气泡,帮助用户辨认不同消息的边界;屏幕顶部的角色形象则给这段交流提供一个明确的对象。后台工作状态也由此成为重要元素:对方不说话时,用户仍需要知道它是否正在处理事情。

这种框架也决定了聊天架构。Muse 有一条被刻意设为主要交流渠道的主聊天,Alex 认为,随着模型能够处理更长的上下文,用户可以像与同一个人持续通信那样,把许多事情都放在这里,而不必每次开启新会话。侧聊天则用于隔离范围明确的任务,或者把某些内容移出主线,也照顾了已经习惯用线程整理工作的用户。

但 Alex 并未把这套架构视为定论。主持人自己就不确定什么时候该用主聊天、什么时候该开侧聊天;他承认,这也是普通用户完全合理的疑问。当前方案展示了连续主线的好处,却还需要进一步帮助用户组织任务、理解两种聊天的分工。持续关系与清晰分类之间的张力,仍是他认为值得探索的设计问题。

## 让用户知道 Agent 没有失联,同时保留检查过程的入口
Alex 用状态展示说明渐进披露如何服务不同用户:最外层只告诉用户"正在工作",下一层说明正在做什么,例如寻找南瓜采摘地点;点击后可以查看已执行的行动,再深入才会看到代码、curl 命令等细节。普通用户不必理解底层操作,也能知道任务正在进行;需要检查、审计的人则仍有入口追溯执行过程。他认为,把大量过程信息直接放进主聊天会制造噪声,不应仅仅因为其他 AI 应用这样做,就默认所有人都需要看到。

主持人指出,过程展示有时也是缓解延迟的办法:用户真正难受的,是不知道 Agent 在推进任务,还是已经卡住。她对 Muse 的正面体验既来自渐进披露,也来自响应本身很快。Alex 则补充,速度过快偶尔也会引起另一种怀疑——它是否真的出去做了事情。这是他描述的使用感受,而非对速度与信任关系的普遍结论。

面对复杂请求,Muse 有时会先用一个表情回应或简短消息确认接收,再去执行耗时工作。Alex 将其类比为人与人的协作:接到困难任务后,不会一直沉默到完成,至少会让对方知道自己已经接下来了。之后,状态显示继续提供进展;用户若怀疑任务停滞或方向错误,可以深入查看。这里需要平衡的不是"展示多少步骤"这一个问题,还包括何时回应、先说什么,以及等待期间如何保持联系。

## 非确定性的 AI,让设计控制转向稳定框架
Alex 认为,进入 AI 产品设计时最需要适应的,是非确定性系统。传统软件中,设计师通常能够预先规定某个功能如何呈现,用户屏幕上的结果大体可预测;而每个人的 Muse 都有不同的个人背景、任务和生成内容,设计师无法再逐一控制所有结果。因此,他把更多注意力转向底层系统、架构和支撑框架,而不是要求每个局部产物都完全符合预想。

主持人观察到,Muse 的生成式界面并不是每次打开都重新安排全部按钮和布局,而是在稳定结构里生成变化:头像、状态、Ideas 和 Feed 等核心元素保持可辨认,具体建议、状态文字和角色动作则随用户与任务变化。Alex 以头像为例:即使用户把助手设成一个番茄,它也会以番茄的形象出现在打字、制作东西等状态中,既延续角色身份,又体现个性化。他同时明确,Feed 的展示单元仍由团队设计,并不是一个完全生成的界面;当前的生成能力仍被放在相对明确的边界内。

这种调整也发生在他对生成产物的评价上。面对自己展示的仪表盘和页面,Alex 有时需要暂时放下设计师对颜色、细节的执着。他当然可以继续修改到完全满意,但也开始接受:一个结果即使没有达到个人审美上的精确要求,仍可能已经非常有用。这不是认为视觉质量不重要,而是他逐渐学会不让精修要求成为使用这些产物的前提。

## 个性化建议,让用户发现与自己有关的能力
Alex 认为,Muse 理论上可以只保留聊天,因为一个足够强的 Agent 能在单一会话里处理很多事情;但"能够完成"不等于"用户知道可以这样要求"。新技术的能力对普通人并不直观,只有输入框,仍然意味着用户必须自己想出用途。Ideas 因此承担了具体职责:把用户可能尚未意识到的能力呈现出来。

关键区别在于建议是否与已有交流有关。通用示例也可能有帮助,但如果用户一直聊高尔夫,接着看到与高尔夫有关的任务建议,就更容易理解这些能力能怎样进入自己的生活。Alex 提到,母亲已经开始使用 Muse,甚至会为让它工作太多而道歉、感谢它的帮助;对他而言,这件事令人欣慰,因为过去自己参与制作的软件很少进入母亲的日常使用。

Feed 则允许用户通过提示继续试验内容组合。Alex 会调整自己的 Feed,厌倦某类新闻后换一个主题,周末也会尝试与孩子有关的内容。他鼓励用户多做这种实验:不是把现有入口当成固定菜单,而是尝试表达自己想持续看到什么,让个人兴趣成为探索 Agent 用法的起点。

## 改变组织与呈现方式,让沉睡的个人资料重新进入生活
Alex 的 Instagram 收藏积累了很多年,却很少回看。他先让 Marlowe 把收藏分门别类,再依据这些材料提出购物和礼物建议;随后,又把原本普通的文字建议做成带有 SkyMall、Sharper Image 杂志风格的购物目录。这种视觉语言对作为九十年代孩子的他有特别吸引力,使每天刷新的建议本身也成为值得浏览的东西。不过,他说明,这份目录尚未接上便捷购买流程,主要仍是一个自己喜欢看的产物,而非完整的购物闭环。

主持人从创作角度补充,Instagram 和 Pinterest 本来就包含丰富的个人视觉偏好,只是过去不容易拿来进一步处理。她会让 Agent 查看收藏板,基于这些参考生成概念,或者帮助找到描述这种风格的语言。Alex 则把自己收藏却从未重新阅读的数百条高尔夫技巧,汇总成一份个人手册:原本分散的内容终于获得了一个可以重新使用的形态。

类似的变化也发生在回忆材料上。Alex 将过去的 Instagram Stories 组成随机回顾的 Feed,自己一天会看几次,尤其喜欢看到女儿成长中的片段。他还让 Marlowe 寻回散落于旧博客平台和网页存档中的文章,先汇成 PDF,再做成类似博客的页面;但真正符合他现在习惯的形式,是每天早晨收到一段随机朗读的播客。听到二十年前自己提出的古怪问题,他既觉得陌生,又发现自己今天仍会认同。

Alex 自己归纳了这些案例的共同点:材料早已存在于生活中,只是原来的呈现方式没有让他继续使用。Muse 对他的价值,不仅是找回资料,还在于把它们改造成当下觉得有趣或有用的形式,给旧内容一个重新被打开的理由。

## 把爱好记录变成复盘与长期追踪,但分析不能代替练习
Alex 已经通过高尔夫服务、手表和练习设备积累了球场、成绩、逐杆表现及挥杆数据。Muse 的作用不是从零开始记录,而是把这些记录组织成解释。他设置了每周检查,打完球后可以收到回合复盘:图表让前九洞表现很差、后九洞明显改善的过程一目了然;在反复打过的球场上,还能比较同一球洞过去与当天的表现。演示中的分析也尝试指出,哪些地方若处理得更好,可能让那轮成绩从 84 杆变成 79 杆,而不是只展示最终分数。

练习时,他会使用多种设备监测挥杆,但对设备输出的专业指标只是部分理解。Muse 帮他拆解练习内容,说明哪些表现不错、哪里可以改善,以及接下来需要关注什么。这些单次反馈又被放进一个持续目标里:他希望达到个位数差点,并让 Muse 知道相关活动都与这个目标有关,使后续交流不必每次重新说明方向。

国际象棋的用法相似。他通过聊天提出需求,希望同时看到近期棋局分析、长期趋势,以及最近一局究竟错在哪里。生成的仪表盘提供逐局复盘,也让他判断自己是否在进步;其中还出现了他没有特意要求的调侃语气,让这个"棋教练"显得有些刻薄,但他觉得有趣。

这些用途并不意味着成绩已经改善。Alex 坦言,工作让他很少有机会打高尔夫,每周自动检查往往等不到新记录,长期目标也没有什么进展;演示中的最近一盘棋,则因为女儿回家而中途退出,分析的帮助因此有限。访谈展示了数据怎样变成更容易理解的反馈,却没有验证这些反馈最终带来了多少实际进步。

## 提到但未深入展开的话题
两人还简短聊到角色昵称与孩子、玩偶的私人关联,表带等购买经历,以及新专辑、演出、品牌联名和电影票提醒;主持人提到定期检查购物清单的降价情况,双方也谈到比价和购买前研究。面对 Agent 出错,Alex 通常仍礼貌表达不满,也猜想更强硬或许有用,但没有提出经过验证的提示策略。结尾还介绍了通过 Muse 提交产品反馈、在 Threads 关注设计幕后,以及节目赞助和订阅信息。
