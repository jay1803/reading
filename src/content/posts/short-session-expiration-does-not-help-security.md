## TL;DR
传统的安全建议主张使用较短的会话超时时间（如15分钟不活动后自动登出），但许多大型网络应用（如Gmail、GitHub）和移动应用却允许用户长时间保持登录状态。文章探讨了这种做法的安全性，认为过短的会话超时并不能有效提升安全性，反而可能带来用户体验和安全上的负面影响。

## 主题

### ⏰ Session Timeout 的常见做法与争议
Web 应用通常会在用户登录一段时间后或一段时间不活动后使会话过期。安全建议通常主张较短的会话超时，例如 15 分钟不活动后。然而，许多大型 Web 应用和移动应用并不遵循此建议，允许用户长时间保持登录状态。

### 🛡️ 威胁模型 (Threat Model)
威胁模型涉及攻击者未经授权访问用户的活动会话。这可能通过窃取 Session Cookies、利用 Session Fixation 漏洞或使用与受害者相同的设备来实现。

### 💥 XSS 攻击
如果攻击者通过 XSS 或 Session Fixation 窃取 Session Cookie，他们可以立即访问有效会话并保持会话活跃。绝对超时可以限制攻击者的时间，但实际上并不能阻止攻击者。

### 📃 Logged Token
如果攻击者在日志中或在窃取用户的计算机后在硬盘驱动器上看到旧的 Session Token，会话超时可能会阻止会话接管。但这更应该通过保护日志或使用硬盘加密来解决。

### 💻 共享计算机 (Shared Computers)
如果用户在图书馆等共享计算机上使用 Web 应用而忘记注销，下一个用户可能会接管其会话。但这种情况在现代并不常见，因为大多数情况下用户使用个人设备，或者公司内部使用公司设备。

### 🔓 攻击者访问设备 (The attacker has access to your device)
如果用户忘记锁屏，攻击者可以访问用户的计算机。会话过期可能阻止攻击者访问会话，但攻击者可以访问用户的电子邮件、Slack、密码库、SSH 代理、浏览器和文件。他们可以通过密码库或“忘记密码”功能创建新会话。

### ⚠️ 重新认证的风险 (Reauthentication is risky)
频繁的重新认证可能导致用户选择更简单的密码、保持密码库打开或将密码放在剪贴板上，从而带来安全风险。

### 🌐 大型网络应用的实践
Facebook、Google、Amazon 和 GitHub 的会话几乎永不过期。他们认为这是一个可接受的风险。

## 总结
过短的 Session Timeout 不一定能提高安全性，反而可能因频繁的重新认证带来安全隐患和用户体验问题，更有效的安全措施包括磁盘加密、锁定计算机和使用 HttpOnly Cookies。
