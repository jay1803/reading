## TL;DR

Tokenmaxxing 是一场市场激励机制设计出来的大规模幻觉：企业把 token 消耗量当成 AI 价值的代理指标，实质上是在给 AI 实验室的「驻场员工」发无限额信用卡。真正应该追求的指标是 ROT（Return on Tokens）= (产出价值 - Token 成本) / Token 成本 × 100。ROT 为负的根本原因不是企业执行能力不足，而是 Agent 架构天然不适合大多数经济性工作。

## 核心主张拆解

Agent 架构的三个结构性缺陷让 ROT 系统性为负：

1. **精度瓶颈**：Agent 每次任务从零即兴发挥，对真实企业工作（欺诈检测、核保决策）而言 80% 准确率等于 0% 可用。人类做到 99%，Agent 做到 50%，没有任何商业价值。

2. **知识盲区**：企业运转依赖成千上万条存在员工脑子里的隐性规则，工程师坐在旧金山永远触及不到内布拉斯加分公司办公室里的实际操作逻辑，Agent 能消化的只是写下来的规则子集。

3. **目标缺失**：没有明确目标函数，Agent 就无法 hill-climb，代码和流程在缺乏评估机制的情况下必然退化成 slop，而更多的 token 消耗让实验室继续受益。

解法核心：**AI 是编译器，代码是运行时**。

- Thinking（把业务规则编译成确定性代码）：成本高，但极少发生。
- Doing（代码执行重复性任务）：成本接近零，且可永久运行。
- 当前实现的 Thinking-Doing Ratio ≈ 1000:1，严重失衡。应该让 Agent 做「把业务知识翻译成代码」一次，然后让代码永远运行，只在规则变化时才重新调用 AI。

具体数据节点：Uber 2026 年 Claude Code token 预算在 4 月就耗尽；顾问披露客户意外烧掉 5 亿美元；Amazon 关闭 AI 排行榜；Legora CTO、Ramp 高管、Palantir CEO 相继公开批评 tokenmaxxing 是「看起来像进步的赌场」。

Poetic 的实现路径：工程师（多为前 Palantir）长期驻场客户现场，逐条萃取隐性规则 → AI 编译成确定性代码 → 代码在生产环境持续运行 → 世界变化时 AI 重新生成代码、回测验证、再部署上线。结果：AIG 99%+ 质量达成，token 用量减少 100x。

## 反驳或薄弱处

- 「Agent 对所有 Doing 工作都是错的」这一论断的主要证据来自 Poetic 自己的客户案例（AIG、SoFi、Chime），没有独立验证的 ROT 数据。
- 文章未定义「大多数经济工作」的边界：对话式客服、创意类任务、高度不确定的探索性研究是否适用这套框架，完全跳过。
- 这篇文章本质上是 Packy 为朋友公司写的软文，Markie Wagner 是核心信源，利益关系明确。
- 「AI 写一次代码、永远运行」这个理想模型隐含一个前提：业务规则相对稳定，但在快速变化的市场环境中，「世界变化触发重新编译」的频率可能远高于预期，token 节省效果会大打折扣。

## 终局图景

不是「AI 变成员工」，而是「企业变成软件」——一段持续自我编辑、回测、进化的确定性代码，以最快迭代速率爬向理想形态。人类的角色是定义「好」的标准，而非规定「怎么做到」。
