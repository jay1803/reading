Pricing models for product-led growth:
### Usage-Based Pricing

→ pricing based on how much you utilize
→ ex: AWS, Zapier

✓ drives value & gets users in the product quickly
✓ win-win (you get what you pay for)

✕ unexpected usage spikes can lead to churn
✕ low-switching costs

### Per-Seat Pricing

→ charging per person
→ ex: Apollo.io, monday.com

✓ scalable, predictable, easily understandable
✓ helps w/ rapidly changing enterprise user base

✕ can disincentivize whole company adoption w/ SMBs
✕ not a great proxy for actual delivered value

### “True-up” Pricing

→ charge for set amount of users on good faith... but then allow more to be added without additional cost
→ ex: Asana (in the early days)

✓ customer-centric approach for the end-users
✓ helpful w/ accessing product adoption in a new product

✕ if product is spreading viraly, this quickly can create headaches
✕ can be abused

### Tiered Pricing

→ charge for different feature bundles
→ ex: Slack

✓ helps customers self-select into great-fit plans
✓ onboarding can be tailored for team or company size

✕ self-selection can create confusion if categories aren't clear
✕ not everyone will fit in neatly into one of the categories

### Persona-Based

→ packages based on needs of specific user types
→ ex: LinkedIn w/ career, sales, and recruiting packages

✓ great for 2 or 3-sided marketplaces
✓ helpful when user types have vastly different needs

✕ can be harder to upsell
✕ sometimes it’s difficult to segment user types effectively

### Flat-Rate

→ one price shared by all user types
→ ex: Basecamp

✓ removes decision-fatigue for the buyer
✓ attractive for its transparency

✕ no personalization
✕ one-size-fits-all removes option to upsell
