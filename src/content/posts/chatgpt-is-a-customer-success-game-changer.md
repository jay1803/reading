## TL;DR
ChatGPT 对 CS 团队最实质的价值不是"智能助手"，而是彻底消除空白屏幕综合症（blank-screen syndrome）——Prompt engineering 决定输出质量，Murphy 认为这是 CS 从业者必须掌握的生存技能，否则会被掌握它的人取代。

## 三个具体场景
- **CSM**：会议前用 ChatGPT 做客户画像分析、头脑风暴、起草邮件开场白，弥补带宽不足和创意枯竭的问题；ChatGPT 写结果，而不是检索已有内容，因此 prompt 质量直接决定输出质量。
- **Enablement**：用 ChatGPT 理解细分客户群的语言习惯与潜在异议，加速内容规模化生产，突破内容创作的"一次只能写一篇"瓶颈。
- **Ops**：将有效 prompt 模板化，把客户记录中的变量通过 API 传给 OpenAI（Zapier/Make 或自定义代码），把 CSM 原本手动完成的会议准备工作自动化——这是文章中唯一有系统性想象空间的用例。

## 证据薄弱处
文章没有一个具体的 prompt 示例，也没有任何实际效果数据；三个场景全部停留在"描述可能性"层面。全文有三处链接指向作者自己的付费课程（Prompt Engineering for Customer Success）。"Game-Changer"是文章的结论，不是论证。

## 留下的那个想法
Ops 自动化那条路径最值得注意：一旦 prompt 模板能从 CRM 自动拉取变量并批量调用 OpenAI API，人工"准备会议"这件事本身就变成了系统噪音。"AI 不会取代你，但懂 AI 的人会"这句话——恰好在 Ops 自动化这条路上，可能先被自己证伪。
