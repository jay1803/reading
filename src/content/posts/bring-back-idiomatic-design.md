## TL;DR
这篇文章真正怀念的不是 Windows 时代的视觉风格，而是“界面惯例”作为公共基础设施：当复制、返回、链接、按钮、菜单在整个生态里都说同一种语言，用户只需学一次；今天的 Web 产品把每个应用都做成独立宇宙，单体更炫，整体更耗脑。

## 核心主张拆解
- 设计 idiom 的价值，不在好看，而在免思考。复选框之所以成立，不是因为它漂亮，而是用户和开发者都默认知道“这个问题该怎么问、怎么答”。
- 桌面时代的强项，不是设计师更天才，而是操作系统和 GUI 库提供了强约束，逼出了跨软件的一致性：File/Edit/View 菜单、Alt 键导航、状态栏、明确的按钮文本、通用快捷键。这让“怎么操作”从单个应用的局部问题，变成整个生态共享的协议。
- Web 时代的问题，不是缺少优秀产品，而是优秀产品彼此没有共同语法。Figma 和 Linear 都做得很好，但图标、快捷键、导航逻辑几乎完全不共通，用户在应用切换时持续支付重新学习成本。
- 作者认为异质化有两个根因：一是触屏革命打断了鼠标键盘时代积累的交互惯例，桌面和移动双端兼容把很多产品锁进尴尬折中；二是现代前端开发把“能做什么”放在“该不该这么做”前面，组件复制放大坏模式，框架抽象又让团队越来越远离 HTML 和浏览器原生习惯。
- 所以他的处方不是复古，而是重新尊重默认约束：能用 `<a>` 就别重造链接，能让 back button 工作就别劫持导航，能用文字就别滥用图标，宁可明显也别暧昧。若必须偏离公共惯例，至少要在组织内部建立强一致性。
- Apple 和 Substack 被拿来当反例中的正例：它们通过强默认、少自定义和跨产品一致性，把“it just works”做成了信任机制。作者真正推崇的不是审美统一，而是约束带来的可预测性。

## 值得质疑
- 文章对桌面时代有一点浪漫化。很多一致性也来自平台垄断、能力受限和交互空间较小，不全是纯粹的设计美德。
- Figma 这类浏览器里的“准桌面软件”本来就在突破 HTML 文档模型，要求它完全服从传统网页惯例，可能会压掉更高阶的交互能力。
- 但作者最强的判断仍然成立：当共同约束消失，设计自由的代价会被转嫁给用户，变成持续的认知税。

## 最后
真正稀缺的不是创意，而是公共可预测性。一个生态如果允许每个团队都重新发明按钮、链接和快捷键，最后损失的不是整齐，而是用户进入心流的能力。
