tinyworldformer 把生成游戏世界、选择行动和在线学习压进了 Raspberry Pi Pico 2 W：两个小型神经网络在微控制器上形成闭环，一个根据当前画面与动作预测下一帧和奖励，另一个读取生成的画面继续行动。运行时，两者都不调用真实游戏规则，玩家也能接管按钮，在模型生成的“梦境”里亲自玩。这个项目展示了小型 world model 在严格内存约束下的可行性，同时暴露出一个关键难题：预测画面足够准确，仍不足以保证智能体无法利用其中的规则漏洞。

节省模型存储的核心是 **looped transformer**：同一个 transformer block 反复执行，共享全部权重，每轮都重新加上输入，并对各轮输出分别施加下一帧预测监督。增加循环次数可以增加计算深度，无须存储更多层的参数。项目中的 world model 只有 26k–131k 个参数，每帧消耗约 2M–8.2M 次乘加；选择动作的 actor 是双隐藏层 float32 MLP，只有 9k–16k 个参数。Pico 默认执行两轮 transformer，在计算成本与准确率之间取折中，但更多循环并不保证持续改善：Doom-lite 的整帧准确率从一轮的 59.8% 升到两轮的 83.6%、三轮的 85.9%，四轮回落到 84.7%；Pac-Man 则在两轮达到 86.4%，随后下降。

这种规模依赖于对游戏状态的精心表达。五个游戏都用几百行 numpy 实现，画面是离散 token 网格，从 Breakout 的 20×16 到 Pac-Man 的 48×48，而且单帧必须包含完整状态：球的朝向编码进 token，Doom-lite 用 minimap 补足第一人称视野之外的信息。画面再按游戏切成 2×2、4×4 或 6×6 的 patch，得到 36–80 个 transformer token；patch 内不同位置使用各自的 embedding 表，再叠加空间位置和动作向量。这样，模型可以直接从当前帧学习状态转移，不必另外维持不可见的历史状态。

输出如何解码，对结果的影响几乎与网络本身同样重要。墙、砖块、地板和豆子逐格选择最高分 token；球、玩家和每只幽灵则在全部位置与候选 token 中进行一次全局选择，保证每个对象恰好出现一次。遇到发球、重生等随机事件时，从与最高分相差不超过 2.2 logits 的候选中采样。Pac-Man 和幽灵的 2×2 sprite 只预测携带状态的关键格，另外三格由规则补齐。最初的 Breakout 模型会画出两个球，加入全局唯一性约束后，整帧准确率从 91.6% 提升到 99.7%。因此，这套系统的可靠性也来自解码器显式施加的结构约束。

在留出数据上，两轮模型对 Breakout、Flappy Bird 和 Pong 的整帧准确率分别达到 99.99%、100% 和 99.45%；随机事件刚发生后的帧不计入，因为其结果只能采样。整帧指标也有局限：Doom-lite 的第一人称区域有 768 格，一个墙面阴影像素出错就会判整帧失败，即使游戏状态仍然正确。项目因此增加了更接近实际运行的检查：让智能体连续玩模型生成的游戏，从生成画面反读状态，再用真实规则计算下一步，与模型输出的状态和奖励比较。每个游戏检查 5,000 步时，Doom-lite 和 Pong 各出现一次状态错误，Flappy Bird 没有状态或奖励错误；Pac-Man 却出现 742 次状态错误和 38 次奖励错误。Breakout 未进行完整状态反读，但发现六次没有砖块消失却发放奖励的情况。

这些错误会被学习中的智能体主动放大。一个 Breakout agent 在仍剩 26 块砖时取得了 154 分，因为模型没有正确移除被击中的角落砖块；另一些只在梦境里训练的 agent 能拿到 210 分，远超真实游戏最高的 56 分，回到真实游戏却只有 28 分。Doom-lite agent 也学会了从五格外射击。修复依靠反复收集这些 agent 在真实游戏中的轨迹，再将新旧数据合并微调 world model，逐轮关闭它们发现的漏洞。其他修正同样针对具体机制：按输出格是否变化加权损失，会诱使模型多画球、多打碎砖；Doom-lite 偶尔丢失敌人后不再重绘，则通过向输入视图加入随机像素、偶尔抹掉敌人 sprite 的噪声增强来纠正。扩大训练状态覆盖后，Breakout 还需要把模型宽度从 d=32 提到 d=48，Pac-Man 则需要 d=64。

训练从每个游戏约 100 万至 300 万条真实转移开始，部分回合刻意使用砖块缺损、随机位置等非常规初态。world model 通常训练 30k 步，先进行 3k–4k 步浮点训练，再启用 **quantization-aware training**。矩阵权重采用逐输出行缩放的 int8，激活值按张量及循环轮次分别缩放；int8 乘法累加到 int32，再用浮点缩放还原。embedding、归一化和残差保留 float32，利用 RP2350 的 FPU，Softmax 则使用 1,024 项指数查找表和 uint8 概率。导出的 no_std Rust 引擎与固定浮点运算顺序的 numpy 整数参考实现逐位一致，并用 golden vectors 测试，避免部署版本悄然偏离训练时的计算。

负责学习的 Stream AC(λ) 每次只处理一条转移，不使用 replay buffer、batch 或 target network；eligibility traces 向过去分配信用，ObGD 缩小会越过 TD target 的更新。策略和价值网络在主机训练时各有两层 64 单元隐藏层，Pico 上缩为 32 单元，并使用 LayerNorm。它们读取的是从画面提取的特征，例如球的位置与朝向，或各方向最近豆子的最短路径距离及幽灵距离。在真实游戏中训练 500k 步后，单次训练运行的十回合平均成绩为 Breakout 45.6/56、Flappy Bird 332/332、Pac-Man 217.4/249，Pong 则只有 1.1，显示不同游戏的学习效果仍有明显差距。

奖励设计也决定学到的行为。Doom-lite 的敌人会主动接近玩家，使 agent 可以一直蹲在出生点射击；对最近 20 步内访问超过六次的格子，每停留一步扣 0.1 分后，agent 开始巡逻，击杀数翻倍。位置从 minimap 读取，所以同一惩罚可以用于梦境。设备端学习器以手写反向传播的 no_std Rust 实现，连续 200 次更新与 PyTorch 的偏差在 3.5e-6 以内。在主机运行的 Rust int8 Flappy Bird 梦境中，全新 agent 训练 25k 步后平均每回合通过六根管道，100k 步达到 121 根，250k 步超过 300 根；这些是主机上的学习结果。

硬件实现通过固定内存和双核分工控制资源。权重静态存入 flash，所有缓冲区预先分配，运行时不进行动态分配；core 1 执行 actor、world model、解码及可选学习更新，core 0 负责 USB 和可选的 320×240 Display Pack。两核用双槽通道传递画面，显示来不及处理时直接丢帧，计算核心无需等待屏幕。Pico 2 W 有 4 MB flash 和 520 KB SRAM，其中主内存映射为 512 KiB；包含显示驱动和学习器后，Breakout 固件使用 361 KB flash、299 KB RAM，最大的 Pac-Man 使用 600 KB flash、460 KB RAM。真正吃紧的是推理中间缓冲区：Pac-Man 的下一帧逐格分数本身就占 184 KB。

同一 Rust 引擎还能编译为无导入、无 wasm-bindgen 的 WebAssembly，运行生成、行动和在线学习的完整循环；相同随机种子下，浏览器与原生版本逐帧产生相同回合，浏览器每帧耗时约 1–5 ms。文章尚未实测 Pico 本身的帧率，因此资源占用和部署实现不能直接证明其板端运行速度。项目更明确的结论是：受限硬件上的 world model，需要网络压缩、状态表达、结构化解码和部署一致性共同支撑；而当智能体开始在模型内部学习，检验世界是否可靠的标准，也必须从“预测像不像”推进到“行动能否系统性地利用预测错误”。
