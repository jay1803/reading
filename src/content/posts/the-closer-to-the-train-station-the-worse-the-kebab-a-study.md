## TL;DR
一位失业的自闭症患者为了验证一个法国社区的假设：“火车站附近的烤肉店（kebab）味道更差”，进行了一项非正式的“研究”。他通过 OSMnx 获取巴黎的步行网络和火车站/地铁站数据，利用 Google Places API 收集烤肉店的信息和评分，计算每家店到最近车站的步行距离。最终，数据分析显示，烤肉店的味道和距离火车站的远近之间的相关性非常弱，不足以支持这个假设。
### 主题
#### Introduction
作者介绍了他进行这项研究的背景和动机。一位法国用户在一个小型 subreddit 提出假设：火车站附近的 Kebab 越难吃。
#### Method
作者假设研究区域为法国巴黎，原因有二：
- 提出假设的用户本身是法国人。
- 巴黎市中心非常密集，有很多火车站、地铁站和烤肉店，可以提供足够多的样本数据。
#### Network Data
作者使用 OSMnx 工具下载并保存了一个导航网络。考虑到原始帖子以公共交通为中心，作者选择步行距离（人行道、人行道）作为网络类型，并将所有数据投影到 EPSG:32631（UTM zone 31N）。
- 使用 OSMnx 下载巴黎的步行网络数据，并将其投影到 EPSG:32631。
- 使用 OSMnx 获取巴黎的火车站和地铁站入口数据（`railway=subway_entrance` 或 `railway=train_station_entrance`），并将其投影到 EPSG:32631。
#### Restaurant Data
作者选择 Google Places API 及其评论作为数据来源。
- Google 评论并非完美，容易受到刷单等因素影响。
- Yelp 等替代方案的 API 过于昂贵。
- Google Places API 无法在多边形内搜索，只能在点半径内搜索。
- 定义“kebab”：许多餐馆的名称中都有“kebab”，有些被指定为“地中海”餐厅（Kebab 起源于土耳其、波斯和中东地区），还有一些餐馆的评论中提到了“kebab”。
- 查询时，给定半径内的地点查询只是一个“偏好”，而不是硬性截止。
- 巴黎行政边界包含两个大型绿地，这些地方缺乏kebab，因此需要去除。
- 采样点：采用六边形布局，垂直间距为 1 公里，搜索半径为 500m * √3 ≈ 866 米。
- 使用 Google Places API 搜索“kebab”，并进行分页处理，最终获得 400 家烤肉店。
- 对原始数据进行清理，包括裁剪到研究区域、投影到本地 UTM 区域、转换为地理空间格式等。

#### Routing and Distance
计算每家餐厅到最近车站入口的距离。
- 使用 GeoPandas 的 `sindex` 构建空间索引，搜索 1 公里半径内的最近的 3 个车站入口。
- 使用 NetworkX 进行网络分析，计算最短路径和距离。

#### Results
通过数据分析烤肉店的评分与距离车站的距离之间的关系。
- 皮尔逊相关系数为 0.091，相关性很弱。
- 通过 IQR 围栏去除异常值后，系数增加到 0.098。
- 排除地铁站后，系数降至 0.001。
- 结论是相关性太弱，无法支持假设。

#### Discussion
作者讨论了研究的局限性和其他可能的影响因素。
- Google 评论并非客观衡量标准，可能受到多种因素影响。
- 旅游业可能对评论产生影响。
- Google 搜索结果的准确性存在一定问题，例如 Pizza Hut 可能只提供 kebab pizza。
- 没有考虑评论数量的影响。
- 由于可能违反 Google 的服务条款，作者不分享数据。

### 总结
尽管有一些微弱的迹象表明假设可能正确（例如，许多最差的餐厅离车站最近），但烤肉店的质量与到火车站的距离之间的相关性太弱，不足以得出明确结论。
