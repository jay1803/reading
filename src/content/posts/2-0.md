## TL;DR
信息 1.0 的真实失败是消费摩擦：内容到了邮箱之后没有优先级、无法追问，最终催生抵触而非阅读。RSS 抓取从来不是瓶颈。

## 核心洞见
Email 容器天然无法解决两件事：登录态内容（Reddit 个人热榜、关注板块）无法靠 RSSHub 稳定覆盖；内容看完之后无法在原地追问。Agent 时代的解法是把"抓取 → 理解 → 投递"整条链路接管，并把输出投进 Discord——一个可以实时追问的容器，而非静态邮件。

## 具体机制
本地起一个专用 Chrome profile 提前登录 Reddit、HN 等网站，OpenClaw 通过 Chrome Remote Debug 协议直接控制该浏览器，抓到的是用户正常登录时看到的个性化内容，绕开 API 限制与反爬。抓取后交给大模型做摘要、去重、分类，按主题分投 Discord 频道（投资频道、技术频道）。同一套流程，prompt 决定输出形态：HN 简报要求"必须选出今天最值得点开的一条并说明理由"，Reddit 简报要求输出候选内容方向直接服务产品选题——两份输出完全不同。

## 隐藏限制
质量瓶颈完全在 prompt，不在抓取。如何评估 AI 去重和分类是否遗漏关键内容，目前仍是黑箱。本地 Chrome 登录态需要人工维护，长期可靠性未被讨论。

把信息消费从"努力过滤"变成"愿意打开"——这才是真正的跃变。技术只是允许条件，改变的是人和信息之间的摩擦关系。
