## TL;DR
作者把 AI coding 当成一次新的技术范式转移来亲手压测，目标是穿过营销噪音，分清真正的能力跃迁与短期包装。为此他选择最极端的实验环境：一个几乎零员工、由 Claude Code 驱动业务运营的公司，因为只有去掉遗留系统和组织摩擦，工具边界与真实生产力才会暴露出来。

## 关键洞察
他把今天的 AI coding 放进自己经历过的几轮技术迁移里理解：敏捷、RSS、SMTP、PC 网络数据库这些变化，都需要靠亲自下场做事才能形成判断，所以这次也一样。于是他搭了 IntensityMagic 的 CompanyOS，假设一家公司的业务运营可以 100% 通过 Claude Code 和多个 agent 运行，只保留 CEO 与极兼职 CTO，用极限实验逼出哪些工作真能被代理、哪些环节仍然需要人。

在这个框架里，他对当下最热的几种 AI 叙事都很冷静。vibe coding 更接近原型开发和 no-code 的新皮肤，适合快速试错，很难支撑可扩展应用；大量拿到风投的钱，本质上是模型套壳或单点功能，随时可能被底层能力升级抹平；更多公司的卡点也不在“有没有用 AI”，而在没有把工作流、代理协作、系统边界和运营流程一起重构，于是开了 Copilot、换了 Cursor，产出方式却没有本质变化。

他当前痴迷的核心问题很具体：在“无员工、无历史包袱”的条件下，Claude Code 到底能把一家公司运转到什么程度。这篇文章把公司本身变成实验台，把 AI coding 变成真实运营里的连续压力测试，用实践而不是口号来理解下一代软件生产方式。

## 一句话总结
AI coding 的价值，在于它是否能重构整家公司如何运行；要看清这一点，必须亲手把系统推到极限。
