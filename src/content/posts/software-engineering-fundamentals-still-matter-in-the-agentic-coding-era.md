Andrew Ng 这篇长文体 X Article 的核心判断是：agentic coding 时代，即便你完全交给编码 agent 去写代码，理解软件工程基本功依然重要——因为这决定了你能否引导 agent 在延迟、可用性、一致性、可靠性、可维护性、简洁性和成本之间做出你想要的取舍，甚至决定你是否知道这些取舍本身存在。他给出的判断很直接：一个不懂软件基本功、只靠 vibe coding 的新手可以做出简单应用，但往往会让编码 agent 在这些维度上做出糟糕取舍，因为开发者压根不知道这些取舍点的存在，也就无法引导 agent 为自己的应用场景做出正确决定。他还提到，当你在构建 AI 应用时，AI 核心能力通常需要嵌入到一个更大的软件系统里，这部分你依然需要参与构建或塑造。

围绕这个判断，他把软件工程基本功拆成五个板块。第一是全栈应用构建：agentic coding 让人得以跳出过去"只做前端"或"只做移动端"式的狭窄专精，但你仍需理解全栈如何运转——UI 组件、缓存、渲染、API 设计、身份认证、状态与会话管理、异步处理、数据持久化、测试、安全、无障碍访问。第二是数据管理：数据是基础性的，也是后期最难更改的部分，需要理解访问模式、选择合适的数据模型与存储方式（关系型、文档型、键值、图）、处理事务与并发、保持数据干净一致且新鲜、管理隐私与合规，以及数据全生命周期——数据架构差，AI 系统能"知道"的东西就会受限。第三是系统架构设计：需要理解需求（用户规模、延迟、成本等），并对平台、前后端边界、单体还是微服务、状态放在哪里、技术栈选型做出决策；架构会随项目从原型到首个生产版本再到规模化系统而持续演进，这要求对组件和上下文都有深入理解。

第四是让系统安全可靠：涵盖测试策略（单元测试与集成测试、覆盖率）、为失败而设计（优雅降级、缩小故障半径）、"安全左移"（把安全考虑提前而不是事后补丁），以及用 AI 工具扫描漏洞和错误配置——但这依然离不开人对安全基本功的理解。第五是规模化与生产运维：部署、软件开发生命周期、CI/CD、基础设施即代码、可观测性、告警与事故管理、扩容技术（负载均衡、分片、复制、架构调整），以及版本控制、代码评审、依赖管理、技术债务这些工程实践习惯。Ng 的结论是：编码知识里有一部分——比如死记语法——正在过时，但真正深入理解软件如何运转的开发者，会远远跑赢那些不懂原理、只靠 vibe coding 的人。

这条帖子是他一个系列文章中的一篇，属于他持续发布的 "AI Engineering Skills" 系列，评论区一条高关注度回复贴出了整个系列的层级思维导图：顶层是 "AI engineering"，下分三大分支——"构建与部署 AI 应用"（LLM 基础、用数据锚定模型、构建 agentic 系统、评估驱动开发、生产运维、机器学习基础）、"软件工程基本功"（即本文讨论的五个板块）、"使用编码 agent"（管理 agent 上下文、规划与执行的取舍、编写验证器与规格说明、多 agent 编排、保持工作流更新），底部还有一层"塑造构建方向"（决定做什么、写规格说明、判断何时"足够好"）。这张图说明本文只是他更大框架里的一环，后续会有更多篇章补齐其余板块。

这套论述权威性较强——Ng 长期在 AI 教育和产业实践两端都有积累，这类"基本功依然重要"的判断也符合大多数资深工程师的直觉，但文章本身偏框架罗列，没有给出具体案例说明 agent 在真实项目里具体是怎样在这些维度上"犯错"的，五个板块下的每一条也都还只是标题层级的清单，没有展开到可操作的程度。真正值得记住的是他提出的判断标准本身：语法记忆这类"操作层"知识正在被 agent 取代，但对系统取舍空间的判断力——知道有哪些维度可以权衡、该往哪个方向权衡——是 agent 时代反而更值钱、更难被替代的能力。
