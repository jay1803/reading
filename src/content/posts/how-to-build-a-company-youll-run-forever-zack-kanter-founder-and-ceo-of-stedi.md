## 嘉宾背景
Zack Kanter，Stedi 创始人兼 CEO。Stedi 是一家 API 优先的医疗健康清算所，2024 年完成 7000 万美元 B 轮融资，由 Stripe 和 Addition 联合领投。在创办 Stedi 之前，他自举式经营汽配电商约 13 年后将其出售。采访者 Brett 来自 First Round Review。

## TL;DR
真正的护城河不是执行力，而是长期可持续地降低成本或长期维持溢价能力。Zack 在 Stedi 验证了一件反直觉的事：把别人没做好的显而易见的东西全做对，涌现出来的产品质量反而能打赢那些追求技术突破的竞争对手——前提是你愿意比任何人都更长时间地"吃玻璃"。

## 创业决策先做减法：不想离开的公司才能永远经营
他从反向推导设计了 Stedi 的架构：先列出让创始人想离开自己公司的原因（许下无法兑现的承诺、过早放弃董事会控制权、引入了不喜欢的投资人），然后逐一决定"不做这些事"。投资人只听已经发生的好消息，坏消息在发生时或之前立即告知，成为他的核心原则。多数创始人抱怨 VC 施压是因为他们做了他们本可以不做的选择——不给出控制权、不许下无法交付的承诺，那些让人想离开的情境就根本不会出现。

## "执行力是护城河"是软件圈最普遍的误解
按 Porter 的定义，护城河必须带来长期更低的成本或长期更高的定价能力，执行力做不到这两点，它只是让你暂时领先。Slack 是典型案例：再好的产品执行，也无法阻止 Teams 靠捆绑销售侵蚀边缘客户——那些不在意产品好坏 20% 差异的 Fortune 500 公司最终选择免费的 Teams，这对 Slack 的定价构成持续向下的压力。

## 质量、速度、成本"三选二"是最败局思维
他把丰田生产系统的核心洞察引入软件：不要去"节约成本"，要去"提升质量"——质量的改善几乎总会带来成本下降，但为节省成本而做的决策（如从 AWS 切回自建服务器）往往因流量假设不成立而适得其反。牺牲质量换速度的代价是技术债，而技术债是永远带着的负担。真正的解法是调整 scope：把需求缩减到"勉强能用"再发布，反而能同时实现三者。

## Stedi 的产品路径：从积木到平台，从 EDI 到医疗
Stedi 花了四年半才首次公开发布，期间把代码库推倒重来约八次。起步策略是把 EDI 转成 JSON 的开发者 API 积木，但集成成本远超 API 费用，商业模型不通。转折点是 2023 年 Change Healthcare 遭网络攻击宕机 60 天，Stedi 推出即插即用替代 API，三周内接到组合外大量求助，真正验证 PMF。医疗的结构性优势：HIPAA 强制统一了 schema，清算所机制让"接入一次、连通所有保险公司"成为可能——这两点在零售/物流 EDI 中都不存在。

## "现实有惊人数量的细节"
Zack 力推 John Salvatier 的同名短文：人类对任何任务的复杂度直觉都严重低估现实。他把这引申为产品决策框架：每个 feature 都是"奇迹的级联"，多个奇迹叠加后成功概率是乘积。在 review PR 时他专门找奇迹，目标是把每个 feature 缩减到一两个奇迹再发布，Demo Day 的真正目的也是此——逼迫团队以周为单位交付可视的增量，而不是考勤。

## 留下的那个想法
折扣零售（Aldi、Costco、Walmart）比任何软件行业都更能教会你如何在极端约束下建立可持续优势，这套逻辑——简化 SKU、降低单位成本、把省出来的钱让给用户——在软件里因高毛利率而有更大施展空间，但几乎没有软件公司真正学过它。Zack 的汽配业务最终做到了投资人当初嘲笑的利润率的 2.5 倍，靠的不是任何技术突破，只是把显而易见的事做到了别人不愿意做的程度。
