## TL;DR
当前 LLM agent 的核心瓶颈不是“能不能把记忆写进文件”，而是无法把推理时经历转化为可持续累积的隐性知识；“agent is just its files”让状态可迁移、可审计、可扩展，但也意味着那些无法被写成文本、代码或规则的直觉和半成型判断会在上下文交接中消失，所以基于现有 Transformer + agent 架构的“AI scientist”短期内更像高效执行者，而不是能长期积累科研直觉的原创思想者。

## 核心主张拆解
- 作者用 ChatGPT 识别其未发表旧文开场：模型能完成复杂认知判断，却说不清判断依据，说明 LLM 确实拥有某种隐性知识。
- 人类的大脑会在日常经验中持续形成新连接、新模式、新直觉；LLM 的隐性知识主要来自训练阶段，推理时看到的新信息通常不会可靠地写回权重。
- Claude Code、OpenClaw 这类本地 agent 用文件系统、Markdown、shell、cron/heartbeat 解决显性状态持久化：任务结果、长期记忆、未完成事项可以留在文件里，模型本身可替换。
- 这套架构的强处也是边界：凡是能被明确写下来的状态都能延续；凡是只能以模糊直觉、隐约关联、未成型假设存在的知识，都很难跨上下文窗口和模型实例传递。
- 因此，现有 agent 可以显著提升编程与大量知识工作效率，但距离能通过实验长期积累科研直觉、形成原创理论的“AI scientist”仍有结构性距离。

## 关键例证
- 主流模型上下文窗口约 100 万 token，但成本与 context rot 会迫使系统压缩或删除旧信息；压缩一旦丢掉关键约束，就可能把“只建议删除邮件”变成“真的批量删除邮件”。
- Marc Andreessen 对 OpenClaw 的描述强调新范式：语言模型 + Unix shell + 文件系统 + Markdown 状态 + cron/heartbeat；agent 的人格和能力可以随模型、运行环境、文件系统迁移。
- 作者用“每周换一个临时员工”的类比指出：对接待、药剂、管道维修等交易型工作，交接笔记可能足够；对需要多年客户理解、长期研究积累、组织语境掌握的工作，显性笔记无法替代持续经验。
- 他在 2010 年 Google 实习时只是给内部数据库加一列，代码只有几行，但理解系统和流程花了数周；难点不是输出代码，而是获得足够上下文。
- 作者二十多年科技/经济写作经验横跨 Brexit、专利流氓、激光雷达等主题，这些沉淀增加了他在新议题上提出有趣观点的概率，但其中大部分是无法完整转交给另一个人的隐性知识。

## 值得质疑
- 文章低估了速度与规模的补偿效应：agent 可以在短时间内经历大量 read-act-write 循环，某些明确反馈丰富的领域可能用外部记忆和检索近似出部分“经验积累”。
- 它默认隐性知识必须存在于大脑或模型权重中，但未来的持续学习、领域 embedding、实验日志结构化、自动蒸馏机制，可能把一部分“直觉”转化为非自然语言的可复用状态。
- “AI scientist”本身有两种含义：若指原创理论家，作者的怀疑很强；若指高通量实验执行、文献整合、假设枚举与工具调用系统，则可能比文章判断更早实现。

## 最后判断
今天的 agent 更像强大的显性状态机器，而不是会沉淀经验的心智；真正关键的突破，不是把文件记得更多，而是让系统把长期实验史压缩成可迁移、可更新、可诱发新直觉的内在表征。
