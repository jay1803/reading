## 嘉宾背景

Noah Shinn 是 Instinct 的创始人和负责人。他在访谈中介绍，公司成立约一年，正在开发通过短信、电话、邮件等现有渠道使用的个人 AI 助手，希望它不仅回答问题，还能操作电脑、处理账户事务，并持续协助用户实现目标。本期由 Patrick O’Shaughnessy 主持。

## TL;DR

Shinn 希望用户越来越少操作软件，却能获得越来越多实际服务：不必浏览订票网站、反复协调日程或记住何时叫车，只需表达意图，Agent 就在后台完成准备、执行和跟进。他认为，这未必意味着现有商家的生意缩小——用户停留在 App 内的时间可能下降，但交易摩擦减少后，出行、餐饮和旅行需求反而可能增加。Instinct 因而押注用户免费、商家为交易分发付费的模式，并用风险资本和定制推理部署支撑前期扩张；与此同时，主动服务也意味着，即使用户没有发消息，系统仍在消耗算力。

## 1. 个人 Agent 的产品突破不只是能力更强，而是让用户无需学习新软件，也能理解和预期它的行为

Shinn 认为，个人 Agent 与许多早期消费软件不同：创始人不必先说服用户接受一种陌生愿景，因为人们从开始使用 ChatGPT 时，就已经期待 AI 能理解自己、处理生活中的事务。Instinct 的任务是兑现这种期待，而不是再增加一个需要学习的 App。它有电话号码、邮箱和可操作的电脑，用户可以像联系一个办事的人一样发短信、打电话或转发邮件；简单的是沟通方式，而不是能力范围。

这种易用性落实在很细的沟通设计中。Shinn 强调，用户不仅要看懂回复，还应能够预期提出请求后会发生什么。消息是否过长、重要信息是否前置、是否需要打开大文件才能找到答案，都影响使用负担。他以阅读长消息时的扫读方式说明，系统应把最需要知道的内容放在开头，而不是只追求语义完整。打扰时机同样重要：对话中的一个例子是，文件即将到签署期限时，Instinct 才主动打电话提醒，并提出可以重发邮件，把文件顶到收件箱上方。

这些品质难以完全通过短期自动评测衡量，尤其是用户是否会在两三周后建立信任。因此，他们把评测与分阶段试用结合：Shinn 先自己使用改动，再交给团队、小规模早期用户，最后才扩大发布。个性化也不是给每个人预设一种鲜明人格，而是逐渐学会对方能接受的消息长度、沟通语气和执行方式。他明确表示，Instinct 不以发展类似电影 Her 中的情感关系为目标。

他预计，入口还会继续变轻。部分用户发送给 Instinct 的消息已有九成以上是语音，他自己也通过手机 Action button 直接录入请求；更长期的设想是借助 AirPods，在行走或运动时完成简短沟通。不过，减少固定界面并不排斥视觉表达：旅行行程、婚礼计划等复杂内容，可以临时生成网页或完整的 Web 应用来承载，而不必为了每一种需求都安装专门的软件。

## 2. Agent 的演进方向是持续追求用户目标，而不只是完成一条条明确指令

Shinn 用取消订阅区分“提供建议”和“代为完成”。用户连接银行账户后，Instinct 可以检查交易记录，询问某项订阅是否仍在使用；得到确认后，不只是提示用户自行取消，而是进入网站、登录、处理邮箱验证，完成取消，再报告节省的金额。用户委托的是结果，不必继续承担中间步骤。

记忆让这种委托逐渐不再依赖详尽指令。他举例说，用户只需发一句“今晚我要到 New York”，系统就可以结合获准访问的位置、航空公司偏好、舱位、座位、餐食和支付方式，安排航班、酒店、机场接送及日历。过去表达过的住宿偏好不仅可以在下一次订房时复用，也可以被用来推测其他选择。穿搭案例也体现了类似变化：用户上传衣柜和自身形象后，系统可以展示本人穿上不同搭配的效果，进而定期提出新搭配，并在用户选定后购买相应衣物。

主动性则意味着，系统需要自己判断何时检查、是否行动，以及是否值得通知用户。Shinn 描述，Instinct 可以在用户起床前检查当天安排，发现暂时没有需要打扰的事便继续后台处理；也可以记住下午某个时点再行动。用户未必已经知道应该提出什么请求，系统仍可能根据已有上下文发现可以帮忙的地方。

他认为，下一步是从单次任务转向持续目标：不是记录一次训练，而是在未来几个月协助达到体重或运动里程碑；不是采购一次商品，而是长期把库存维持在指定上下限之间。他说，已有小企业把后台事务放在 Instinct 上运行，其中一部分实现了自主处理。这里的交互单位不再是“现在替我做这一步”，而是“持续利用可用工具，维持我想要的状态”。

## 3. 有效委托依赖逐步建立且可撤回的信任，而自主行动的安全不能只靠 Agent 自己判断

更多信息能够让 Agent 更了解处境、提前准备并完成更多事情，但用户需要先愿意交出这些信息。Shinn 说，他们观察到，建立信任通常需要几周，他并不认为应该强行缩短这一过程。用户应按自己舒服的节奏授权，也可以随时撤回。团队把首次提供信用卡、账户密码或其他敏感信息所需的时间，作为信任的代理指标；据他介绍，约四成用户在使用三周后提供了个人信用卡，连接至少一项敏感信息的用户留存率约为八成。

他把安全分成两类问题。第一类是敏感数据的保管、隔离与访问控制，许多既有企业也需要解决。第二类是自主行动新增的风险：系统不仅知道信息，还能读取外部内容、访问邮箱和日历，并使用信用卡消费。保护数据本身之外，还必须防止外部恶意内容或模型生成的错误触发真实操作。

为此，Shinn 描述了独立于 Agent 主体的防护系统。输入侧的“防火墙”检查即将被读取的文字和其他媒体，拦截试图诱导 Agent 的恶意内容；行动侧的监控系统则在工具调用或其他操作发生前进行审查，可以暂停、批准或拒绝下一步。他以模型凭空生成某个专有名词为例，说明为什么需要另一套机制在内容转化为行动前检查，而不是让执行任务的 Agent 同时承担全部判断。

他也承认，早期版本尚未具备这些防火墙和主动监控。团队后来不是只修补个别问题，而是建立系统性的防护，并持续通过对抗测试寻找更难的攻击与边界情形。面对主持人对未来泄露和攻击的担忧，他反复强调的原则仍是：安全应进入公司和产品的基本工作方式，用户始终保有对数据及授权的控制权。

## 4. Agent 之间的协调网络必须表达信任的层次，而不能只记录谁与谁相连

Instinct 的“可信联系人网络”首先针对安排会议的反复沟通。双方本来只是想找到一个共同可行的时间，却需要不断交换空档、旅行计划和时区。Shinn 希望用户只需表达“本周内见到这个人”，双方 Agent 就能在各自权限内寻找时间，并落实到日历。

关键不只是连接两个账户，而是表达不同关系允许共享什么。配偶可能愿意开放几乎全部信息，同事可能只能查看工作日历，或在需要时取得邮箱中的某类文件。Shinn 因而把它描述为带有不同权重的关系网络，而不是只有“是朋友／不是朋友”的图谱。

技术限制之外，他还希望利用现实关系中的信任约束。如果一个只获准协调日程的人开始索取其他资料，系统不仅应限制访问，还可以提醒资料所有者，对方正在寻找什么。按照他的设想，越界请求因此不只是一次系统拒绝，也会影响双方如何理解这段关系。

这种协调还可以扩展为持续组织共同活动。他介绍，有朋友群让各自的 Agent 每周策划不同的聚会，结合大家的空闲时间、兴趣、Spotify 收听记录及可参加的演出选择方案。其中一个六人群体还安排同一辆 Uber 依次接人，协调路线与接送通知。在这些例子中，Agent 承担的不只是某个人的事务，而是原本需要整群人反复投入精力的后勤工作。

## 5. Agent 可能减少用户停留在商家 App 的时间，却通过降低交易摩擦增加真实服务需求

餐厅预订是 Shinn 用来说明交易入口变化的例子。Agent 可以比人更频繁地检查空位，但他更感兴趣的是改变匹配方式：用户可以表达这是配偶的重要生日或纪念日，餐厅也可以表达自己希望优先接待什么场合。双方 Agent 如果能传递这些需求，预订便不必完全依赖谁先刷新页面。这是他正在探索的合作方向，而不只是让机器更快抢位。

旅行则展示了标准化界面可能如何被意图表达取代。在线旅行平台把不同酒店、航空公司的供给汇集起来，让用户筛选和购买；Agent 希望进一步接过筛选与安排本身。Shinn 同时承认，原有企业积累的数据和服务网络仍有价值，因此他倾向于与它们合作重塑体验，而不是把所有平台都视为必须替代的对象。

面对主持人关于 Uber Eats 等企业何时会抵制 Agent 的追问，他把收入拆为两部分：一部分来自用户停留、广告和界面中的追加销售，另一部分来自实际商品或服务的交付。他认为，不能简单假设失去前一部分后，企业就只剩原来较小的生意。假如系统根据日历和交通提前安排车辆，或在用户深夜返家前询问是否订惯常的餐食，使用服务所需的操作会减少，交易次数反而可能上升。用户更少进入 App，却可能更多使用这家企业的服务。

他没有把这一判断推广成适用于所有行业的结论。对于高度依赖注意力的企业，他认为变化会更困难；具体结果仍需逐个行业探索。他提出的实践方式是与商家开展小规模 A/B 测试，例如只向少量用户开放某种 Agent 体验，观察用户是否更满意、是否更容易找到想要的商品，以及交易量是否增加，再决定是否扩大合作。

## 6. 免费 Agent 希望靠交易分发收费而非出售注意力，但商家付费与用户利益如何一致是商业模式的核心问题

主持人把“个人对齐”落到收入来源上：雇员由自己支付薪水，因此至少能够理解其主要激励；免费 Agent 如果从别处获得收入，用户应如何理解它代表谁的利益？Shinn 回应说，越聪明、越了解用户的系统，越不能利用这些能力说服用户购买或订阅本来不想要的东西。他明确表示，不希望复制免费平台通过广告影响消费的模式。

在产品目标上，他也反对把 Instinct 仅仅定义为服从指令的任务执行器。它应追求更高层目标，包括建立信任、照顾用户利益，以及在用户遗漏事情时提供支持；完成一项合适的请求，是实现这些目标的一种方式，而不是唯一准则。

他的商业设想是向用户提供免费体验，由获得交易的商家支付统一抽成，以此交换分发。按他的说法，平台当时的年化交易规模已达到约十亿美元，约一半来自旅行。他希望获得的是把需求带给商家的价值，而不是主要参与支付链条中小额手续费的分配；支付机构本身仍在提供有用的基础设施。

旅行行业既有佣金是他认为可以较早利用的收入来源，例如部分精品酒店愿意为带来的订单支付较高比例佣金。但他强调，这不代表 Instinct 会采用某个固定高抽成，最终能够收取多少，取决于它能否真正成为大量数字行为的入口、获得足够强的分发能力。他把普遍免费视为个人目标，而非已经作出的终身承诺；谈到商家付费时，仍坚持不应以违背用户意愿的方式影响行为。

## 7. 个人 Agent 的扩张竞赛同时受分发和算力约束，单位成本下降并不能消除提前押注容量的风险

Shinn 说，Instinct 最初向约两百名亲友开放，每人获得五个邀请名额，之后依靠用户推荐和自发分享加速增长，访谈时日增长约为一成，尚未投入营销费用。邀请制的目的不是制造排他性，而是避免用户突然增加、算力却无法跟上。主持人将竞争概括为：大公司正在补齐产品质量，新公司则必须尽快取得分发；Shinn 承认，巨头可以直接触达庞大用户群，而 Instinct 需要靠口碑增长追赶。

算力使这种增长不同于普通消费软件。他说，自己约四成时间都在考虑供给：需求快速增长，但新增算力上线需要数月，不能等用户到来后再按原价即时补齐。提前采购少了可能需要以数倍价格补购，采购多了又意味着对尚未出现的需求作出大额承诺。他反复提出“究竟应该提前买多少”的问题，并未给出最终答案。

需求也不只来自更多用户发送更多消息。主动 Agent 可以在全天不同时间检查安排、处理信息、判断是否需要行动；用户直接参与的对话反而可能只是工作量的一小部分。Shinn 因此预计，这类产品需要的计算量会远超仅围绕显式请求工作的系统，不过他没有提供具体的单用户日成本或未来总需求数字。

降低单位成本依赖按工作负载重新组织推理部署。实时交互需要低延迟，但后台阅读、整理和准备可以等待数分钟甚至数小时，适合更高效的批处理。他说，团队通过针对这些差异定制部署，在内部评测、A/B 测试和用户参与度上维持接近前沿模型的表现，同时降低服务成本。

这种优化仍需要资本支持。Shinn 认为，每月收取高额订阅费是较容易兑现的短期路径，但可能让公司停留在局部最优。风险资本的用途，是承担经过计算的前期风险，让团队有时间证明交易规模和跨行业合作模式，而不必在商业模式成熟前，就让所有用户先承担完整服务成本。

## 提到但未深入展开的话题

对话还提到，一对用户借助 Instinct 找回自己出现在 US Open 现场大屏上的视频；Shinn 简短评价了另一款 Agent 产品，并表示自己更关注尚未获得理想 AI 体验的广大用户。其他话题包括邀请名额引发的人情顾虑、炫耀与转售，Instinct 命名及避免人名式拟人化的考虑，以及 iMessage、WhatsApp 等渠道依赖；他表示，超过一半流量并不经过 iMessage。主持人也提及融资规模、估值和投资方，Shinn 则把回答重心放在资本需求与合作伙伴支持上。结尾，他感谢工作和生活中周围人的善意，希望给予同样的体贴作为回应。
