在长上下文的智能体工作负载中，决定总账单的关键已逐渐从输入、输出单价转向 **cache read 成本**：每轮新增的 token 或许不多，但模型必须反复读取不断膨胀的既有上下文，导致累计费用随轮数近似二次增长，因此仅比较每百万 token 的常规输入输出价格很容易选错模型。

以一个初始上下文为 60k token、每次工具调用新增 500 token 输出并读回 5,000 token 的假想会话为例，运行 20 轮后，DeepSeek V4-Flash 总成本约 0.03 美元，其中 cache read 为 0.01 美元，占 18.4%；Claude Opus 5 总成本 2.32 美元，cache read 为 1.04 美元，占 44.9%；GPT 5.6 Sol 总成本 2.16 美元，cache read 同样为 1.04 美元，占 48.1%。此时后两种模型将近一半的支出已经来自缓存读取，但 GPT 5.6 Sol 仍略低于 Opus 5。

同一会话延长到 100 轮后，成本结构发生显著变化。DeepSeek V4-Flash 总成本约 0.19 美元，其中 cache read 为 0.09 美元，占 48.1%；Claude Opus 5 总成本增至 21.34 美元，cache read 达 16.31 美元，占 76.4%；GPT 5.6 Sol 总成本更达到 36.20 美元，其中 29.55 美元、即 81.6% 来自 cache read。原因在于每轮虽然只增加约 5.5k token，所有此前积累的上下文仍要再次读取；会话越长，每轮被重复读取的缓存越大，最终让缓存费用压倒新输入和输出费用。

这也意味着减少工具调用轮数能产生远高于线性比例的节省。若为智能体提供更专门、单次可完成更多工作的工具，使一次任务所需轮数降低 10%，单次运行的总成本可下降约 16%。这一估算也符合许多文档分析和编程智能体的实际模式：模型思考后执行很短的 Bash 或 grep 命令，命令本身写入的内容有限，返回的文档或既有代码却很多，于是主要开销来自对旧上下文和检索结果的重复读取。对多数自主智能体而言，假设接近 100% 的 cache hit rate 也具有现实合理性。

与此同时，超长上下文对应的 **KV cache** 所占存储空间正在迅速缩小。DeepSeek 的 Compressed Sparse Attention 和 Heavily Compressed Attention 等算法，可将约 fp8 精度的 1M token 上下文压缩到大约 5GB。KV cache 因而能够快速从显存卸载到系统内存，甚至 NVMe 闪存；在 RAID 式配置和 PCIe 5.0 存储上，1–5GB 缓存理论上可在远低于 100 毫秒的时间内写入和读回。Nvidia 与 AMD 还支持 GPU 直接访问 NVMe，绕过系统 RAM，一组 NVMe 驱动器由此可以承载数以万计的智能体会话。这类需求也可能是近期 NVMe 成本上涨的原因之一。

DeepSeek 已把低廉的缓存读取价格作为推理 API 的重要卖点，其 cache read 报价约为其他同模型供应商的十分之一。即使其价格可能因硬件资源失衡而上调，底层缓存压缩与存储技术仍在持续降低真实服务成本，供应商之间的竞争也可能进一步压低 cache read 价格。当前定价与底层成本下降的速度并不同步，这给前沿模型实验室留下了可观的利润空间。

100 轮的 Opus 5 会话尤其能说明这种价差：它在 cache read 上花费 16.31 美元；若每轮两分钟，整个会话约持续 3.3 小时，生命周期内平均上下文约 330k token。即使采用远高于 DeepSeek 压缩水平的 30KB/token 估算，缓存也只占约 10GB，相当于用户支付约 0.5 美元/GB-hour，而 AWS 的内存租赁价格低于每 GB-hour 1 美分。大规模推理还要承担分层缓存管理和复杂网络调度成本，确保 KV cache 在正确时间出现在正确设备上，因此不能把 API 价格简单等同于 RAM 或 SSD 成本；但对本地部署和多数企业级 on-prem LLM 场景，这些额外复杂性通常远低于超大规模服务，缓存本身的边际成本也更有限。

GPT 5.6 Sol 还存在一个会让价目表比较进一步失真的计费悬崖：当单次调用的输入超过 272k token 后，OpenAI 会把整次调用的输入价格提高到两倍、输出价格提高到 1.5 倍。Anthropic 则明确表示长请求维持相同的每 token 单价，900k-token 请求与 9k-token 请求采用同一费率。因此，GPT 5.6 Sol 在 20 轮时比 Opus 5 便宜，分别为 2.16 和 2.32 美元；到 100 轮时却比 Opus 5 贵约 70%，达到 36.20 美元，而 Opus 5 为 21.34 美元。仅跨越 272k token 后的重新定价，就给 GPT 5.6 Sol 的总账单增加了 76%。

随着上下文窗口扩张、智能体运行时间延长以及 KV cache 压缩技术成熟，模型经济性的核心指标将越来越接近"长期反复读取上下文要付多少钱"。评估模型和设计智能体时，必须同时考察 cache read 单价、工具调用轮数、上下文增长速度以及长上下文阶梯定价；只看常规输入输出费率，得到的成本排序可能在短会话中成立，却在真正长期运行的任务里完全逆转。
