## TL;DR
代码的价值不只是把设计稿变成可运行界面，而是在运行、触摸、反馈、再调整的过程中发现设计本身。作者把 code 定义为一种设计媒介：它让“元素之间如何互相反应”从抽象想象变成可感知的关系系统。

## 核心主张拆解
### 设计发生在交互反馈里
界面设计不能只靠静态判断完成，因为真正的问题藏在使用感、反应链和元素关系中。改变 X，观察 Y 如何变化；如果感觉不对，再改 X；当所有分散元素的关系开始形成一个整体，设计才接近平衡。

### Code 是指定“如何工作”的工具
作者采用的设计定义不是“它看起来怎样”，而是“它如何工作”。在这个定义下，代码天然是设计工具，因为代码直接规定状态、反馈、行为和关系，而不只是执行别处已经完成的视觉决定。

### 发现优先于实现
文章最关键的转向是：coding is finding。写代码不是把答案落地，而是在可运行系统中寻找答案；界面只有被操作、被反复调整时，设计判断才会变得具体。

## 值得质疑
这篇文章是短札，论点清楚但证据很薄：它没有区分不同类型的代码工作。对强交互产品、原型、工具界面，code-as-design 很成立；对后端基础设施、合规流程、批处理系统，这个命题需要重新限定。

## 最后一层
“代码是设计”真正反对的是把设计理解成先验蓝图。很多界面问题不是想清楚后再实现的，而是实现之后才暴露出来；代码让设计从脑内判断进入现实摩擦。
