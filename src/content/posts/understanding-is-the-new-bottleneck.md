AI agent 越能快速生成和验证代码，人类对系统的理解就越成为持续参与创造的瓶颈。Geoffrey Litt 强调，即使 agent 的自我检查能力不断提高，开发者仍需要理解它写出的代码，因为项目由许多轮迭代构成：对现有系统掌握了哪些概念、形成了怎样的心智模型，直接决定下一轮能提出什么想法、看见哪些改进空间。只会判断成果是否符合规格、架构是否合理，还不足以保持这种创造能力；短期跳过理解所积累的 **cognitive debt**，会在后续演进中限制人的参与。这与 Margaret Storey 和 Simon Willison 推广的认知债务概念相呼应。

解决这一瓶颈，需要把教育中帮助人建立理解的方法带进 AI 开发流程，逐行阅读 diff 只是其中一种手段。Litt 每天使用的 `/explain-diff` skill，会在 agent 完成工作后生成 HTML、Markdown 或 Notion 讲解文档。它先补齐既有系统的背景，再解释修改目标与相关概念，最后进入代码。例如，在调整游戏视角的任务中，讲解从游戏引擎开始，以"用二维绘图技巧让花园呈现三维感"为目标，介绍 isometric projection，再通过可交互插图让读者拖动花园里的石头、观察坐标变化，建立空间直觉。Notion 支持在页面中嵌入交互式 HTML，使这些实验可以直接放进讲解文档。

有了背景与直觉，代码变化也需要按理解顺序重新组织。普通 diff 往往按文件名字母顺序堆叠改动，Litt 所称的 **literate diff** 则用连贯文字串起修改，穿插代码片段，解释每一步与整体目标的关系。他仍然阅读原始 diff，但会先读这份讲解，有时还会打印出来带到咖啡馆，以减少干扰。不过，易读的材料仍可能制造"看过就懂了"的错觉。受 Andy Matuschak 对阅读局限的讨论，以及他与 Michael Nielsen 将间隔重复测验嵌入文章的实践启发，Litt 在讲解末尾加入了五道交互式问题，并规定自己通过测验后才能把代码发给别人；审查他人的代码时也执行同一标准。测验由此成为 **速度调节器**：当 AI 的工作循环快于人的理解速度，它会强制检验人是否真正跟上。

比阅读和答题更进一步的办法，是让 agent 构建可以亲自探索的 **micro-worlds**。这一思路来自 Seymour Papert 的 Mathland：如同住进法国能自然学习法语，学习者也可以在一个环境中，因好奇和行动而逐渐掌握数学。Litt 将它用于理解代码执行：编写 Prolog interpreter 时，他让 agent 帮忙制作专用 debugger，自己逐步运行逻辑程序，沿时间轴前后查看 stack、每一步求值的规则，并留下"这里正确应用了这条规则"之类的注释。亲自操作这些状态变化，使调试过程同时成为建立理解的过程；把调试全部交给 agent，则不会自动给人带来同样的认知积累。

个人网站迁移提供了另一个例子。Claude 最初写好了从一个框架迁往另一个框架的脚本，但 Litt 不熟悉新框架，审查时只能觉得"大概没问题"。他随后要求 Claude 制作一个像电子游戏指挥中心的界面：旧站与新站并排运行，由他点击按钮逐步执行迁移，观察页面效果与文件树如何变化。新站在眼前逐步成形，让他以接近亲手迁移的方式理解系统，同时省去了自行搭建操作流程的大量时间。这里，agent 生成的辅助代码承担了教学作用，让人通过可控的操作理解另一批代码。

个人理解还需要扩展为团队共同理解。成员拥有相近的心智模型、用同一组词语唤起相同的系统图景，才能高效讨论、接续彼此的想法；各自与 agent 独立工作容易让这些基础分散在不同人的上下文中。Litt 以 Notion 的协作为例：Claude 和 Cursor agents 可以在 Notion 中运行，生成的技术方案默认进入协作页面，团队成员能立即评论和讨论，使方案形成的过程同时成为共享理解的过程。

这些方法延续了计算机作为认知增强媒介的早期愿景。约五十年前，Alan Kay 就设想让孩子在交互游戏中边玩边修改代码，以此理解物理，让计算机提供超出书本的学习方式。AI 让定制模拟、交互解释和探索工具的制作变得更容易，也让这一愿景获得了新的实现条件：自动化释放出的能力，可以继续投入到人的理解之中，让人更深入地进入创造循环，并有能力决定下一轮值得做什么。
