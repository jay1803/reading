## 实现成本归零之后，品味才是稀缺要素

过去的产品开发流程建立在一个假设上：实现很贵。文档、设计、原型都是为了在动手之前充分降低风险。这个前提已经消失。OpenAI 现在的状况是：给每个人无限 token，一个功能可以同时有 90 个团队在各自实现。实现本身不再是瓶颈；在 90 个看起来都像生产版本的原型里辨别"这个值得留下"的判断力，才是新的稀缺要素。Ambrosino 把这个能力叫 taste，但他明确区分了它和审美偏好——它包括系统思维、战略方向感、媒介选择判断、以及知道当前处于流程的哪个阶段。

## 原初标记（Primal Mark）：第一个人造物锚定所有后续反应

最反直觉的一点：现在的工程师可以立刻 vibe code 一个原型，这反而让文档在某些场景下更有价值，而不是更没价值。原因在于"原初标记"效应——人们看到高保真原型会以为它已经到了生产阶段，开始对着一个本该是探索的东西提需求、做决策。文档更擅长传达"这是哪个阶段"的信号；原型更擅长压力测试交互模式。关键不是哪种媒介更好，而是为你要做的那件事选对媒介。PRD 还没死，但用错了场景的 PRD 和用错了场景的原型一样有害。

## AI 设计能力滞后，不只是训练难题

AI 在设计上滞后有几个层次的原因。第一，AI lab 历史上优先强化能加速 AI 研究的能力——能写出正确代码的模型直接服务于研究飞轮，而设计能力不在那条链条上。第二，设计比代码更需要新颖性：代码应该过度拟合已知模式，设计需要随机性和文化感知；AI 把 Linear 的网站输出一遍并不算设计能力。第三，有一个更难解的层面：视觉设计背后存在代码抽象层的映射关系——"这两个看起来不同的元素在语义上共享同一个交互模式"——这种深层一致性是当前技术还触及不到的。

## 角色定义方式在变，但角色本身不会消失

Codex 团队的设计师写代码，PM 有计算机科学硕士学位，角色边界正在模糊，但 Ambrosino 对"干脆取消 PM"这个流行论断持明确反对意见：这不是淡化职能，而是丢掉了多年积累的最佳实践和踩过的坑。他的描述是：角色现在由"你花时间做的事情的平均值"来定义，而不是由职能边界来定义。对 PM 而言，当前最有效的模式是"区域防守"——两个 PM 紧挨着工作通常是坏信号，说明有地方没有覆盖到；目标是铺开保证全场覆盖，在混乱的探索中充当品味锚点。

## 同一个产品，两个月的模型差距决定成功或失败

Codex app 如果在去年 11 月发布会直接失败，但 2 月发布成功了。产品形态没有任何本质区别，唯一差异是模型能力。Ambrosino 把早期版本总结为"too AGI-pilled for the moment"——让用户把任务完整交给模型，但模型还没到那个水平。同期 Claude Code 采用更保守的形态（本地运行、主动问问题、不要求用户全权委托），反而效果更好，因为和模型实际能力匹配。这意味着功能的正确发布时机完全取决于模型成熟度，而不是设计的好坏——同一个功能可以失败五次，然后在某次模型迭代之后突然 work。

## Codex 的定位：工作协调层，而非超级应用

Ambrosino 对"超级应用"这个词明确厌烦，但描述的愿景很清晰：Codex 是"home base"——你在这里开始工作、结束工作、自动化工作，它调用你已经在用的其他工具，而不是取代它们。OpenAI 内部的非工程师（营销、法务、财务）在 Codex 被设计为对他们"主动不友好"的情况下，依然不愿意换用为他们定制的其他工具——产品质量产生的粘性可以超越使用场景的精准匹配。Brent 用 Codex 剪视频的案例最具体：模型发现自己不能直接控制 Premiere Pro，于是为 Premiere Pro 写了一个插件再继续操作。这个模式——Codex 通过连接器、computer use 或自建插件与现有工具协作——是当前形态的核心。
