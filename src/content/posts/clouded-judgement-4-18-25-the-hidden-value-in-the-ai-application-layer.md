## TL;DR
AI foundational model公司（如 OpenAI、Anthropic）正显示出进入应用层的兴趣，例如通过收购或自建编码助手等应用。此举的主要动机可能是为了获取大量有价值的、甚至是专有的用户交互数据，用以改进其核心 AI 模型，同时也为了在模型 API 定价可能商品化的未来，开辟新的利润来源。
### 主题
#### AI模型公司向应用层拓展
近期有传言称 OpenAI 计划以 30 亿美元收购编码助手公司 Windsurf（前身为 Codeium）。Windsurf 与 Cursor 或 GitHub copilot 类似，利用如 Anthropic 的 Sonnet 3.7 或 OpenAI 的 GPT 4.1 等模型为开发者提供编码工具。此外，OpenAI 也在访谈中预告了即将推出的自有软件工程代理（SWE agent），而 Anthropic 最近也发布了 Claude Code。这些事件表明，AI 实验室正倾向于向上游移动，进入基础设施和应用层。
#### 寻求新的盈利增长点
模型公司进入应用层的一个原因是，如果模型 API 的定价变得商品化，它们需要其他的途径来创造利润。基于自身模型开发的应用是一个自然延伸。但这可能引发渠道冲突问题：模型公司是否会限制其最先进的模型仅供自有应用使用，而通过 API 提供稍旧版本，从而在竞争中优待自己的产品？目前推测，短期内它们可能仍会优先考虑最大化模型使用率，通过 API 发布最新模型，但若它们越来越像应用公司，这种情况可能改变。应用层目前可能存在更多可挖掘的利润空间。
#### 获取关键的用户数据以改进模型
应用层能产生海量的用户数据，这可能是模型公司向上拓展的更重要原因。以 OpenAI 的 ChatGPT 为例，用户与其对话产生的多轮文本数据是极其宝贵的资源，有助于通过反馈循环（如让用户选择偏好的回答）改进模型。对于编码领域而言，虽然有大量开源代码库，但更多代码存于非公开仓库。编码助手应用能获取大量专有代码数据和用户交互反馈（例如用户选择哪个自动补全建议），这对改进代码生成模型至关重要。同样的数据价值也存在于生物、生命科学、法律、医疗等数据更倾向于私密的领域。拥有应用层可以建立数据反馈闭环，减少对 Scale AI、Surge、Mercor 这类数据标注服务商的依赖和成本。
#### 云软件公司估值指标更新
软件即服务（SaaS）公司通常基于其未来12个月（NTM）预期收入的倍数进行估值。这是一个简化的估值框架，因为多数公司尚未盈利或产生显著自由现金流（FCF）。
当前市场估值中位数：
- 整体中位数：4.7x
- 前五名中位数：17.7x
按预期增长率分组：
- 高增长（>27% NTM 增长）：中位数 13.7x
- 中增长（15%-27% NTM 增长）：中位数 8.7x
- 低增长（<15% NTM 增长）：中位数 3.7x
文章还讨论了 EV / NTM Rev / NTM Growth（估值倍数相对于增长率的效率）、EV / NTM FCF（企业价值与未来12个月自由现金流倍数）、估值倍数与增长率的相关性散点图。
关键运营指标中位数：
- NTM 增长率：11%
- LTM 增长率：15%
- 毛利率：76%
- 营业利润率：(6%)
- FCF 利润率：16%
- 净收入留存率：108%
- 客户获取成本（CAC）回收期：43 个月
- 销售与市场（S&M）占收入百分比：39%
- 研发（R&D）占收入百分比：24%
- 行政管理（G&A）占收入百分比：16%
文章还提到了 Rule of 40（收入增长率 + FCF 利润率）和毛利调整后回收期（GM Adjusted Payback）的计算方式。
### 总结
AI 基础模型公司进入应用层，主要是为了获取改进模型所需的用户数据，并探索模型 API 之外的潜在利润增长点。
