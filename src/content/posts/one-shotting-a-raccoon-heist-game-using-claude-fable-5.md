Claude Fable 5 已经能从一条旧推文和两张概念图出发，一次性完成可部署、可在手机上运行且经过自动化测试的 3D 浏览器游戏，但它展示出的主要突破是自主软件工程能力，游戏设计本身依然平庸、重复而缺乏乐趣。

Simon Willison 在 2022 年曾让 GPT-3 根据"一群浣熊组队实施盗窃"生成游戏简介，又让 DALL-E 制作概念截图；四年后的 2026 年 8 月 5 日，他把这些旧素材交给运行在 Claude Code for web 中的 Claude Fable 5，只补充了一份目标性提示：开发浏览器 3D 游戏，提供适合小屏幕的触控操作，调用 OpenAI 的 gpt-image-2 生成纹理，自主完成所有设计决策，尽快提交可展示标题页的 index.html，并在开发过程中频繁 commit、push，同时持续更新 notes.md。整个实验均由 Willison 在手机上发起和查看，没有指定技术栈，也没有进行后续设计干预。

为解决 Claude Code for web 开发期间难以预览的问题，Willison 使用 GitHub Pages 直接部署代理正在工作的分支：先创建仓库，让 Claude 尽早提交 index.html，再到仓库的 Settings → Pages 中选择"Deploy from a branch"并指定类似 claude/3d-raccoon-heist-game-50n293 的工作分支。此后每次 push 约 30 秒便会出现在公开页面上；这一方法同样适用于私有仓库，但生成的网站仍可被任何猜到仓库名称的人访问。频繁 push 因而把原本封闭的代理执行过程变成了可持续预览的开发循环。

Fable 5 自行选择了 Three.js，将其 vendored 到仓库以避免 CDN 依赖，又编写 gen_textures.py 调用 gpt-image-2 生成七张地面和墙体纹理，并在使用前抽查图片质量。它随后完成基础游戏，通过预装 Chromium 和 Playwright 在桌面、竖屏手机、横屏手机三种 viewport 下截图和运行测试；发现移动端看不到主角、垃圾箱基地和两只队友浣熊后，它自行定位并修复。它还用单独的 gen_title.py 生成低多边形夜景标题图，提示词明确包含戴黑色面罩的浣熊、金币、翻倒的垃圾桶、暖色窗户、满月与电影式轮廓光，不过最终桌面布局把图片裁得只剩上方三分之一，连主角浣熊都消失了，说明素材生成成功并不等于呈现效果也经过充分审美校验。

成品让玩家控制一只蒙面浣熊，从垃圾箱藏身处潜入月光下的郊区庭院，拾取金币、宝石、戒指、甜甜圈和鱼，再把战利品送回基地计分。物品会可视化堆在背上并降低移动速度；披萨提供 6 秒加速，稀有金色电视价值 120 分，但更难搬运。第一晚有一名用手电筒搜寻的守卫，第二晚增至两名，第三晚加入依靠嗅觉追踪、无视视线遮挡的猎犬；警车灯光扫过街道，屋主会随机从窗口探头，海鸥还会俯冲抢走未拾取的战利品。游戏提供三个结算等级——TRASH PANDA、CAT BURGLAR 和 MASTER OF DISGUISE——并用 localStorage 保存最佳成绩。移动端使用随触点出现的动态摇杆和 DASH 按钮，桌面端支持 WASD、方向键与空格。

猎犬是代理自主加入的最有价值机制：一只带红色尖刺项圈、会摇尾巴的低多边形棕色犬在随机位置间巡逻，玩家进入 12 个单位后便会被嗅觉锁定，拉开到 17 个单位才会脱离追踪，头顶的鼻子图标和吠叫用来传达状态。Fable 5 不仅编写了犬只的几何模型和步态动画，还通过暴露在 window.__rh 下的调试接口把玩家传送到猎犬附近，自动验证"游荡—追踪—抓获"的状态变化并截图检查。这种把创意、实现、可观测接口与回归测试连续完成的能力，是此次实验最突出的部分。

整个项目最终包含 7 次提交。自动化测试覆盖拾取、存放、追逐、被捕、黎明、夜晚升级、失败重试以及桌面和移动端流程，并实际发现两个仅靠表面演示很容易遗漏的问题：真实手机上的 canvas 被渲染为两倍尺寸，因为一次 cssText 赋值清除了 Three.js 写入的内联尺寸，而 DPR 为 1 的桌面测试此前掩盖了它；胜利画面的星级 div 又继承了标题页全屏 .stars 样式，悄悄拦截"下一晚"按钮的所有点击。两项问题均被修复并加入回归测试。游戏部署后不再调用外部 API，全部图像已作为静态资源提交，音乐和音效则由 WebAudio 程序化生成，包括与潜行氛围相称的 walking-bass jazz。

然而，完整的技术实现没有转化为出色的玩法。所谓"浣熊团队"只有垃圾箱旁两只纯装饰性的静态队友，没有任何分工、协作或团队机制；每晚的主要循环始终是捡物品、避开灯光、装满后返回存放。难度提升幅度很小，第三晚的猎犬才带来稍有意义的变化，而且游戏整体非常容易通关。固定夜晚时长还造成明显的节奏缺陷：玩家可能早早收集完全部物品，此后只能等待天亮。3D 场景、垃圾桶、手电筒光锥、统一的低多边形视觉、移动端支持和程序化配乐都达到了连贯可用的水平，但只能掩饰玩法层面的单薄，无法提供持续决策、风险变化或重玩价值。

Willison 因此把它评价为一个令人惊叹的单提示起点，同时也是一个质量中庸的成品游戏；他此前用 vibe coding 制作的其他游戏同样在玩法上令人失望。这个实验显示，编码代理已经能够自主选型、生成资产、构建完整系统、部署预览，并借助浏览器测试发现真实的跨设备缺陷，但"什么会让玩家觉得有趣"仍依赖经验丰富的人类反复设计、试玩和调节。游戏开发也因此特别适合作为代理能力的低风险试验场：它能同时暴露模型在工程执行上的长处，以及在互动系统、节奏和乐趣设计上的边界。
