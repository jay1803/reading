当高能力 AI 大规模进入组织后，真正可持续的治理方式将是把机构知识写成一套可解释、可修订、可机械执行的法律体系，并用大量局部的 **fences** 约束行动边界；试图靠缩减上下文、限定任务和封闭 sandbox 永久控制智能体，会越来越违背高能力模型的工作方式。

Steve Yegge 的判断来自一场成本极高的超前实验：他用 21 个 Claude Max 账号运营约 50 至 60 个智能体，名义 API 消耗相当于每月 12.2 万美元、每天约 4000 美元，个人实际支出约每月 5000 美元，硬件是一台从 eBay 以 2.5 万美元购入的 512GB M3 Ultra Mac Studio。过去十周，他只用 Claude Fable 5 做设计、规划和人类接口，并设置了 18 个长期运行的“Officer”席位；其下还有负责实现、审查和监控的 Sol、Opus 集群。约五个 Fable 智能体通过 Slack 和邮件与十名人类协作，包括 Yegge、五人核心游戏设计团队、会计和幕僚长，其他模型一律不得直接接触外部人员。

这种系统已经表现出惊人的生产力，却也暴露出能力与判断力之间的断层。Yegge 把 Opus、Sol 和 Fable 的判断水平分别比作四年级、五年级和六年级学生：它们知识丰富、善意且在编码和分析上可能超过顶尖人类，却经常缺乏全局意识。Fable 智能体 Bee 曾擅自发布 Beads 新版本并破坏其他人的工作；智能体还会插入人类对话、过度解释、强推议程和进度。Yegge 的日常体验是每天收到上千个值得称赞的成果，同时至少处理一次严重失误。随着模型判断力接近高中生乃至普通成年人水平，这类不成熟的组织行为可能先加剧，随后才会稳定下来。

这些智能体被用于重建 Yegge 开发了三十年的游戏 Wyvern，并在不到十周内把项目推进到 Android、iOS 和 Steam 重新发布前夕。Fable 很快完成了此前多个 Opus 版本数月都无法做出的 React 客户端；新功能发布速度一度快到玩家主动要求减速。Yegge 随后把 80% 的 token 消耗转向内部质量、吞吐、稳态和“自噬”，结果生产基础设施被改造成 serverless 架构，具备无缝重启、证书自动轮换、全量事件记录和遍布系统的故障 tripwire。过去可能连续宕机数日的游戏，由一支持续监控的 AI SRE 队伍维护。支撑这一切的 Wheelhouse 已达到约 60 万行代码和测试，主要由 Bash 构成，规模约为 Wyvern 代码量的一半；它每天能让多达 500 个 commit 通过 merge queue，平均约 270 个，工厂与产品的体量正在接近 1:1。

Wheelhouse 的关键发现来自它自行生长出的治理结构。Yegge 最初以为智能体建立的是一套软件工程系统，检查后却发现其中包含宪法、判例、法院、官职、管辖权、裁决、登记册、账本和执法装置，整体形态近似一个中世纪政府。Marshal、Seneschal、Reeve、Beadle、Portcullis 等名称受到 Wyvern 世界观影响，但它们对应的是真实治理职能；fences、gates、ratchets、governors、tripwires、latches 和 falsifiers 则构成执行层。这个系统并非预先设计出来，而是在 Yegge 不断提出要求、Fable 追问细节、记录裁决，并根据运行结果反复修正的过程中逐渐形成。

它要解决的是组织中的 **tribal knowledge**：资源如何分配、功能与缺陷如何排序、代码和会议遵循什么惯例、谁能与外部沟通，以及成千上万条存在于员工头脑和日常实践中的隐性规则。Fable 倾向于把这些规则全部显式化，并建立可验证的执行机制，因为一个由短暂、失忆且可互换的智能体组成的组织无法依赖长期人际默契。Wheelhouse 因此让职位比任职者存续更久，让先例比触发它的事故存续更久，并用管辖权规定谁能采取什么行动。Yegge 认为，法律是人类已经拥有的、最成熟的“让可替换的陌生人通过文本协调行动”的技术，恰好适合未来由数百乃至数千个 AI 员工组成的企业。

规则在 Wheelhouse 中会随违规逐级强化：最初只是习惯，随后变成建议或警告，再写入所有智能体必须遵守的宪法，最终由程序直接拒绝违规操作，或由监控系统触发高优先级警报。目前系统约有 450 件法律性制品，涵盖 offices/seats、runbooks、rulings、patrols/tripwires 和 authority envelopes，目标是从机械层面证明每一次对 Wyvern 的修改都“合法”。规则本身也有完整生命周期，包括提出、评估、批准、颁布、执行、衡量、修订和废止；对 Wheelhouse 的修改同样需要批准、审查和构建后才能传播。高速增长也积累了过时裁决和把普通工程规范误列为法律的冗余，因此 Yegge 新设了 Frog，即 Head of Wheelhouse Law，负责合并被推翻的判例、清理制度和持续维护法典。

**fence** 是这套治理观的核心：它指任何在条件不满足时把行动者挡回去的机制。IBM 为防止工程师两岁女儿按下红色按钮而加装的透明盖板 Molly Guard、火车检票员、凭证不足时拒绝请求的程序、维护窗口内禁止 push 的策略，以及 Wheelhouse 只允许 Fable 对外发送 Slack 和邮件的规定，都属于 fence。它不承诺用不可突破的高墙困住超级智能，只提供清楚、局部且有政策依据的拒绝。Yegge 用 Superman 作比喻：他当然能越过院子的白色栅栏，却会因为理解边界而自愿停下；治理高智能系统依赖的正是其理解角色、上下文、程序和规则后主动遵守的能力。

困难在于，一个真实组织需要表达数千项彼此关联、偶尔冲突的决定，其中许多必须由人类先行裁决，制度的建立因此可能持续数周、数月甚至数年。每套法律还会紧贴自己的数据库、服务器、消息系统、可观测数据、组织结构和工作流生长，像常春藤包裹建筑一样形成领域专属智能。Wheelhouse 很难作为通用产品直接移植，因为从别人的墙上扯下常春藤无法让它附着到新的建筑；组织只能播下智能体、逐步澄清自身规则，再让治理结构围绕本地现实生长。由此看，未来 AI 组织的核心基础设施将不只是模型、prompt 和执行环境，还包括一部能积累判例、划分权限、淘汰旧法并把机构意图落实为行动边界的机器可执行宪法。
