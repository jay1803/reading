## TL;DR
TCP 的可靠性设计核心是"端点智能、路由器哑巴"——重传、排序、流控、拥塞控制全在用户两端处理，中间路由器只管转发。这个设计让互联网可以无限扩展，但也意味着可靠性靠的是协议约定而非基础设施保障，任何绕过它的行为都会把代价转嫁给全网。

## 具体机制
- **端口 vs IP**：IP 把包送到正确机器，TCP 通过端口把数据交给正确进程。一条连接由五元组唯一标识（协议 + 源 IP + 源端口 + 目标 IP + 目标端口），64K 端口上限直接来自头部的 16 位字段。
- **序号与累积 ACK**：发送方给每段打序号，接收方回 ACK=N 表示"N 之前全收到"。中间有缺口时 ACK 停在缺口处——乱序检测和重传触发都由此驱动。
- **流控**：接收方在每个段的 `window` 字段通告剩余缓冲区大小，防止发送方把接收端打爆。
- **拥塞控制**：1986 年互联网带宽从数十 KB/s 暴跌至 40 bps（比特每秒），根因是丢包重传形成正反馈崩溃。由此引入的 slow start / backoff 算法让 TCP 在感知网络压力时主动降速，靠端点集体自律维持全网稳定。
- **三次握手**：SYN → SYN+ACK → ACK。需要握手是因为可靠传输必须维护连接状态（谁发了什么、收到了什么），握手让双方协商初始序号。

## 隐藏限制
- **窗口 16 位上限**：最大通告 64KB 接收窗口，高带宽高延迟链路（大 BDP）会成为吞吐瓶颈，实际需要 window scaling 扩展（RFC 1323）。
- **RST 攻击面**：任何能伪造五元组的中间人都可以注入 RST 强制断开连接——防火长城就是典型的工程应用。

## 留下的那个想法
互联网的稳定本质上是一个公共物品博弈：TCP 拥塞控制依赖所有端点集体"守规矩"，足够多的实现绕过它（如低质量 UDP 栈或恶意客户端），全网稳定性就会集体失效。互联网没有中央执法者，健壮性靠的是协议设计让自私行为代价高于合作。
