## TL;DR
FIFA 世界杯直播基础设施的授权逻辑全部放在前端，后端 API 从不验证角色——任何人只要通过公开的球员经纪人注册拿到 Entra 账号，就能在世界杯进行中替换任意摄像机的直播信号，甚至篡改比分与解说员数据。

## 关键时刻
- 作者在 agents.fifa.org 完成球员经纪人注册，FIFA 自动将账号加入其 Microsoft Entra 内部租户
- fdp.fifa.org 前端显示"您无任何角色，访问被拒"，但绕过客户端检查后，后端 API 毫无鉴权，直接返回完整的流媒体管理面板
- 面板内含世界杯全部赛事的 RTMP 推流地址和流密钥，均为生产环境实时数据；每场比赛有 5 个摄像角度（PGM 主播、战术机位、Camera1、高侧左/右），所有角度共用同一个流密钥
- 作者将预览 manifest 拖入 VLC，确认是从东京看到的赛事现场直播信号，随即关闭
- 同一账号还能访问解说员信息系统（cis.fifa.org）、写入比赛数据（修改比分、调整开球时间、发布战术阵容）、以及一个暴露 23 个内部 Excel 文件的 Azure Function

## 背后逻辑
- 根本原因：客户端读取 JWT 中的 NO_ROLES 标志并渲染拒绝页面，后端却信任任何经认证的租户成员，从不复核角色
- 流密钥共用逻辑使攻击成本极低：一个密钥，一个 RTMP 推流命令，即可劫持单场比赛所有摄像角度，将任意内容推送至全球转播链路
- FIFA 无 bug bounty、无 security.txt、无已发布的漏洞披露政策；作者在东京凌晨3点被迫依次致电 FIFA 苏黎世总部、达拉斯会展中心、MediaKind、HBS、CISA 24/7 值班线、FBI，最终 MediaKind 接听并响应，漏洞次日被修复

## 更大意义
- 漏洞修复为服务端返回 403，但 FIFA 始终未回复致谢、承认报告或讨论补偿，却仍将作者留在官方赛事文件分发列表中
- 这是一个教科书级的"客户端授权不等于真正授权"案例，同一失误影响至少三个内部系统，暴露的不仅是技术欠债，更是在最高曝光度赛事期间对安全响应渠道的完全忽视
