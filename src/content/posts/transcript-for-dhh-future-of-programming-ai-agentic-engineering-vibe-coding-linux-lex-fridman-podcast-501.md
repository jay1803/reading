## 嘉宾背景

David Heinemeier Hansson（DHH）是 Ruby on Rails 的创造者、37signals 的 CTO、Basecamp 与 HEY 等产品的共同建设者，也是作家、开源软件维护者和赛车手。他近年转向桌面 Linux，先后开发 Omakub 与基于 Arch Linux 的 Omarchy；最新版本 Omarchy Quattro 的开发几乎完全由 AI 代理执行代码实现，由他负责愿景、取舍、审查和发布。主持人 Lex Fridman 是 AI 研究者和播客主持人，也长期编程并亲自使用多种 AI 编程代理。

## TL;DR

DHH 的转变并不是从"相信手写代码"跳到"相信自动生成"，而是从把创造的价值寄托在亲自控制实现，转向接受自己只需控制作品的方向与形状。他反复强调，AI 带来的真正稀缺并非更好的提示词或更多算力，而是一个人是否足够清楚自己想把世界变成什么样，并愿意对不合适的结果说"不"。但当实现速度不再构成约束，人类也更容易陷入持续加速、身份失落和无止境优化；因此，这场技术跃迁最终迫使他们讨论的不是如何产出更多代码，而是什么值得创造、为何值得承受转型，以及有限的人生应当投入何处。

## 1. AI 代理的质变不只是提高编程效率，而是把人类从实现路径的决定者变成了可选的监督者

DHH 认为自己一年前对 AI 的判断并没有自相矛盾：当时可用的主要是自动补全和聊天助手，它们可以帮助查资料、解释问题或提高既有工作的效率，却没有改变他亲手雕琢代码的基本方式。真正的分界点是 2025 年 11 月 24 日发布的 Opus 4.5。几天后，他试着交给它一些任务，第一次看到模型产出在风格和质量上都接近自己会写、并且愿意直接合并的 Ruby 代码。关键不只在模型"更聪明"，还在 agent harness 能让它操作计算机、调用工具、运行测试、检查结果并修复错误，使抽象能力转化成完整工作成果。

随后，子代理又把长任务拆成多个并行部分，显著压缩完成时间，但早期阶段仍需要 DHH 指定目标、路线并持续审查。到访谈所说的当年夏天，Opus 5、Fable、GPT Sol 等模型开始能接收模糊的问题描述，自行规划路径、选择实现方法，并在出错后恢复；DHH 因而觉得自己在"如何产生代码"这部分已经变成可选角色。他仍会查看关键系统层的代码和整体结构，但在 Omarchy Quattro 中没有手写任何已发布的新功能，一些 UI 和辅助代码甚至没有逐行阅读。

Omarchy 是他判断这种变化已经超出演示阶段的主要依据。他还举出 Python 动画库迁移到无依赖 Rust 可执行文件的案例：模型自行制定计划、完成迁移、验证视觉效果和性能、建立仓库与软件包，并提交 Omarchy 的变更；不同前沿模型也能以不同时间和成本重复完成任务。在调试方面，代理可以从日志追到应用源码，定位具体缺陷，乃至发现尚未发布版本里的问题。DHH 把这类长程规划、自我验证和跨步骤协调称为"AGI 的闪现"，但明确没有声称它们已经在通常意义上成为全面的通用智能。

## 2. 当实现能力被商品化以后，软件创造的核心转向问题选择、品味判断与通过使用来发现需求

Lex 认为有编程基础的人能更系统地描述架构、验证和安全要求；DHH 则说，自己的资深经验一度反而成了限制：他会精确告诉代理按照自己熟悉的路径实现，而更新的模型在只得到问题或目标时，常能提出更好的方案。他以 Claude Code 系统提示大幅缩短为例，认为过度详细的人类指令不再只是多余，还可能压缩模型的方案空间。传统编程知识仍有助于判断架构、复杂度和变更比例，但它不再天然等于善于创造产品；很多程序员擅长实现，却未必知道软件应该为谁解决什么问题、第一版应该包含什么，或者什么样的交互才值得保留。

DHH 把新的开发方式与 Agile 的基本洞见联系起来：用户和开发者通常都无法在看到软件之前准确说清自己需要什么，因此不应试图先写出完备规格。更有效的方式是从足够模糊的意图出发，让代理迅速生成一个可用版本，再通过真实使用发现哪里不对、什么重要、什么可以删除。Omawrite 就是这种过程：他只提出要一个符合自己需求的 C++/Qt Markdown 写作工具，约二十分钟后得到初版，两天内便停止使用 Typora，之后都在自己的工具里写作。

在人类仍然占优势的环节上，两人强调"差异化评价"：与其要求人从空白处完整设计，不如让代理提供少量不同方案，人可以迅速判断自己偏爱哪一个。Lex 把这延伸到自然语言本身——有效提示不一定像规格书，也可以像诗歌一样，用带有风格和适度歧义的语言传达方向，让智能系统参与解释。DHH 接受模型输出的非确定性，认为同一提示产生不同答案正是创造性的一部分。人的控制因此从逐行规定实现，转成提出值得解决的问题、体验成品、选择方向，并在结构显得失衡或过度复杂时给出编辑式反馈。

## 3. 多代理并行将个人创造力放大到新的量级，却也使人类注意力和组织沟通成为主要瓶颈

单独等待一个代理工作，会让 DHH 感到被动甚至无用；同时驱动多个代理，则让他持续处于提出任务、回应问题和做决定的状态，重新获得类似心流的体验。他最初在 tmux 的多个 pane 中运行代理，后来使用带状态和完成通知的 Herdr，并通过 Tailscale、GL.iNet Comet KVM 和多台计算机把环境扩展到大约十六条并行线程。Neovim 已更多被用作项目浏览器和查看上下文的工具，而不是手写代码的主要场所。

他不会把同一个模型当成唯一裁判。常见流程是由 Fable 或 Opus 负责规划和实现，再用 Codex xHigh、Grok 或 GitHub Copilot 独立审查；第二个模型经常发现第一个遗漏的真实问题。代理也开始脱离实时聊天界面，被放进 Basecamp 的异步协作系统，像同事一样领取 to-do 或 card。DHH 还在构建定时运行的 Oma bot，让它自动处理 issue、PR、测试和报告，最终只通过邮件交给他少数"合并、关闭或改变方向"的决定。

这种并行并不意味着人类拥有无限带宽。DHH 和 Lex 都描述了持续任务切换带来的高强度疲劳：工作中几乎没有低能耗的"滑行"，而是一个问题刚结束就立刻进入下一个。DHH 将它比作在没有长直道的赛道上不断过弯——令人兴奋，也不可长期维持。他把这视为新范式诞生期的冲刺，预计随着协调、审查和故障处理进一步自动化，人不必继续全天看守代理。

大型组织也不会因为代码生成变快就自动获得同等提升。DHH 认为，团队的主要瓶颈往往是人与人之间的沟通、层层审批以及所有人都想参与塑形的组织机制，而不是实现能力。更根本的问题是，许多组织并不知道自己想要什么，缺少愿景、想法和品味；把低质量想法实现得更快，并不会产生好软件。因此，直接控制代理的个人和小团队可能获得十倍乃至更大的杠杆，而为旧生产方式设计的庞大组织很难立即完成同样的转变。

## 4. AI 扩大了能够创造软件的人群，但开放参与只有在强有力的筛选和统一愿景下才会转化为好产品

代理让个人可以不再等待通用软件覆盖自己的全部需求，而只实现自己真正使用的那部分功能。DHH 用 Omawrite、Omacut 和 Omarchy 插件说明这种变化：一个人可以先为自己制作高度定制的工具，再让代理完成 README、GitHub 仓库、release 和其他维护工作，使它自然具备被别人使用和贡献的条件。Omarchy Quattro 发布后数日内出现数百个插件；DHH 在三个月里合并了一千多个 PR，其中许多来自非传统程序员或没有 Linux 发行版开发经验的人，原本停留在他们脑中的想法因代理而变成了可审查的实现。

但他并不认为民主化意味着所有贡献都应进入产品。Basecamp 5 早期曾让设计师直接进行 vibe coding，短时间产生了许多单独看似合理的 PR，叠加后却破坏了系统架构，团队不得不人工清理。这让他区分了从零制作个人工具与修改大型既有代码库：后者至少在当前仍需要理解整体结构的人把守架构。代理遵循指令、补测试和整理说明的能力，也不能自动提供跨越整个产品的一致愿景。

DHH 对开源维护者的回答不是阻止 AI 贡献，而是更坚定地筛选。代理可以先排除重复、错误或未经验证的 PR，在虚拟机中复现并测试剩余方案，再把少数成熟候选交给维护者。维护者没有义务帮助每一项贡献落地，可以直接拒绝不符合路线和审美的改动。由此形成的是"广泛生成、严格策展"：更多人和模型提供创意，少数对产品负责的人维持方向、架构和取舍。DHH 认为，这种模式既扩大了开源参与，也使从头开始的新项目更有机会挑战被旧流程和既有产品束缚的大公司。

## 5. Linux 的开放、可配置与可诊断性使它从面向专家的困难系统转变为最适合代理改造的个人计算平台

DHH 认为，Linux 过去最劝退普通用户的特征——配置文件、命令行、公开源码和晦涩而具体的错误信息——恰好成为代理时代的优势。macOS 和 Windows 的大量设置被封装在 GUI 或受控接口中，难以完整自动化；他以 Raycast 配置和 macOS 默认快捷键为例，称许多操作仍需要手动点击。Linux 则把系统状态暴露给工具：代理可以读取配置、调用 CLI、检查 systemd 日志，并在必要时追踪到应用或上游项目的源码。

Omarchy Quattro 的 crash watcher 展示了这种可诊断性：应用崩溃后，用户可以让默认代理分析日志、定位源码中的具体问题并准备 bug report。DHH 还讲到 mise 的竞态条件；代理不仅找到问题，还下载了项目源码，发现开发者已做但尚不完整的修复，并在新版本发布前将进一步的问题报告给维护者。对普通人而言无法理解的错误文本，在熟悉大量开源代码的模型面前反而成为精确入口。

Omarchy 试图同时提供强烈预设与开放修改，而不是让用户从空白 Arch 系统开始组装一切。它预装 DHH 选择的工具、主题和工作流，能够快速安装并立即投入使用；同时，用户可以通过自然语言创建插件、替换面板、增加股票显示或改变系统行为。DHH 不想把它做成廉价模仿 macOS 或 Windows 的熟悉桌面，而是明确押注 tiling interface、终端和"可塑计算机"。他把这看作早期个人计算愿景的回归：Commodore 64 启动后直接进入 BASIC，本来就是可编程的，只是过去需要掌握"象形文字"；代理现在把这种能力翻译成了日常语言。

## 6. 卓越来自对现实限制的不耐烦，而代理让原本近乎荒谬的目标变成持续发现和创新的发动机

Omarchy 的安装目标最初只是十五分钟，已经远快于 DHH 设置新 Mac 所花的四十二分钟和设置 Windows PC 所花的一个半小时。达到两分钟后，他开始追问为什么不能低于一分钟；突破一分钟后，又转向针对特定硬件制作可能在约十二秒内完成的 turbo image。对"几分钟已经够快"的质疑，他引用 Mitchell Hashimoto 的话回应："追求卓越无需解释。"在他看来，速度、美感和使用愉悦本身就值得追求，不必先证明短期商业回报。

明确的数字把优化变成游戏，也迫使他们重新检查默认顺序。代理尝试在用户填写姓名、密码和时区时预加载数据，并行执行原本串行的步骤，改变安装流程，缩减镜像尺寸，重新打包字体与 NVIDIA 驱动。把完整 JetBrains 字体包替换成实际使用的精简版本、提高压缩等级等工作，每次只节省若干兆字节或几秒，却让团队理解更多底层限制。DHH 把这种过程比作 McLaren 工程师从整辆车上继续削减数百克重量：局部收益看似不成比例，持续追逐却会积累成另一类产品。

Lex 补充说，数值目标也会产生与指标本身无关的外溢发现，如登月任务推动其他工程能力。DHH 同意，并把一分钟安装、四分钟一英里、超深潜水表和过度建造的 Mercedes-Benz W126 放在同一类追求中：当一个人拒绝把当下行业惯例视为自然极限，略微超出"合理"的目标就可能重画整个类别的边界。代理的作用是降低试验每一种猜想的成本，让这种不耐烦能够持续转化为实际迭代；但最终驱动它的仍是人对某种具体卓越的执着，而非单纯增加代码产量。

## 7. 技术进步要求人们放下以旧技能定义的身份，但真正支撑适应的不是无限优化，而是创造、关系、责任与有限生命带来的意义

手写优美的 Ruby 代码曾同时给 DHH 带来工艺满足和经济价值。保持架构简洁、连贯、可修改，可以让小团队以较低成本长期演进软件；在 token 和上下文仍有限的当下，这些品质对代理同样有价值。不过，他认为亲自雕琢每一行代码的经济回报正在快速下降。手写代码不会消失，就像人们仍会为旧游戏机制作新游戏或为了体验而骑马，但它可能从主流生产方式变成一种自愿选择的工艺。

DHH 并不否认由此产生的失落。Lex 把变化描述为向旧编程世界告别，DHH 也承认，允许自己短暂哀悼是一种合理的适应方式。他只是没有强烈依恋，因为自己最初学习编程并非迷恋条件语句，而是想让不存在的东西出现；代理让他回到了这个出发点，并提供了比过去更大的表达空间。Quattro 虽然是他亲手写代码最少的重大版本之一，却仍让他极为自豪，因为满足感已经从个人完成每个动作，转成像教练或编辑一样塑造团队成果。他把这种身份变化与退役运动员寻找比赛之外的新角色相比较。

对于程序员的就业前景，他同时保留两种可能：软件价格下降可能扩大需求，就像 ATM 降低银行网点成本后一度增加柜员数量；但生产率的含义也确实是用更少的人完成同样的工作，某些岗位会消失，具体劳动者将承受真实而艰难的过渡。DHH 支持生产率增长，却没有说个人痛苦因此不重要。他建议不要推演两次模型迭代之后的职业世界，因为连最了解前沿的人也无法预测；当前更可行的是学习现有工具、参与建造，并通过开源共同体与其他人建立联系。即使离开一年，快速变化的工具也可能在两周内重新赶上，因此没有必要把持续追逐每一种短暂技巧当作生存条件。

谈到更长远的适应，DHH 把希望与对子女的具体责任联系起来。成为父亲让未来不再只是抽象的经济增长，而是孩子将要生活的世界；养育所要求的牺牲，也因为指向所爱之人而获得意义。他认为不同历史时期的人都经历过看似独一无二的剧变，而爱、创造、共同体和责任并未因此失效。

这种有限的人类尺度也贯穿他对长寿和自我优化的态度。他不认同"Don't Die"式的无限延寿目标，认为九十到一百年的人生大致足够；但他承认，如果真有永生药，自己是否会改变立场仍是未知。他停止佩戴 Oura Ring，是因为睡眠评分只是在已经知道睡得不好的情况下再增加一层提醒。对于戒酒、饮食和健康指标，他与 Lex 讨论的不是否定健康，而是避免把单项指标优化到挤压社交、亲密关系和真实体验。Omarchy 日历中的 memento mori 功能会显示一年和预计人生已经过去的比例；DHH 喜欢这种提醒，因为死亡不是需要从生活中排除的故障，而是使时间、选择和投入获得重量的边界。

## 提到但未深入展开的话题

两人还谈到公共表达与政治分歧。DHH 以欧洲大规模移民为例，主张禁忌议题只有在人们愿意承担声誉代价时才会进入公共讨论，同时承认相关讨论可能滑向种族主义；他和 Lex 都希望恢复一种能够容纳强烈分歧、又不把人永久归入政治阵营的文化。其他话题包括 Fable、Opus、Sol、Grok、Kimi 和 DeepSeek 的能力、成本与分工，Claude Code、OpenCode 和开放权重模型，AI 安全及攻防能力，语音提示和转录工作流，AI 电影、互动叙事与模型意识，OpenClaw、Hermes Agent 和具有长期记忆的个人代理，社交媒体推荐算法对愤怒、成瘾和政治内容的放大，Linus Torvalds 的领导与沟通风格，PewDiePie 作为非传统软件创造者的示范，Omarchy 手机版和浏览器开发，赛车造成的身心耗竭，对 20 世纪八十年代的怀旧，以及丹麦羊角面包、博物馆餐厅、海鲜和旅行饮食等生活趣谈。
