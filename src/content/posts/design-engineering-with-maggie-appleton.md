AI 加速了设计原型的实现，却把人的核心工作进一步集中到问题定义、交互判断，以及让人和 agent 能共同操控的工具上。Maggie Appleton 在 GitHub Next 担任 staff research engineer，通过原型探索软件工程师与 AI 协作的新方式；她把设计与工程都视为解决问题的过程，两者使用的材料不同，而理解工程约束能让设计师与工程师更有效地合作。

Maggie 的职业路径连接了 cultural anthropology、视觉表达和前端开发。毕业后，她曾面对一条可能通向为美国军方发明酷刑技术的职业道路，拒绝后转向科技行业。她在开发者教育公司 Egghead 做了四年插画师，后来成为 art director；为了准确画出 React components、useEffect 和 JavaScript functions，她必须先理解这些概念，插画工作因此成为她学习前端工程的途径。她也为 Dan Abramov 的 Just JavaScript 课程制作过插画。人类学背景则让她持续关注软件背后的人与关系：技术功能的成立，并不保证人愿意采用它。

这种差距在她担任 Elicit 首位设计师时变得具体。2021 年，距离 ChatGPT 发布还有一年，团队已尝试用 LLM 加速科学研究，并花数月探索“新的 AI 界面”，包括带卡片的 infinite canvas 和类似 Notion 的可组合文档。科学研究者最终想要的却是熟悉的简单表格。这个经历让她认识到，即使底层能力发生变化，产品仍可以从用户已经掌握的交互原语起步，减少理解和使用的负担。设计还必须为新能力建立合适的名称与动词，让用户知道有哪些对象、能执行哪些操作；卖运动鞋的网店已有成熟词汇，新的 AWS 产品则可能需要重新建立这套概念体系。

在确定这些问题之前，Maggie 经常先用纸笔画草图。手绘一个想法通常比向 Claude Code 描述它更快，而且草图第二天仍留在笔记本里，不会被后续几十轮 prompt 淹没。这也暴露出当前 agent 规划流程的局限：连续提出大量 A、B、C 选择题，会把思考变成密集的决策负担。她描述，用户到了第二十题就可能疲惫，尤其当 agent 已标出“A 为推荐选项”时，容易开始不断按回车接受建议。流程虽然获得了确认，人的判断却可能已经退出。

为了在实现阶段保留直接控制，Maggie 会让 coding agent 制作她称为 **jigs** 的交互原型。这个名称来自木工中辅助特定操作的夹具：原型附带 sliders、color pickers 等控件，让她实时调整颜色、尺寸和动画速度，相当于为当前任务搭建一个个人版 Figma。它把反复描述修改要求的工作，转化成可以直接观察和操控的参数。确定要构建什么之后，她会写详细 spec，并列出 agent 应如何验证成果；随着新一代模型能力提升，她在工作中已不再查看生成 PR 的代码。这个做法适用于她的原型探索场景，不能据此推导生产软件也可以省略代码审查。

把实现交给模型仍需要警惕 **capability gaslighting**。Maggie 用这个词描述一种能力错觉：frontier model 今天表现得像专家，第二天却在同类任务上严重失败，用户仍因先前的成功而相信它具备稳定能力。一次出色表现不足以建立持续可靠的预期，agent 也存在同样的问题。模型能够生成设计，并没有消除人的判断与风格选择；人还要评估生成结果是否适合具体用户、任务和体验。

这种协作的更深层障碍，是双方依赖的材料不同。Agent 的世界包含 weights、models、skills 和 MCPs，人的思考则与实体、纹理、光线和材料相连。Maggie 希望 agent 能像站在身旁的协作者一样，看懂笔记本里的草图并帮助推进想法，但现有工具还难以做到。纸上草图与可调参数的 jigs 因而指向同一个需求：为人和 agent 建立共同可理解、可操作的工作对象。工程师也可以把 AI 当作耐心的设计导师，询问何时调整 line height、怎样设计 sidebar、每行容纳多少字符，逐步补足过去较难获得的产品设计知识。AI 带来的设计收益，取决于人能否在更快的实现过程中持续看清问题、操控结果，并验证自己的判断。
