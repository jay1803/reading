## TL;DR
一个没用过终端的家庭主妇用五台 Mac Mini 各跑一个 AI Agent，做出了孩子专属无垃圾电视 App；一家千人工程团队 15 分钟推了 75 个 PR，把 PR review 周期从 150 小时压到 15 小时——两件事说的是同一件事：AI 现在已经可以让"完全没有相关经验的人"直接越级到有工程能力。

### 案例一：Jesse Genet 的五 Agent 家庭操作系统

#### 核心机制：物理隔离即安全策略
Jesse 给每个 Agent 各配一台 Mac Mini，不是炫耀预算，而是解决数据泄露问题：财务 Agent 能读银行账单但不能发任何消息，调度 Agent 可以发短信但没有财务数据。隔离的是权限边界，不是机器。

#### 照片是最低摩擦的结构化输入
核心工作流极简：拍照 → 发给 Agent → 得到结构化输出。课程材料、实体玩具、书页、补给品，全部通过照片进入 Agent 的上下文。Agent 负责分类、记录、关联，人只需要举起手机。

#### "决策文件"防止 Agent 反复重开已关闭的问题
Jesse 在 Obsidian 里维护一份决策文件，每个 Agent 都知道这份文件的存在。一旦一个问题被标记为"已决策"，Agent 就不再质疑或重问。简单，但对付反复询问同类问题的 Agent 非常有效。

#### 没有终端经验照样能用编码 Agent 交付真实软件
Jesse 四天时间和 Cole（编码 Agent）迭代，做出了部署到 Google TV 的儿童无广告流媒体应用。方法：描述想要什么 → Agent 说"做不到"时推回去 → 持续迭代。技术背景不是前提，持续推回去才是。

### 案例二：Coinbase 千人工程团队的 AI 采用路径

#### "Speed run"：用一次高密度冲刺打破惯性
100 人同时跑 Cursor 15 分钟，推出 75 个 PR。这个活动同时完成三件事：建立"AI 真的能提速"的组织级共识、暴露有效工作流、把旁观者转为参与者。

#### 领导者亲自写代码，而不是倡导采用
Chintan 花数月每天自己用 Cursor 修 bug、写功能，然后才让团队采用。现在他的日历几乎是空的——AI 消灭了协调开销，他把时间还给了写代码。

#### 指标要落在流程级别，而不是用量
PR review 时间从 150 小时降到 15 小时，用户反馈到功能上线的周期从数周压缩到分钟级。这些指标直接映射交付速度，比"AI 调用量"更能说明问题。

#### 用 AI 分析 AI 使用数据，识别 power users 行为模式
Coinbase 用 Cursor 本身分析 Cursor 的使用数据，把工程师分成从"不活跃"到"超级用户"的群组，发现 agent 重度用户的生产力是其他人的 16 倍。这个数字驱动了后续针对不同群组的定向辅导。

#### 从"反馈"到"上线"的自动化闭环
用户反馈采集、优先级判断、任务生成、代码实现、验证——Coinbase 把这个链路打通成近实时的自动化闭环，让 AI 的价值从"写代码"扩展到"加速产品学习循环"。

### 边缘判断
两个案例放在一起，暗示了一个尚未被充分讨论的风险：当"没有经验"和"有一千人团队"都能用 AI 达到同等交付速度时，真正的壁垒会从"能不能做"转移到"知不知道做什么"——而这恰好是 AI 目前最帮不上忙的地方。
