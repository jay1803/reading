## TL;DR
Prompt bar 已成新 SaaS 标配，但界面同质化后激活反而更难——真正的分水岭在于谁能把空白输入框变成可重复的价值时刻，而不只是一次 wow。

## 核心洞见
传统激活路径（Setup → Aha → Habit）正被 Prompt → Context → Output → Action → Habit 的对话循环取代。激活不再是注册后的阶段，而从用户开始输入的瞬间就持续发生。这把所有 onboarding 设计压力压到"第一个 prompt 及其直接下一步"——没有这一环，后面所有的习惯都无从建立。

## 具体机制
作者分析了 40+ 款 AI 产品，提炼出有效模式：
- **具体化示例 > 开放邀请**：Canva 给"设计社交帖"而非"输入任何东西"，每个入口直通一个定制化体验；Replit 的首页示例在教用户如何写好 prompt
- **按任务类型组织建议**：Zapier 按工作流类型分组，Gamma 用标签式 CTA，让用户看见选项时就建立心理模型
- **显式 vs 隐式 Context 都有效**：Lovable 仍用经典问卷做个性化；Notion 靠占位文字和示例传达角色边界——两路目标相同：让输出"感觉是为我准备的"
- **输出后保持动能**：Bubble 在生成后立即给出三个自然后续操作，避免用户在第一个 wow 后流失；Blink 在输出中嵌入追问
- **社会证明即转化**：Lovable / Vercel 首页展示用户生成案例，让人看见可能而非只看见承诺；Rork 的"Published with Rork"标签同时承担品牌背书和灵感触发
- **别给产品贴错标签**：Airtable 把 Omni 定位成"研究助手"，却埋没了它作为数据库构建工具的核心能力——入口处的认知定锚在悄悄缩窄用户想象

## 隐藏限制
对 Context 捕获中"隐式推断 vs 显式提问"哪种激活效果更好，作者只说"都行，看情况"，无数据支撑。文章在付费墙前被截断，后半部分框架未能读到。

界面越来越像是表象；示例选择才是真正在告诉用户"这个产品是什么"——这比任何 UX 设计细节都更早、更深地塑造用户的预期。
