## TL;DR
Cloud 应用提供了便捷的协作，但用户失去了数据的真正所有权；传统的本地应用确保了用户的所有权，但协作困难。Local-first 软件是一种新的软件范式，它将本地设备上的数据视为主副本，通过后台同步实现协作，旨在结合两者的优点，让用户在享受云端协作便利的同时，也能完全拥有和控制自己的数据。

### 主题
#### Cloud 应用与传统应用的矛盾
Cloud 应用（如 Google Docs, Figma）让实时协作和跨设备访问变得简单，但其根本问题在于数据存储在服务商的服务器上，用户实际上并不完全拥有自己的数据。用户受制于服务商，面临服务中断、数据丢失、隐私泄露以及功能强制变更的风险。
传统应用将数据存储在本地文件中，用户拥有完全的自主权和控制权，可以永久保存和备份。然而，这类应用在多设备同步和实时协作方面表现不佳，容易产文件冲突和版本混乱。
Local-first 软件的目标是结合两者的优点：既有 Cloud 应用的无缝协作，又有传统应用的个人数据所有权。

#### Local-first 软件的七个理想
Local-first 软件将本地设备上的数据副本作为主数据，服务器仅作为辅助同步和备份的次要角色。这种模式带来了七个理想特性：
1.  *即时响应，没有加载动画*：由于数据在本地，所有操作都能立即响应，无需等待网络请求，数据同步在后台安静进行。
2.  *数据不被困于单一设备*：数据可以在用户的多个设备（手机、平板、电脑）之间同步，支持跨设备工作流。
3.  *网络连接是可选项*：软件在离线状态下功能齐全，用户可以随时读写数据。当网络恢复时，数据会自动同步。
4.  *与同事无缝协作*：支持像 Google Docs 一样流畅的多人实时协作，同时也能支持类似 Git pull request 的异步协作模式。
5.  *数据可被长期存续 (The Long Now)*：由于软件和数据都在本地，即时软件公司倒闭，用户依然可以通过虚拟机或模拟器在未来几十年甚至更长时间里访问自己的数据，避免“数字黑暗时代”。
6.  *默认安全和隐私*：数据存储在用户本地设备上，避免了中心化服务器成为攻击目标。通过端到端加密，云端服务器只能存储无法读取的加密数据。
7.  *用户保留最终所有权和控制权*：用户对本地数据拥有完全的控制权，可以任意复制、修改和处理，不受任何服务商的 API 或服务条款限制。

#### 现有数据模型的评估
- *文件 + 邮件附件*：速度快、可离线、用户控制权高，但协作性极差，多设备同步笨拙。
- *Web 应用 (Google Docs, Trello)*：协作性好、支持多设备，但速度慢、离线功能弱、用户几乎没有数据所有权和控制权。
- *云同步服务 (Dropbox, Google Drive)*：在桌面端表现好，速度快、可离线、用户控制权高。但在移动端体验差，且无法解决多人同时编辑同一文件产生的冲突问题。
- *Git 和 GitHub*：最接近 Local-first 理想的模型，完全支持离线工作，用户控制权高。但它主要针对基于行的文本文件（如代码）设计，对其他文件格式支持不佳，并且不支持实时、细颗粒度的协作。

#### CRDTs：实现 Local-first 的基础技术
Conflict-free Replicated Data Types (CRDTs) 是一种从底层就为多用户协作设计的数据结构。与传统数据结构不同，CRDTs 可以在不同设备上被独立修改，当设备联网后，这些修改可以被自动、无冲突地合并。
CRDTs 能够处理细颗粒度的变更（例如单个按键），从而实现类似 Google Docs 的实时协作体验。它不关心数据同步的渠道（可以是服务器、P2P 网络或 U 盘），这使其成为构建 Local-first 应用的理想基础。
Ink & Switch 团队基于 CRDTs 开发了开源实现 [Automerge](https://github.com/automerge/automerge)。

#### 原型实践与发现
Ink & Switch 团队开发了三个原型应用 (Trellis, Pixelpusher, PushPin) 来验证 Local-first 软件的可行性，并得出以下结论：
- *技术可行*：CRDT 技术可靠，自动合并数据的功能表现出色。
- *离线体验极佳*：用户可以在离线时自由工作，联网后无缝同步，没有数据丢失的焦虑感。
- *开发者体验良好*：CRDTs 与函数式响应编程 (FRP) 模型（如 React）结合得很好，简化了协作功能的开发。
- *冲突并非大问题*：由于 CRDTs 能处理细颗粒度的语义化变更，并且用户在协作时会自然地避免冲突，实际工作中很少遇到需要手动解决的冲突。
- *可视化历史很重要*：提供类似 "time travel" 的界面，帮助用户理解文档的演变过程。
- *性能问题*：CRDTs 会存储所有历史记录，导致性能和存储占用成为挑战，这是需要持续优化的主要领域。
- *网络通信仍是难题*：P2P 技术尚不成熟，NAT 穿透等问题仍未完全解决。服务器在 Local-first 架构中依然有其作用，例如作为数据备份、发现节点或提供计算资源，但其角色从“中心权威”转变为“辅助支持”。

### 总结
Local-first 软件是一种旨在通过将数据所有权归还给用户来重塑未来的软件开发范式，它利用 CRDTs 等技术，在不牺牲现代云应用无缝协作能力的前提下，确保了数据的持久性、隐私和用户自主权。
