## TL;DR
初创企业应首先定义一个极其狭窄的理想客户画像 (Ideal Customer Profile, ICP)，即使最初的尝试可能不准确，也需要通过不断迭代来找到最佳定位，从而实现产品市场匹配并为后续扩张打下基础。本文汇集了 Vanta, Clay, Retool, Okta, Pilot, Productboard, Webflow, 和 Thena 等公司创始人的经验，分享他们如何找到并优化各自的 ICP。
### 主题
#### 定义狭窄 ICP 的重要性
选择一个极其具体的 ICP 对于初创公司至关重要。广泛的目标客户群体会导致产品路线图被不同方向的需求拉扯，营销信息变得泛化，网站上展示的客户案例也可能与潜在目标客户不相关。一个恰当的 ICP 应该非常明确，具体到公司阶段、行业、买家画像、当前使用的解决方案，甚至是促使他们购买的触发事件。目标是让特定买家画像的用户在看到产品时，会产生“这就是为我量身定做的”感觉。
#### ICP 的假设与验证过程
即使在产品仅有初步设想（例如，只有几张幻灯片上的模型）的阶段，创始人也应为其公司定义一个关于 ICP 的工作假设。First Round 提出的 "4 P’s" 框架——人 (Person)、问题 (Problem)、承诺 (Promise) 和产品 (Product)——强调了首先明确“人”的重要性。这个假设需要通过数百次的客户对话来不断验证和调整。最终，创始人会感受到那些迫切需要产品的潜在客户与那些仅觉得产品“有趣”的客户之间的显著差异。ICP 并非一成不变，它会随着公司的发展和市场的变化而演进。
#### Okta：从小处着手，逐步扩张
Okta 在2010年创立时，企业对将 SaaS 应用迁移到公有云仍持谨慎态度。Okta 最初并未将大型企业作为目标客户，因为相较于中小型企业 (SMBs)，大型企业当时对云端应用的依赖程度不高。
- 初始 ICP：拥有三个或更多 SaaS 应用的 SMBs。
- 选择 SMBs 的原因：他们的需求更为一致，这使得 Okta 更容易构建可扩展的业务，并专注于较小的功能集，从而形成更清晰的产品路线图。相比之下，满足五个大型全球企业各自不同的需求会使产品构建更加困难。
- 扩张策略：Okta 的增长策略如同剥洋葱，核心解决方案对更大的客户依然有价值，只需在其基础上增加满足其更复杂环境和本地系统需求的额外功能。例如，大型企业同样需要连接 SaaS 应用到其公司目录。
#### Vanta：为 ICP 构想更美好的未来
Vanta 的联合创始人兼 CEO Christina Cacioppo 在探索创业想法时，最初尝试了语音助手等方向。通过大量用户访谈，她发现安全合规是许多公司普遍存在的痛点。
- 关键转折：与 Figma 的一次交流。当时仅有30人的 Figma 为了争取 Google 这个客户，将 Google 的安全调查问卷变成了自己的产品路线图。这让 Cacioppo 关注到了 SOC 2 认证的重要性——这是 SaaS 公司获取企业客户的关键，证明其数据安全能力。
- Vanta 的 ICP 假设：如果能自动化 SOC 2 流程，帮助初创公司更容易地获得认证，从而赢得企业客户，这将是一个巨大的机会。尽管当时获得 SOC 2 认证的初创公司很少。
- 核心理念：预见并解决 ICP 未来会面临的压力和需求，帮助他们进入更高层次的市场。
#### Clay：克服“承诺恐惧症”，专注单一 ICP
Clay 提供将 API 连接到电子表格以丰富数据的功能，最初吸引了各类用户，包括招聘人员、销售人员和前端工程师。尽管产品功能强大，但五年后收入仍接近于零，用户在初步兴奋后并未持续使用。
- 问题：试图满足所有潜在客户的需求，导致产品价值主张不清晰，团队过于“ malleable ”（易受影响）。
- 解决方案：创始人 Kareem Amin 决定选择一个特定的 ICP——出海销售团队，并全力投入。
- 原因：Amin 意识到需要先专注于一个领域，清晰地测试并快速获得反馈，以此“赢得执行更广泛使命的权利”。
- 感悟：缩小范围实际上能提升价值；宏大的愿景不能取代解决当前实际需求的重要性。Clay 的主页也从泛化描述转变为针对特定用户群的精准营销。
#### Retool：系统性测试 ICP 假设
Retool 是一个供开发者快速构建内部工具的拖拽式平台，在公开上线前就获得了40个客户和200万美元的 ARR。创始人 David Hsu 将寻找 ICP 的过程视为科学实验。
- 初始错误假设：
  - 目标用户：FileMaker 开发者。Hsu 通过渗透 LinkedIn 上的 FileMaker 开发者社群并发起大规模外展活动进行测试，结果显示产品市场匹配度 (PMF) 不高，收到的回复很少，唯一的通话对象认为 Retool 是个糟糕的主意。
  - 公司规模：2-3人的小型初创公司。
- 迭代后的正确 ICP：
  - 目标用户：主要使用 React 或 JavaScript 的前端和后端开发者。事实证明，这些工程师虽然通常不喜欢拖拽式编程工具，但他们更讨厌从头构建内部工具。
  - 公司规模：大型企业。一个早期客户是一家财富250强公司，拥有约12万名员工，每年花费4亿美元构建内部工具。
- 发现：全球约50%-60%的软件是面向内部的，这是一个巨大的市场。
#### Pilot：选择“困难模式”的 ICP 进行压力测试
Pilot 提供月度订阅式记账服务，其创始人 Waseem Daher 基于前两次创业经历，深知财务和会计处理对于早期创始人的痛点。
- 初始 ICP：在确定产品方向后一天内，Pilot 就将 ICP 定位为初创公司。
- 选择初创公司的原因：这是一个“困难版本”的问题，因为初创公司的会计需求变化极大，从两人小团队到拥有财务副总裁和主计长的三百人公司，需求差异显著。
- 目的：通过解决这个复杂场景的问题，可以对模型进行压力测试，并防止产品过度拟合某个特定的、过于简单的用例。
#### Productboard：找到通往更大细分市场的视线
Productboard 的创始人 Hubert Palan 曾是一名产品经理，他深感当时流行的工具（如 Jira, GitHub）主要服务于工程师，而缺乏满足产品经理需求的功能，例如处理客户反馈和痛点。
- 明确 ICP 的过程：Palan 制作了一个 Keynote 原型，并与数百人交流。他将对原型表现出兴奋的人记录在电子表格中，并根据七个关键维度进行分析：公司规模、产品阶段、数字优先或数字化转型、单一产品与多产品、产品组织规模、对客户的关注度、B2B与B2C。
- 早期 ICP：早期阶段、数字优先、具有强大客户中心和产品导向文化、拥有一个产品团队、构建单一（理想情况下）B2B产品的初创公司。
- 策略：初期专注于非常简单的产品团队。如果能证明有足够多的人符合这个初始细分市场，那么就找到了进入其他更大细分市场的“视线”。
- 建议：在寻找产品市场匹配时，要明确目标细分市场的标准。对于那些不符合标准的人，应礼貌地结束访谈，避免浪费时间。
#### Webflow：选择最“弱势”的用户群体
Webflow 最初的想法是构建一个可视化的 Web 应用构建器，但因问题定义过于宽泛和解决方案过于宏大，其 YC 申请被拒。联合创始人 Bryant Chou 加入后，帮助团队明确了方向。
- 突破口：关注自由职业网页设计师。联合创始人之一 Sergie Magdalin 曾是自由职业平面设计师，深知其痛点：设计师需要将 Photoshop PSD 设计稿交给开发者编码，并为此支付高达50%的收入。
- 市场创造：Webflow 旨在将网页设计和网页开发这两个原本分离的领域结合起来，为“设计师-开发者”这一当时尚不存在的市场创造产品。他们顺应了响应式网页设计、移动优先、HTML5 统一标准以及设计重要性日益提升的趋势。
- 核心理念：通过解决特定群体的痛点，逐步实现更宏大的愿景。Webflow 最初被拒的 YC 申请中“重塑软件开发”的愿景，在十年后演变为公司使命——“将开发超能力带给每个人”。
#### Thena：寻找“相似者”
Thena 是一个现代 B2B 票务平台，其创始人 Mike Molinet 在成功将 Branch 扩展到1亿美元规模后，运用其二次创业的经验来定义 ICP。
- Thena 的 ICP：向技术型利益相关者销售技术产品的公司，例如 API, SDK 和安全类公司。
- 原因：这类公司的产品技术复杂度越高，对持续互动和支持的需求就越迫切。相比之下，那些产品简单、销售结构一次性的公司则不需要持续互动。
- 战术方法：使用 Keyplay 等工具进行客户列表构建。具体做法是分析现有已购买客户的特征，然后创建一个包含500家特征高度相似的公司列表，从而实现精准营销，避免“广撒网”式的低效做法。
- 核心观点：ICP 的假设一定会改变，而不是可能改变，需要持续迭代。
### 总结
初创企业成功的关键在于勇敢地选择一个狭窄的理想客户画像 (ICP)，谦逊地承认最初的错误，并坚持不懈地迭代，直到找到最适合的市场切入点，进而实现增长和扩展。
