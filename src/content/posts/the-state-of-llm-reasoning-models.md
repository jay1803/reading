## TL;DR
这篇文章主要讨论了大型语言模型（LLMs）在推理能力方面的最新研究进展，特别关注于推理时间计算扩展（Inference-time Compute Scaling）的方法。自从 DeepSeek R1 发布以来，出现了许多新的推理时间计算扩展方法，通过增加推理时的计算资源，可以显著提高 LLM 的推理能力，甚至可以让较小的模型在特定任务上超越更大的模型。
文章详细介绍了一系列最新的研究论文，探讨了各种推理时间计算扩展技术，包括“Wait” 令牌、测试时间偏好优化、思维切换惩罚、关联思想链、自回溯机制、潜在推理、计算优化测试时间扩展、测试时反馈学习、推理和规划的推理时间计算基准、内部思维 Transformer 以及代码生成测试时间扩展等。
文章指出，推理时间计算扩展是当前提高 LLM 推理能力的热门研究方向，但同时也存在成本和延迟等方面的权衡。未来的研究将集中在开发更强大的推理模型以及平衡成本和性能。
### 主题
#### 推理模型的定义和主要策略
推理模型是一种专门设计用于解决多步骤问题的 LLM，它会生成中间步骤或结构化的“思维”过程。与仅提供最终答案的简单问答 LLM 不同，推理模型会显式地展示其思维过程或在内部处理它，这有助于它们在复杂的任务（如谜题、编程挑战和数学问题）上表现得更好。
提高推理能力的主要策略有两种：
1. 增加训练计算量
2. 增加推理计算量（也称为推理时间扩展或测试时间扩展）

#### 推理模型开发的四种方法
1. 推理时间计算扩展：这种方法在推理时提高模型的推理能力，无需训练或修改模型权重。核心思想是通过增加计算资源来换取性能提升，例如 Chain-of-Thought 推理和各种采样过程。
2. 纯强化学习：这种方法仅依靠强化学习（RL）来开发或改进推理能力。通常涉及使用来自数学或编程领域的可验证奖励信号来训练模型。
3. 强化学习和监督微调：这种混合方法结合了 RL 和监督微调（SFT），以实现比纯 RL 更稳定和更具泛化性的改进。
4. 监督微调和模型蒸馏：这种方法通过在高质量标记数据集（SFT）上进行指令微调来提高模型的推理能力。如果这个高质量数据集是由更大的 LLM 生成的，那么这种方法也被称为“知识蒸馏”。

#### 推理时间计算扩展的细节
推理时间扩展通过在推理过程中增加计算资源来提高 LLM 的推理能力。
一种方法是提示工程，例如 Chain-of-Thought（CoT）提示，其中“逐步思考”等短语引导模型生成中间推理步骤。
另一种方法涉及投票和搜索策略，例如多数投票或集束搜索，通过选择最佳输出来优化响应。

#### s1: Simple Test-Time Scaling
这篇论文介绍了一种名为“wait”令牌的方法，可以看作是前面提到的“逐步思考”提示修改的更现代版本。“wait” 令牌可以控制输出的长度，让 LLM 生成更长的响应，进行自我验证和纠正。
具体方法：
1. 创建一个包含 1000 个训练示例的精选 SFT 数据集，其中包括推理轨迹。
2. 通过以下方式控制响应的长度：
 a) 添加“Wait”令牌以使 LLM 生成更长的响应、自我验证和自我纠正
 b) 通过添加思维结束标记分隔符（“最终答案：”）来停止生成。他们称这种长度控制为“预算强制”。

#### Test-Time Preference Optimization: On-the-Fly Alignment via Iterative Textual Feedback
测试时间偏好优化（TPO）是一个迭代过程，在推理过程中将 LLM 输出与人类偏好对齐（这不会改变其底层模型权重）。
迭代步骤：
1. 为给定提示生成多个响应。
2. 使用奖励模型对响应进行评分，以选择得分最高和最低的响应作为“选择”和“拒绝”响应。
3. 提示模型比较和评论“选择”和“拒绝”的响应。
4. 通过将评论转换为文本建议来更新原始模型响应，从而优化输出。

#### Thoughts Are All Over the Place: On the Underthinking of o1-Like LLMs
研究人员探索了一种称为“欠思考”的现象，即推理模型经常在推理路径之间切换，而不是完全专注于探索有希望的路径，这降低了解决问题的准确性。
为了解决这个问题，他们引入了一种名为思维切换惩罚（TIP）的方法，该方法修改了思维切换令牌的 logits，以阻止过早的推理路径转换。

#### Trading Inference-Time Compute for Adversarial Robustness
在许多情况下，增加推理时间计算可以提高推理 LLM 的对抗鲁棒性，即降低成功攻击的概率。与对抗训练不同，此方法不需要任何特殊训练，也不需要事先了解特定的攻击类型。
但是，也有一些重要的例外情况。例如，在涉及策略模糊性或漏洞利用的设置中，改进是有限的。此外，新的攻击策略（如“少思考”和“书呆子狙击”）可能会降低推理改进的鲁棒性。

#### CoAT: Chain-of-Associated-Thoughts Framework for Enhancing Large Language Models Reasoning
研究人员将经典的蒙特卡罗树搜索推理时间扩展与“联想记忆”相结合，后者在探索推理路径时充当 LLM 的知识库。使用这种所谓的联想记忆，LLM 可以更轻松地考虑早期的推理路径，并在响应生成期间使用动态变化的信息。

#### Step Back to Leap Forward: Self-Backtracking for Boosting Reasoning of Language Models
本文提出了一种自回溯机制，允许 LLM 通过学习在训练和推理过程中何时何地回溯来提高其推理能力。虽然训练涉及教模型使用 <backtrack> 令牌识别和纠正次优推理路径，但关键贡献是一种基于推理时间树的搜索，它使用这种学习到的回溯能力来探索替代解决方案。
独特之处在于，这种探索不需要依赖外部奖励模型。

#### Scaling up Test-Time Compute with Latent Reasoning: A Recurrent Depth Approach
研究人员提出了一种模型，该模型不是通过生成更多令牌来改进推理，而是通过迭代潜在空间中的循环深度块来扩展推理时间计算。此块的功能类似于 RNN 中的隐藏状态，它允许模型在不需要更长令牌输出的情况下优化其推理。
然而，一个关键的缺点是缺乏明确的推理步骤。

#### Can 1B LLM Surpass 405B LLM? Rethinking Compute-Optimal Test-Time Scaling
许多推理时间扩展技术依赖于采样，这需要过程奖励模型（PRM）来选择最佳解决方案。本文系统地分析了推理时间计算扩展如何与 PRM 和问题难度相互作用。
研究人员开发了一种计算优化扩展策略，该策略适应 PRM、策略模型和任务复杂性的选择。他们的结果表明，通过正确的推理时间扩展方法，1B 参数模型可以胜过缺乏推理时间扩展的 405B Llama 3 模型。

#### Learning to Reason from Feedback at Test-Time
这很难归类为推理时间或训练时间方法，因为它在推理时优化 LLM，更改其权重参数。
因此，本文探索了一种使 LLM 在推理过程中从错误中学习的方法，而无需将失败的尝试存储在提示中（这会变得昂贵）。这种方法不是通过将先前的尝试添加到上下文（顺序修订）或盲目生成新答案（并行采样）来优化答案，而是在推理时更新模型的权重。
为此，作者引入了 OpTune，这是一种小型、可训练的优化器，可根据模型在先前尝试中犯的错误来更新模型的权重。

#### Inference-Time Computations for LLM Reasoning and Planning: A Benchmark and Insights
本文对用于推理和规划任务的各种推理时间计算扩展技术进行了基准测试，重点分析了它们在计算成本和性能之间的权衡。
作者评估了多种技术 - 例如 Chain-of-Thought、Tree-of-Thought 和 Reasoning as Planning - 涵盖了 11 个任务，包括算术、逻辑、常识、算法推理和规划。
主要发现是，虽然扩展推理时间计算可以提高推理能力，但没有一种技术在所有任务中始终优于其他技术。

#### Inner Thinking Transformer: Leveraging Dynamic Depth Scaling to Foster Adaptive Internal Thinking
内部思维 Transformer（ITT）在推理过程中动态分配更多计算。ITT 不是像标准基于 Transformer 的 LLM 那样对所有令牌使用固定深度（= 使用相同数量的层），而是采用自适应令牌路由为困难令牌分配更多计算。这些困难令牌多次通过同一层以进行额外处理，这增加了这些困难令牌的推理计算预算。

#### S\*: Test Time Scaling for Code Generation
推理时间扩展可以通过并行扩展（生成多个答案）、顺序扩展（迭代优化答案）或两者兼而有之来实现。
S\* 是一种专门为代码生成设计的测试时间计算扩展方法，可改进并行扩展（生成多个解决方案）和顺序扩展（迭代调试）。
该方法分两个阶段运行：
1. 生成：模型生成多个代码解决方案，并使用执行结果和问题提示中提供的测试用例迭代优化它们。
2. 选择：一旦多个解决方案通过了公开测试，模型必须选择最佳解决方案（如果可能）。在这里，S\* 引入了自适应输入合成以避免随机选择。

#### Chain of Draft: Thinking Faster by Writing Less
研究人员观察到，虽然推理 LLM 通常会生成详细的逐步解释，但人类通常依赖于仅捕获基本信息的简明草稿。
受此启发，他们提出了 Chain of Draft（CoD），这是一种通过生成最少但信息量大的中间步骤来减少冗长的提示策略。因此，从某种意义上说，这是一种推理时间扩展方法，它通过生成更少的令牌来提高推理时间扩展的效率。

#### Dedicated Feedback and Edit Models Empower Inference-Time Scaling for Open-Ended General-Domain Tasks
许多用于扩展推理时间推理的技术依赖于具有可验证答案的任务（如可以检查的数学和代码），这使得它们难以应用于开放式任务，如写作和一般问题解决。
为了解决有关可验证答案的这一限制，研究人员开发了一个系统，其中一个模型生成初始响应，另一个模型提供反馈（“反馈模型”），第三个模型根据该反馈优化响应（“编辑模型”）。

### 总结
推理时间计算扩展已成为今年提高大型语言模型推理能力的最热门研究课题之一，它允许在不修改模型权重的情况下提升模型性能。未来的研究将集中在两个主要方向：一是开发尽可能强大的模型，在基准测试中名列前茅；二是平衡不同推理任务的成本和性能权衡。
