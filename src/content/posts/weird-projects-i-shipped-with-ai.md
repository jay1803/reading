## TL;DR
AI 编程的早期产物不一定表现为“创业公司海啸”，更可能先表现为一批以前不值得投入完整工程成本的小项目：游戏、学习工具、无限 wiki、离线植物数据库、CLI 扩展。这些项目的共同点不是宏大，而是 LLM 把“想法到上线”的摩擦降到足够低，让原本会停在 GitHub 半成品阶段的东西真的被交付出来。

## 核心洞见
作者用自己过去十二个月的个人项目反驳一个常见质疑：如果 LLM 真能写代码，为什么没有出现大量 AI 生成的新应用、服务和游戏？他的答案是，写代码只是产品交付瓶颈之一，真正阻碍个人项目上线的还包括 UI 打磨、数据库、支付、部署、数据抓取、反爬、维护成本和试错次数。

最有说服力的例子是项目分布很散。Skifreedle 是 SkiFree 的每日挑战版，AI 让作者有余力实现不同游戏对象、最快纪录 ghost、十五到二十种 UI 方案试验；Autodeck 把随机主题自动生成 Anki 卡片做成网站，并接入 Stripe，已有 500 多人试用，付费订阅能覆盖推理和托管成本；Endless Wiki 已生成超过 28 万个页面，还迫使作者处理爬虫耗尽推理预算的问题；VicFlora Offline 则是一个为低网环境缓存植物识别数据库的 PWA，解决的是非常具体的个人/小众需求。

这些案例说明 AI 对个人创造者的价值不只是“更快写代码”，而是把大量边角工程任务从“太麻烦所以放弃”变成“可以顺手补齐”。这会释放很多小而真实的软件，而这些软件未必会被风投、媒体或应用商店看见。

## 具体机制
LLM 在这里主要放大三类能力。第一是实现跨度：作者可以从前端游戏、Stripe 支付、数据库、爬虫、PWA 缓存一路做到部署，不必因为某个陌生环节卡住。第二是试错密度：Skifreedle 的 UI 主题能试十五到二十版，而手写时可能只够试两三版。第三是小众问题的经济性：VicFlora Offline 这种为特定使用场景服务的工具，传统成本下很难排进个人开发优先级。

Endless Wiki 的反爬细节也很关键。作者发现普通链接触发 LLM 生成会被爬虫快速消耗预算，于是改用 JavaScript 模拟“页面尚不存在”的链接。这类运行期问题不是单纯代码生成能解决的，但 AI 降低了整体工程成本，让作者还有精力继续修补产品边界。

## 隐藏限制
这篇文章是强个人证据，不是宏观证明。它能证明“一个高能力开发者借助 LLM 可以多交付很多奇怪小项目”，不能直接证明非开发者也能稳定交付复杂产品，或 AI 会自动制造大量成功公司。

另一个限制是，作者列出的项目多属于个人可控范围：规模小、风险低、用户预期轻、维护负担有限。企业级软件、监管行业、多人协作、长期安全责任仍然会被需求判断、产品运营、质量控制和信任成本限制。

## 最后一层
这篇文章真正指出的变化，是软件创造的激活能下降了：AI 先改变的未必是“谁能创办大公司”，而是“多少原本不会被做出来的小工具开始存在”。
