## 简单 ≠ 容易，"C 语言简单"是对执行成本的误判

C 语言标准短、规则少，这是真的。但"简单"（simple）描述的是可以用少量规则解释的东西，"容易"（easy）描述的是执行成本低的东西。两者之间没有因果关系。

指针是最典型的反例：理论上一句话讲完，实践中每次使用都要同时回答六个正确性问题——谁拥有这块内存？需要释放吗？谁负责释放？内存区域多大？指针当前是否有效？有没有被提前释放？答错任何一个，结果是崩溃、内存泄漏或安全漏洞。

## Rust 的"复杂"是换来执行可靠性的代价

Rust 的引用语义、生命周期、借用检查器看起来更复杂，但在 safe Rust 范围内，编译器强制保证正确性，开发者不需要在每次解引用时手动回答那六个问题。表面复杂性换来了执行可靠性——写对的难度反而比 C 更低。

用"C 很简单"来贬低 Rust 复杂度，是把描述语言规模的尺子拿去量程序员的执行成本，两把尺子不通约。Unsafe Rust 另当别论——那确实像拿链锯在杂耍。
