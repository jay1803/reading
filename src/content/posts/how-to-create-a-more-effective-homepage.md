## TL;DR
大多数初创公司主页失效，根源不是设计差或文案弱，而是团队还没就"我们是什么、为谁做、为什么更好"达成共识就开始写 copy。作者的核心主张：先用一页纸锁定 messaging building blocks 并拿到跨职能 sign-off，再把这些 blocks 翻译成各页面 copy——把反复争论变成翻译任务。

## 关键洞察
- **Messaging ≠ copy** 是全文的承重区分。Messaging 是意图和准则，copy 是针对具体渠道的措辞。大多数团队把它们混在一起，导致每次改主页都重新触发"我们到底是什么公司"的争论。先把 messaging blocks 锁死（不超过一页、提前跨职能 sign-off），后面所有 copy 都变成翻译。
- 大多数初创公司的 messaging guide 长达数页，细到无法使用。作者明确说：不要做那种。只保留：顶层定位（问题 / 产品 / 目标用户 / 差异化）+ 利益点与对应证明材料 + 使用场景 + 产品运作方式（3步）。
- **主页公式本身是保守的**：hero → social proof → 2-3 benefits → 可选（use case / persona / how it works）→ CTA bar。作者建议早期公司照着模板做，通过 copy / 颜色 / 字体 / 视觉来差异化，而不是靠非常规 UX。这与"让主页令人难忘"的常见冲动相反。
- **Social proof headline 常被浪费**："Companies love us" 是最典型的无效标题。改成受众明确的版本（"Top GTM teams love Pocus" / "Join thousands of developers using CodeSee"）同时完成可信度建立和用户自我筛选两件事。
- Benefits 区块里用截图而非插图，因为截图本身就是证明材料——它证明产品真实存在且具体运作。
- 文章本身是残缺的：Step 4（实际写 copy 的方法）在付费墙后，全文止步于"把 messaging blocks 映射到各区块"，没有给出怎么把 blocks 变成有说服力的句子。

## 一句话总结
主页改不好，往往因为在动笔写 copy 之前整个团队根本没对"我们是谁"达成过共识——messaging guide 的价值是把这场争论前置并一次性关闭，而不是让它在每次改稿时重复上演。
