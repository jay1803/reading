SondeHub 从一个玩笑式注册的域名，演变成了被军事行动、航空安全调查和政府机构依赖的公共基础设施，而维护它的业余爱好者也随之承担了可能影响生命安全的服务责任。这个转变源于一项持续扩展的能力：公开接收气象气球的数据，将其整理成完整轨迹，再结合风场模型推算飞行路径与发射地点。同一套帮助爱好者寻找 radiosonde 的工具，也能暴露军事部署、支持远程打击，并为事故调查提供线索。

项目最初连独立服务都算不上。作者约在 2017 年经 Mark VK5QI 接触气象气球追踪，当时澳大利亚的小规模社群借用面向业余高空气球的 Habhub，主要追踪 Melbourne 和 Adelaide 的 radiosonde。随着气象气球数量增加，Habhub 默认将它们从地图中过滤掉；2018 年 5 月 12 日注册的 sondehub.org，只负责跳转到附带专用过滤参数的 Habhub 页面。同年 7 月，团队开始代理 radiosonde 数据接收，并将更多、未经自身限流的数据存入独立的 OpenSearch 集群。作者起初只是借此试验 Amazon Web Services（AWS）和分析平台，但到 2019 年，Habhub 与 aprs.fi 已难以承受负载，建立独立后端成了实际需要。

SondeHub 很快获得了官方系统未能提供的数据价值：它能够一直追踪 radiosonde 到地面。2019 年，团队收到与保险索赔有关的查询，一枚 radiosonde 据称砸到马匹，导致马匹受惊撞穿围栏。同年，他们发现气球发射量在 GPS rollover 时明显下降，最初怀疑自己的软件出了问题，后来确认是 Vaisala 设备故障阻止了发射，SondeHub 自身反而正常处理了日期翻转。2020 至 2021 年，团队建立兼容 Habhub 前端的 API，开始接收完整数据，并通过 S3 提供开放访问，同时运行自己的轨迹预测器。此后又增加 websockets、MQTT 实时数据流，并在 ARDC 资助下开发面向业余高空气球的版本；Habhub 最终因缺乏维护关闭，团队赶忙迁移能够保留的功能与资源。

真正将项目带入军事领域的是 Mark 开发的 **reverse predictions**：利用已升空 radiosonde 的观测数据和风场模型，反向推算大致发射位置。这项功能能识别记录不全的发射站，并将气球归属到具体站点；它也让团队意外标出了炮兵阵地，因为风场数据同样用于计算火炮射程。2021 年，一封邮件要求他们不要在地图上明确标注某个敏感军事设施。团队保留了反向预测功能，但会在收到真实有效的请求后删除相关发射站标记；同一方法还识别出海上的多艘军用舰艇。公开的气象观测，由此成为推断军事位置的入口。

2023 年的 "China spy balloon" 事件进一步放大了 SondeHub 的曝光度。2 月 11 日，美国据称使用 AIM-9X Sidewinder 击落了一枚业余无线电气球，文章将此概括为价值 439,000 美元的导弹对付派对气球。Washington Post 链接到 SondeHub 后，作者一早收到高流量告警，网站仍大体承受住了访问压力。此后，来自 .mil、.gov 地址以及航空业、空中交通管制机构的支持请求明显增多，原本面向爱好者的服务开始被纳入专业机构的工作流程。

更直接的战争关联出现在 2024 年 12 月。预测 API 遭遇大量请求，告警此后几乎每周出现。启用日志后，团队发现请求集中来自一个 IP；他们先确认一家私人公司确实在调用后端，却发现那家公司并非异常流量的来源。将预测路径绘制到地图上后，团队意识到这些调用涉及俄乌战争中的行动。通过联系人获得的消息提到 mHAB，以及可能利用 SondeHub 帮助固定翼飞行器沿风场抵达目标区域的其他团队。联系人随后在乌克兰军事群组中寻找使用 Python 脚本和开源风场预测引擎的远程打击团队，告知其查询方式正在造成服务问题，若不调整便可能被封禁。作者公布相关图像时主动降低了坐标精度，仅展示较早、且不完整的数据，并延迟发表文章，直到气球作战已更广为人知。

此时，通常的 API 滥用处理方式产生了生命安全风险。团队怀疑对方没有正确使用接口，却无法直接联系操作者，于是迅速制作 Docker Compose 配置，让使用者能够自行部署预测器，摆脱对 SondeHub 公共服务的依赖。由于来源 IP 属于 AWS，他们同时联系 AWS，明确要求不得传播 HTTP 请求数据，也不得封禁、限流或终止来源账户：中断访问可能导致人员死亡，请求数据则可能暴露发射地点。最终，操作者收到 AWS 通知，得知自己的 Lambda function 被标记为疑似抓取 api.v2.sondehub.org，主动联系团队，双方通过邮件沟通了本地部署方法。维护者要解决的已经包括服务负载、军事位置保密和使用者安全之间的冲突。

面对军事机构的主动合作请求，团队则尝试划出另一条边界。2025 年，美国 "Office of the Secretary of War (Intelligence and Security)" 索取数据。SondeHub 通常会为具有共同社群利益的需求免费查找、处理和发布数据，但这次看不到相应收益，决定收费。作者不愿协助军方，尤其不愿协助美国军方；考虑到原始数据已经公开、其他人也能够完成处理，他最终接受了至少用收入支付基础设施费用的理由。然而，发票发出后既未获付款，也没有后续消息，团队始终不知道对方索取数据的具体用途。

航空安全领域的往来同样暴露了机构对气球活动的认知缺口。NTSB 曾查询 Utah 在 2025 年 10 月 16 日 12:00 至 13:00 UTC 之间的气球信息，涉及一宗经 ACARS 报告的疑似飞机与气球碰撞。SondeHub 追踪的气球没有吻合，但团队提供了附近存在 Windborne 气球的线索；Windborne 后来确认它很可能涉及该碰撞，并修改系统以降低后续风险。另一次，塔台运营人员急切要求联系气球的控制方，担心飞机接近这些目标。团队只能解释，相关气象气球按计划发射、升空后不受操控，作者认为它们可能适用 FAA Part 101.D，而且 SondeHub 并不掌握发射方的联系人或登记信息。掌握轨迹数据，让这个民间平台不断被当作气球活动的协调入口，却没有赋予它相应的控制权。

平台还收到过 Iowa 的 Anamosa 房主求助：有人到其物业回收 radiosonde，途中撞到建筑物后未留字条便离开。它也能观测 GPS jamming 与 GPS spoofing；作者对某些异常轨迹模式是否用于识别目标或诱使飞行器以特定方式坠毁提出猜测，但没有给出确定解释。使用者横跨气象部门、海军航空项目、研究机构、NY Times 视觉调查团队，以及署名包含 "Certified Tea Specialist" 和 "Cheese Fortune Teller" 的自由撰稿人 Jennifer Billock。多数机构与厂商愿意合作，因为回收 radiosonde 能减少环境遗留物并促进公民科学；Meteolabor AG 却以战略原因拒绝提供数据或样机，其附带的个人回复还夹杂 chemtrails 和 "climate hoax" 阴谋论。

SondeHub 的经历揭示了开放基础设施的一种责任错位：功能由志愿者为公民科学逐步搭建，关键用途却由外部机构和战争参与者不断扩展。一旦公开数据能够推断军事位置、预测器能够支撑实际行动，删除标记、保留日志、执行限流或维持访问，都可能产生远超服务器运维的后果，而这些决定仍落在最初只想追踪气球的维护者身上。
