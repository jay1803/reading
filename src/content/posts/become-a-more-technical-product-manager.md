### 概述
这篇文章主要介绍了产品经理需要了解的技术基础知识，包括 API、代码部署、系统架构、分支、数据库、单元测试等多方面内容。文章旨在帮助产品经理更好地与技术团队协作，提高产品质量和开发效率。作者通过讲解基本概念、举例说明、提供实践操作等方式，帮助读者理解并掌握这些技术知识 <citation>7</citation,。
### 主题
- 💻 软件产品的三个基本组成部分：客户端、服务器和数据库。
客户端是最终用户使用的网站或应用程序。服务器处理来自客户端的请求。数据库是数据的永久存储。

- 🚪 API（应用程序编程接口）：API 是服务器的前门，允许其他应用程序访问数据或触发事件。
API 分为公共 API 和私有 API。公共 API 供公司外部的开发人员使用，私有 API 仅限应用程序或产品内部使用。OpenAI 提供了多种 API，包括图像生成、音频转录和聊天响应,。

- 🔄 API 请求类型：REST API 是最流行的 API 设计模式，它支持多种请求类型，最常见的是 GET 和 POST。
GET 请求用于获取数据。POST 请求用于提交新数据到服务器。例如，可以使用 POST 请求在 OpenAI 的 /images/generations 终端节点上创建新映像。

- 📝 API 请求的组成部分：包括 Base URL、Endpoint 和 Query parameter。
Base URL 是所有 API 端点的“home”。Endpoint 是要访问的特定资源。Query parameter 是通过请求传入的其他数据。

- ⚙️ 工程师使用的代码工具：Git,。
Git 是一个版本控制系统，用于跟踪对代码所做的更改。工程师使用 Git 和 GitHub 等产品将更改从本地计算机移动到在线存储，以便其他人查看和编辑。工程师创建分支来进行更改，完成后提交拉取请求，由其他工程师审查并合并到主分支。

- 🌿 分支（Branches）：分支是代码的副本，工程师使用这些 API 来单独进行更改。
工程师在分支上进行更改，完成后提交拉取请求（Pull Request）。其他工程师会审查拉取请求，提出改进建议，批准后将独立分支合并回主分支。

- 🧪 测试类型：包括单元测试、集成测试、端到端测试和用户验收测试。
单元测试是与新功能一起编写的代码，用于测试各种功能。集成测试是软件的不同组件之间的测试,。端到端测试是完整的工作流程演练，与所有相关系统交互。用户验收测试要求用户从头到尾使用功能的当前版本。

- 🚀 部署实践：分为计划部署和持续部署。
计划部署按周期进行，如每周、每月或每季度。持续部署（CD）允许开发人员在代码合并到分支时自动将其部署到一个或多个环境。持续部署通常与持续集成（CI）配对，CI 指每次将新代码添加到分支时自动运行测试。

- 🛠️ 环境：通常包括 Dev、Staging 和 Production。
Dev 环境专供开发人员使用。Staging 环境是 Production 的紧密副本，用于测试和内部使用。Production 环境是客户每天使用的主要环境。
