## 嘉宾背景

Alessio Fanelli 是 Kernel Labs 创始人、Late in Space 播客联合主持人，也经营位于 San Carlos 的卡牌店 Merlion Games。他成长于罗马，家庭从事向餐厅配送鱼类的生意；软件开发、卡牌交易与小型实体企业的交叉经验，使他关注的不只是智能体能否写代码，而是 AI 能否降低现实业务中长期受人力带宽限制的信息处理成本。

## TL;DR

Fanelli 的核心判断是：自主智能体真正稀缺的不是生成能力，而是一个能持续保存状态、暴露异常、接收纠偏并把人留在关键决策节点上的管理系统。Symphony、Linear、VPS、技能文件和视觉工具的共同作用，是把人与模型的关系从逐轮对话改造成任务管理；同一原则也适用于卡牌采购、库存盘点、个人财务和邮件监控——机器维持连续上下文，人只在判断、返工和承担责任时介入。

## 1. 当模型能够长时间独立工作后，人的角色为何必须从"提示智能体"转向"管理智能体"？

Fanelli 接触自主编码并不晚：三年半前，他的播客搭档就做过名为 Small Engineer 的早期自主编码系统。但当时它更像一个有趣的演示，模型难以可靠完成长时间、多轮任务。后来模型能力提高，瓶颈随之改变：问题不再只是如何写出一个更好的 prompt，而是如何同时启动、观察和纠正多个持续运行的任务。

最初的 Kanban 方案可以把任务放进队列并触发执行，却很难支撑两三轮以上的干预。本地运行也意味着人必须回到特定电脑前查看状态；主持人 Claire Voe 描述自己仍要不时下楼"叫醒"四台 Mac Mini，正好体现了这种局限。Fanelli 因此把运行环境迁到云端 VPS，并让同一批智能体可以从 Linear、短信、手机和 shell 等不同入口接受管理。Zoo 为他提供预装编码智能体的 VPS，Symphony 则负责把任务状态转化为编码运行。

在这套模式里，人不再跟随模型的每一步推理，也不逐条查看 trace，而是定义任务、审查结果、指出偏差并决定是否返工或合并。录制过程中，他直接在 Linear 创建了一个界面清理任务，智能体随即开始工作；任务完成后会进入 human review，他可以从手机查看 Vercel preview、评论代码或前端，再将任务退回 rework。所谓"自主"因此不是移除人，而是把人的介入从持续提示改成阶段性的分配、验收和纠偏。

Fanelli 对产出增幅也保持克制：理论上并行智能体能完成更多工作，但人不可能每天审查一百件新东西。管理层本身仍有吸收上限，因此更好的 ergonomics 和远程控制并不等于无限产能；它首先改变的是人参与工作的方式。

## 2. 自主编码的关键是否不是更复杂的编排，而是用状态和工件塑造上下文？

Symphony 本身没有赋予 Codex 新的编码能力。Fanelli 将其称为一种"塑造上下文"的方法：以 Linear 为 source of truth，把原始规格、执行计划、验收条件、验证步骤、PR 评论、返工清单和最终状态保存在同一任务生命周期中。它解决的不是模型"会不会写"，而是团队能否知道模型拿到了什么信息、在哪里出错，以及下一步应当发生什么。

具体流程由状态变化推动。Fanelli 先在 Linear issue 中写一份通常相当简短的规格，再把任务移入 to-do；Symphony 检测到状态后启动 Codex，并创建 workpad，由智能体补充实现计划、acceptance criteria 和 validations。完成后任务进入 human review，人可以在 GitHub PR 上逐项评论；任务被移到 rework 后，智能体会把评论整理成返工 checklist，说明各项问题及处理方式，修改后重新提交，合并后再进入 done。

这种结构的价值在失败时尤其明显。因为初始规格、第一次 workpad 和 rework workpad 都留在一个任务里，Fanelli 可以回溯错误究竟源于规格、计划、执行还是验收，并据此修改 AGENTS.md 或 workflow.md。相比之下，直接使用 Codex 的零散会话很难搜索，也难以重新拼出完整因果链。

主持人因此把 Linear 概括为整个代码库工作的状态机：任务如何拆解、实现、接收评论和进入下一阶段，都由预先规定的生命周期承接。Fanelli 还用 PyQueue 探索了更激进的版本——把 repository 和 Pi agent 放进 VPS，让互联网上的其他人直接提交 coding task。他把这类未来协作描述为"request for prompt"：关键交换物不再只是代码，而是足以让智能体继续工作的上下文。

## 3. 决定自主运行能走多远的，为什么往往是工具与可观测性，而不是编排框架本身？

Fanelli 使用的是 Symphony 的 Elixir 参考实现，主要改动集中在 workflow.md 和可视化界面。原版更接近一个监视 Linear 状态并启动任务的循环，没有完整 UI，也默认不提供逐任务 token ledger。对他而言，搭起这个状态循环并不困难；真正困难的是让智能体遇到视觉、环境或部署问题后仍能继续，而不是过早退回 human review。

Kernel Labs 为此开发了 Glimpse：一个面向编码智能体的 Playwright 扩展，可以截屏、录制视频，并对不同截图做 visual diff。此类工具让智能体能够观察实际运行结果并自行验证修改。Fanelli 的判断是，决定一次 run 能持续多久的，通常不是外层编排有多复杂，而是智能体是否拥有足够的浏览、视觉、验证和诊断工具。

可观测性还包括每项任务消耗的 token 与时间。Fanelli 展示的多数任务约消耗 1500 万、3000 万或 6000 万 token，而一次把本地项目改造成可部署于 Vercel 的任务达到约 2.21 亿 token；后者涉及重写存储和请求处理，因此高成本并非毫无缘由。这里的重要信息不是某个数字天然"合理"，而是团队应逐渐形成对不同任务成本量级的预期。如果实际消耗远离预期，往往意味着智能体反复碰壁，规格、检查方式或工具层可能存在缺口。

因此，token ledger 不只是费用记录，也是一种间接故障信号。异常长的执行可以反过来帮助人定位缺少的工具和验证环节，再把改进写回控制环境。Fanelli 并未声称 token 数能精确衡量任务难度；他的说法是，两者通常具有方向性的关系。

## 4. 为什么自然语言工作流越有力量，就越需要克制、审计和定期清理？

Claire Voe 指出，许多团队一开始就设计庞大的智能体编排平台和复杂流程图，但 Symphony 的核心控制面其实主要是一份自然语言 spec：它规定工作流的 primitives、需要保存的内容，以及任务如何在软件生命周期中流转。新一代模型能够相当严格地执行这种 Markdown 规格，因此复杂流程未必需要同等复杂的传统编排代码。

但这种力量也放大了指令债务。Fanelli 曾在编码智能体尚不具备原生 worktree 支持时，自建 worktree manager，并在每个 AGENTS.md 中写下"必须使用它"。工具后来升级，这条旧指令仍留在部分项目中，于是智能体每次启动任务都会重新安装一个已经不需要的组件。问题不是模型没有服从，而是它过于忠实地执行了过时规则。

模型还倾向于新增例外，而不是删除旧规定。若被告知"不必总是使用 Workflow Manager"，它可能保留原规则，再追加一句"不需要每次使用"，使文件同时包含互相拉扯的指令。类似地，智能体会把"某个 Symphony 实例已经注册"之类的动态事实写进 skill.md；Fanelli 认为，这种信息应当在运行时搜索，而不该固化进长期规则。

他的 skill.md 因而刻意保持有限：说明 Symphony 放在哪里、各实例如何命名、repository、workspace、log 和 state 如何组织，列出必要前置条件及精确命令，但不试图规定模型完成任务的每个动作。如果必要条件缺失就询问，否则直接工作。控制文件的职责是给出稳定边界，而不是积累所有曾经有用的细节。

这也使技能维护成为持续工作。Fanelli 和 Voe 主张定期重新 diff、清理并重写 Markdown 文件，删除重复、矛盾和失效内容。Codex 的 create skill 功能虽然降低了创建门槛，却也可能诱使用户生成描述含糊、范围过大的技能；模型又会高度服从这些文件，最终使自动化变差。自然语言规则不是无成本的笔记，而是会在每次运行中重复生效的程序。

## 5. AI 如何把现实世界中的异构信息转化为即时商业决策？

Fanelli 为 Merlion Games 开发 Power Buyer，是为了更系统地寻找和管理值得采购的 Pokémon 卡牌。高价卡牌的信息并不集中在一个干净数据库中：PSA 等评级机构为卡牌提供证书编号，但要使用相关 API，往往得先找到一个具体证书作为入口；市场报价分散在 eBay、TCGPlayer 等页面中，关键编号有时只存在于商品图片里，不同评级公司之间还需要按业务规则进行比较。

他让 Codex 浏览网页，为价格超过 1000 美元的卡牌寻找 PSA certificate number：智能体打开页面、下载图片并从图中提取编号，再把结果补回 Power Buyer。随后，另一个技能规定如何筛选值得寻找的卡牌、如何按每批五张执行查询以降低被 eBay 限制的风险，以及如何处理 PSA、BGS、CGC 等不同评级体系。智能体从 Power Buyer API 取得目标，通过内置浏览器搜索市场报价，并判断某张价值数万甚至五万美元的卡牌是否可能被低估。

其中不同评级等级"等价"的对应关系是 Fanelli 放入技能中的交易规则，而非访谈提供数据验证的客观换算。**证据薄弱处**：这些对应关系及"低估"判断的可靠性没有展示历史成交数据、误差范围或评估结果，访谈只演示了工作流如何执行。

商业价值来自采购决策而非浏览器演示。卡牌是库存型生意，可投入并成功周转的资本越多，潜在收益越大；自动搜索高价值标的可以扩大人工采购团队能覆盖的市场。Fanelli 还计划把同一能力带到 trade show：卖家现场递交卡牌时，工作人员目前要逐张搜索 eBay 或 TCGPlayer 并即时估价，查询速度直接限制成交机会。对这类场景，AI response time 不只是模型 benchmark，而是现实工作人员能否在有限时间内完成更多交易。

演示也暴露了系统仍会犯低级错误：某个带美元符号的链接被 Codex 误解析为 skill 引用，导致它寻找技能而不是访问 URL。Fanelli 没有把自主运行描述成无故障系统；这个例子反而说明，即使业务逻辑成立，细小的接口约定也足以使执行偏航，需要工具、验证和人工审查共同兜底。

## 6. AI 的经济杠杆为何可能最先释放在小企业，而不是无限扩张的软件工厂？

Fanelli 对"软件工厂"无限扩张持保留态度。即使 Salesforce 之类的大型公司可以更快生成代码，也不可能每周向市场发布五千项功能；组织协调、产品理解和用户吸收能力都会形成上限。模型在单一任务上继续增加产出的边际价值，因此未必像代码生成能力本身看起来那么大。

小企业面对的是另一类约束：并非缺少一个大型软件平台，而是两三个人每天只能识别、搜索、盘点和记住有限的信息。过去的软件擅长处理标准化数据，却很难经济地覆盖图片、标签、现场物品和不断变化的非结构化页面。Fanelli 认为，多模态 LLM 的可塑性使这些长期被视为"不值得软件化"的工作第一次可能被自动处理。

Pokémon 卡牌只是一个例子。Voe 拍下家中各处书堆，让 Gemini 识别约六百本书，按类别和物理位置编目，并找出夫妻双方重复购买的书。Fanelli 则提到父亲在罗马经营的鱼类配送业务：员工每天拿纸笔进入冷库记录鲜鱼和冻货，之后才发现少了几条金枪鱼或一箱虾。他设想，用 Meta glasses 等设备结合 AI 即可自动化一部分盘点。**证据薄弱处**：访谈没有实际部署该鱼类库存方案，也没有讨论识别误差、冷库环境、系统集成或食品供应链对准确性的要求，因此"可以轻易自动化"是愿景性判断，而非已验证结果。

这些案例的共同点是现实信息与人类带宽不匹配：Goodwill 中可能出现被低估的 Prada 包，卡展上可能出现价格不透明的卡牌，仓库里可能存在人工记录遗漏。传统规模经济通常让大组织优先从技术中获益；Fanelli 认为，AI 反而可能让小规模经营者以较低成本获得过去需要更多员工才能维持的识别、研究和运营能力。

他把这视为 AI 最积极的结果之一：不是让现有巨头无上限地产出软件，而是让更多两三个人经营的专业化企业成为可能。他在日本旅行时观察到大量由少数人经营、经营者也乐于维持其规模的小店，希望美国出现更多类似企业。Voe 则把自己概括为"一个到一个半人，加上一群 agents"的小生意，这种组合正是他们设想的组织形态。

## 7. AI 的另一种价值，是否不是替人做决定，而是成为防止遗漏和失误的"认知安全网"？

在个人财务场景中，Fanelli 看重的不是 AI 代替人下注，而是持续记住账户状态。卖房之后，他用 ChatGPT 的账户 connectors 帮助梳理资金安排。过去，他每次查看投资都要重新想起资金放在哪里、当前计划是什么、是否应调整配置，以及某个投资机会是否真实。反复检查并没有持续创造新价值，更多是在缓解"我会不会把事情搞砸"的焦虑。

他希望 AI 充当 safety net：持续保留上下文、帮助人保持原定方向，在出现值得关注的问题时再要求介入。这是一种 context offloading，而非责任转移。访谈没有展示 AI 给出的具体投资建议，也没有证明其财务判断准确；**证据薄弱处**：把连接账户的 AI 当作财务安全网涉及数据完整性、建议可靠性和风险责任，节目只陈述了 Fanelli 的个人体验。

邮件监控体现了同一机制。他曾让 Wafer 每五分钟读取 Gmail，只判断是否出现真正需要查看或回复的邮件。此前，他会因为担心遗漏而不断检查收件箱；有了持续监控后，他相信重要邮件出现时自己会收到提醒，因此不必保持长期警觉。Wafer 后来关闭，但这个例子说明，自动化的收益有时不是替人完成一项显性的劳动，而是消除人为了防止遗漏而不断重建上下文的心理负担。

这也与前面的编码系统形成对应：无论对象是 PR、卡牌库存、个人资产还是收件箱，机器负责维持连续状态并监控变化，人则在异常、判断和责任节点介入。AI 的价值不只以"多完成多少任务"衡量，也包括让人少惦记多少事情。
