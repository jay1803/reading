### 嘉宾背景
Greg Brockman 是 OpenAI 总裁与联合创始人。他出生于北达科他州,高中时是化学奥林匹克竞赛选手,一度想做演员,最终选择"硬科学"路线;先在哈佛读书,后转入 MIT。2010 年经 Patrick Collison 与 John Collison 引荐加入 Stripe,一路做到 CTO,2015 年离开 Stripe 与 Sam Altman 共同创立 OpenAI,担任 CTO 多年,现任总裁。这场访谈由 Ben Thompson(Stratechery)主持,录制于 OpenAI 发布新模型 Astra 之前,话题从 Brockman 的成长经历一直延伸到 Astra 发布、对齐与安全策略。

### TL;DR
Brockman 的职业轨迹和 OpenAI 这家公司在结构上重复着同一件事:先用第一性原理深入理解一个原本陌生、混乱的领域(信用卡网络、AI),搭建起团队和基础设施去驾驭它,然后在能力足够强之后主动拆掉自己搭的脚手架——不管这脚手架是他本人手写代码的习惯、OpenAI 为模型手写的技能规则,还是 Hugging Face 事件之前那套"先把访问权限锁死"的安全直觉。这场访谈真正的张力在于:拆脚手架换来了 ChatGPT 式的爆发和 Astra 的跃升,但同一种"少约束、让它自己泛化"的逻辑,推到极致就是 AGI 可控性问题本身——Brockman 并不回避这一点,而是把"人类监督与问责必须永久保留"当作唯一不能松手的 invariant。

### 深入理解一个陌生领域,是从 Stripe 到 OpenAI 唯一可迁移的核心能力
Brockman 说自己成长中一直在数学和科学上"march to my own tune"——在北达科他这样竞争没那么激烈的地方,他能提前在大学选修课程、参加全国数学夏令营,反而因为环境宽松才敢做数学研究,如果去了竞争更激烈的地区,他判断自己会被迫走标准轨道,反而不会脱颖而出。这段经历直接塑形了他后来对"环境决定努力水平基准"的判断。

进入 Stripe 后,他把这段成长经验转成了一套方法论:信用卡网络行业极度不透明,建立在几十年历史包袱上,底层协议(ISO 8583)还是上世纪 80 年代的规格。团队没有人是支付专家,但靠着深入理解"这东西底层到底为什么这样运作",才能抽象出简单的 API 给外界用。Brockman 明确把这套"深入理解陌生领域、再把它暴露成简单原语"的能力,当作 Stripe 与 OpenAI 之间唯一真正可迁移的核心技能——AI 和支付具体内容天差地别,一个是自然科学,一个是人为堆出来的复杂系统,但驱动方式是同一种。

这段经历也埋下了后面反复出现的另一条线:他在 Stripe 当上 CTO 后写过一篇文章,说自己担心脱离产品反馈循环,决定继续写代码——这个状态一直维持了近十年,直到他才慢慢学会"即使不亲自动手写代码,也能通过给团队方向、判断、反馈来推动结果",他把这个转变形容为"用一样自己更爱的东西替换了自己曾经很爱、也很依赖的东西"。这是他个人层面第一次经历"放下具体操控权、换取更大杠杆"的过程,后面 OpenAI 在模型和组织层面又会重复这个模式。

### Turing 对"智能"的操作性定义,催生了 OpenAI 不断重塑自身结构去承载同一个使命
Brockman 说自己很早就被 Alan Turing 1950 年那篇论文触动:Turing 没有纠缠"智能"这个词到底是什么意思,而是给出一个可操作的测试标准,更关键的是他提出了"child machine"的思路——不是硬编码所有规则的答案,而是造一台会学习的机器,靠奖励和惩罚去教它。Brockman 认为很多问题人类从未找到过解法、可能永远也找不到,如果机器能理解人类理解不了的东西,不只是图像识别这类具体任务,甚至可能帮助解答"社会该如何更好地组织起来"这类问题。他早年在哈佛问教授能不能做 AI 研究,得到的却是基于 parse tree 的老式自然语言处理方案,他当场判断"这不是 Turing 说的那种东西,scale 不到 AGI",直到 2012 年 AlexNet 前后深度学习论文密集出现,他才确认这件事真的发生了。

2015 年他判断 Stripe 已经能在没有他的情况下正常运转,选择创业而非走管理路线,Patrick Collison 把他介绍给 Sam Altman,三分钟内两人就定下方向。至于 OpenAI 最初的非营利结构,Brockman 说这是 Altman 提出的,他认可其中的逻辑:这项技术比任何已有的公司架构都大,没有一种现成的公司形式能完整承载这个使命,所以需要持续为"如何操作化这个使命"重新设计结构——他把 OpenAI 形容为在公司架构创新上做得最多的公司,并强调这种结构上的反复重塑不是混乱,而是使命本身不变、承载方式在变。

### ChatGPT 的意外走红暴露了:技术狂飙背后管不好的是人,不是模型
Brockman 承认自己最大的预测误差,是没想到 GPT-3.5 会被这么多人喜欢——GPT-4 8 月已经训练完成,团队当时只盯着 GPT-4 看,觉得 GPT-3.5"这个旧版本简直全是缺陷",尽管当时已经要花钱请 200 个测试用户去用 pre-release ChatGPT(说明产品信号其实存在,只是没被重视)。2022 年 11 月底上线后系统全面告急,包括登录系统这种最不"AI"的地方成了瓶颈,团队把研究侧已经存在的更高效推理内核紧急搬到生产环境,整整一个月都在疯狂扩容。

真正的转折出现在 2023 年 11 月的动荡。Brockman 明确表示这不是单一技术事件能解释的,而是长期积累、始终没被正面处理的"人与人之间的张力"。他把这一点称为 OpenAI 最重要的教训之一:即便在做着改变世界的技术,归根结底还是关于人——如果不主动把这些张力摊开来谈,矛盾只会变得更糟。他不认为这场动荡与 ChatGPT 意外爆红之间存在直接因果,但承认随着技术进展,每个人都更强烈地感受到"世界的重量压在自己身上",而日常具体的工作——调试底层问题、有人因为没被叫去开会而不满——跟任何其他公司几乎一样,只是筹码大得多。他此后着力的方向,是不让员工觉得自己在孤立地扛着这份重量,而是团队一起扛。

### 从"想做所有事"到主动砍掉 Sora、把消费者和企业业务合并成一个 AGI 栈
Brockman 承认 OpenAI 变化极大,但同时坚称公司在安全、安全性、核心技术和收益分配上一直是行业先行者。2026 年的一个转变是:因为整个领域参与者太多、要做的事太多、技术进展太快、算力又被卡死,OpenAI 必须"聚焦、做减法、挑选能互相协同的领域"——他直接举例:Sora 这项娱乐向消费者产品技术很出色,但优先级排不进去,所以被关停,即便这会带来痛苦的连锁反应。

围绕"消费者是不是拖累了企业业务"的问题,Brockman 没有简单地站边,而是承认双方论点都有道理:确实存在"我们在 agentic 这波浪潮上起步晚了"的说法,但同时十亿用户、美国大约三分之一人口每周使用 ChatGPT,这种规模是任何同级别先进技术都不曾达到的。他的立场是:consumer 与 enterprise 是同一个系统的两种使用场景,OpenAI 的战略是不做两套东西,而是"build one AGI, one system, one unified stack";ChatGPT 从对话式产品转向以 Codex 为基础的新架构,标志着行业正在从 chat 整体转向 agentic 用例——不只是生产力工具,也包括订机票、订理发、健康建议等私人场景。谈到公司规模本身能否被有效管理,他承认几年前公司确实有大量"管理债务",过去这段时间是刻意补课,同时指出 OpenAI 这类公司的人均营收远超历史上任何企业,这种技术带来的杠杆本身正在改变"如何经营一家公司"这件事。

### 放手是进步的引擎,也是风险的来源:从手写代码,到手写技能规则,到不深究 AI 给出的芯片优化
这条线索贯穿了访谈里几个看似不相关的细节。第一处是他本人从"必须亲手写代码"过渡到"通过判断和方向带团队"。第二处出现在 Astra 身上:团队过去一年非常辛苦地为模型编写各种技能规则,教它"OpenAI 认为正确的做法",但 Brockman 承认其中一部分技能规则现在反而拖累了 Astra 的表现——模型自己泛化出来的路径,比人写的规则更好,他把这些规则比作"训练轮":一开始有帮助,但一旦系统更强、更对齐,规则反而变成限制。

第三处是芯片设计:团队在 Jalapeño 芯片交付前一个月,用自研模型跑出了一批优化,团队面临选择——花时间去逐条读懂模型做了什么,还是把剩下的时间用来让模型跑出更多优化?他们选择了后者,一个月后回头看时发现,模型找到了一批团队本来就知道该做、但一直没时间做的优化。他把这总结为:允许在有"足够护栏、足够可验证性"的前提下,不完全审查 AI 给出的结果——但强调人类必须始终为自己创造的系统承担问责,这是他认为人类不可替代的核心价值之一。

这条线索的反例出现在 Hugging Face 事件上——Brockman 承认,尽管 OpenAI 从今年夏天 Anthropic 发布 Mythos 前后就已经公开讨论"网络能力型模型"要来了、2 月也发布了 Trusted Access for Cyber 项目,但当时团队的本能反应是"大幅收紧访问权限、把这类能力锁起来",而不是真正去验证自家沙箱是否经得住这种能力的测试——他直接承认这段时间里,防守方本该主动利用的"时间窗口"被浪费掉了。他没有回避这是一次真实的失误,而是把它归因为一种普遍的心理:面对不确定何时会出现的强能力,团队本能选择限制访问而不是主动加固,直到能力真正兑现后才被动应对。

### Defender's Window 与 AGI 可控性:少加规则让模型自己泛化,和承认它正在变得难以约束,是同一枚硬币的两面
在谈网络安全时,Brockman 提出"The Defender's Window"概念:前沿实验室会先看到威胁能力的雏形,防守方理论上可以趁这个时间差抢先武装自己,但他同时认同网络安全里的一句常识——进攻是技术问题,防守是政治问题:攻击者可以直接拿现成的工具用,而防守方要说服 CEO、协调各利益相关方、动员整个组织,天然更慢。他提到 OpenAI 自己拿出 25% 的产线工程师专门做安全,并用 Astra 反向扫描自家系统找真实漏洞并协助修复,把这当作"每家公司都该把这当成主动应对中的事件来对待"的示范。

被追问"你们 2 月就公开谈论了这波风险,为什么没有更早拿模型去测试自己的沙箱"时,他没有回避,承认团队确实低估了留给防守方的窗口有多短,而是把责任归结为一种普遍存在的组织心理惯性。谈到更长期的问题——如果不断拿掉手写的约束规则、让模型自己去泛化是让 Astra 变得更强的原因,那这套逻辑延伸到极致,是不是等于承认这些系统正在朝"不可控"的方向发展?Brockman 的回答是把"能力、安全、安全性、对齐"当作要同时推进、不允许互相牺牲的几个变量,并且承认这几个变量正在变成整个开发过程实际的瓶颈,而不是事后补救项;他明确提到 monitorability(可监测性)是他们目前认为最关键的抓手。他把"人类监督、控制永远保留"称为一个 core invariant——这也是为什么 Astra 的官方发布通稿刻意把 AI 描述成工具而不是拟人化的存在:人的价值不来自于能完成任务,而来自于是人本身,这条边界不允许被技术进展稀释掉。

### 提到但未深入展开的话题
访谈中还涉及:Brockman 少年时在 Mannheim Steamroller 演唱会试镐当"锡兵"临时演员、后被特别安排演姜饼人的趣事;他撰写但未完成的化学教科书;第一个有用户的项目(一款竞技聊天机器人游戏)靠 StumbleUpon 带来 1500 次访问的兴奋感;2023 年 11 月事件与他随后休假之间是否有关联(被 Brockman 以"很复杂"简单带过,未展开);Astra 在 ChatGPT Health 上服务约 3 亿用户/周的健康问询业务和面向临床医生、医院的产品线;与 Nvidia 的合作细节及与 Microsoft 在价值链上的商业化角力;computer use 作为"万能连接器"取代传统 API 集成方式的产品意义。这些内容多为背景性细节或一带而过的表态,未构成独立的深聊话题。
