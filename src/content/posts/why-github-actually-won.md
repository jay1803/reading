## 概述

这篇由 GitHub 联合创始人撰写的文章，分析了 GitHub 成功的原因。作者认为 GitHub 之所以能成功，是因为它在正确的时间出现，并且具有良好的品味。作者还探讨了 Git 胜过 Mercurial 等其他版本控制系统的原因，以及 GitHub 在此过程中所扮演的角色。

## 主题

-   📅 正确的时间：
GitHub 出现时，分布式开源版本控制工具开始变得有用、稳定并被采用，但当时并没有人认真地（更不用说商业化地）托管它们。大型托管商并不关心，而较小的参与者也不够认真。

-   🧑‍💻 品味：
其他托管商专注于分发和收入流，而 GitHub 关心开发者。GitHub 的联合创始人都是以产品为中心的开源软件开发者，他们关心开发者体验，并有创造力去抛开关于它应该是什么样子的假设，并构建他们想要的工作方式。其他人则试图构建他们认为可以卖给广告商或首席技术官的东西。

-   ⚔️ Git 胜出：
作者认为 Git 胜出的原因有两个：Linux 和 Linus 的推广以及 GitHub 和 Ruby 社区。Linux 项目使用 Git 和 Linus 发起该项目为 Git 提供了即时的可信度。同时，Ruby 社区迅速接受了 GitHub，使得每个会议演讲都有 GitHub 的推广 。

-   🤝 社区推动：
Ruby 社区在早期就接受了GitHub，几乎所有的 Ruby 社区的人都在 GitHub 上发布他们的东西。 因为当时 Rails 很热门，每个人都在关注 Ruby 社区的开发者们在做什么，他们是软件世界中很酷的开发者，他们在用 GitHub。Linus 本人也曾提到，Ruby 社区出人意料地让 Git 在一夜之间爆发。

-   🆚 与 Mercurial 的竞争：
Mercurial 在很多方面与 Git 相似，甚至在很多方面更好，但 Git 最终胜出。作者认为，GitHub 在托管领域的统治地位在短短几年内就击败了 Mercurial。截至 2008 年 12 月，GitHub 托管了大约 27,000 个公共存储库，而 BitBucket 只有 1,000 多个。

-   🏢 公司倒闭：
在 2006-2007 年，人们首次了解分布式版本控制系统，Git 和 Mercurial 开始竞争。2008 年，GitHub 推出。2011 年，Google Code 和 BitBucket 都增加了 Git 支持，这标志这 Mercurial 的棺材钉上了钉子。Git 赢了，GitHub 现在基本上是不可战胜的。仅仅 4 年后，到 2015 年，Google Code 完全放弃并关闭了服务。

-   💰 融资问题：
作为旁注, 文章中提到“VC 投资对联合创始人来说不是一个选项”，这是完全不正确的。从一开始就在和 VC 谈判。
