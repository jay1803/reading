AI agents 正在让普通用户获得自行改造软件与工作流的能力，而 Apple 围绕权限、应用和封闭生态建立的控制体系，正在与这种个人计算的未来发生冲突。Ben Thompson 的一台 Mac Mini 遭入侵，使这个矛盾变得具体：限制软件访问的安全机制迫使他频繁使用远程桌面，远程桌面的漏洞成为攻击入口，最终发现入侵、协助排查的却是持续运行的 Claude。

这台始终在线的 Mac Mini 只运行 Claude 和 Codex，与 Thompson 的日常数据隔离。他为同事开发的 Gecko agent 权限受到刻意限制，自己真正依赖的助手则是一条长期运行的 Claude Code 对话，负责记录想法、追踪项目，并通过状态看板和 Telegram bot 接收交互。他选择 Claude，是因为它在 Code 环境中更能处理跨主题讨论，也更能按要求记录信息；其 monitoring tool 可以持续监听输入，但每隔 30 分钟就会停止，因此 agent 会定时重启监听。正是一次例行重启暴露了异常。

Claude 发现，每个新 shell 都会读取的 /etc/zshenv 被植入启动钩子，调用 /var/tmp/.xmr，以 root 权限下载并运行挖矿程序，将收益发往外部钱包。两个文件均归 root 所有，日期被改成 1969 年 12 月 31 日；脚本中的中文注释提及此前批次，指向自动化攻击活动。Claude 随即停止执行命令，没有删除或改动现场，并提示账户已能免密码运行管理员命令。Thompson 没有采纳它“不要再调用 Claude”的建议，继续让它排查，最终把入侵时间定位到四秒钟的窗口，创建后续监测工具，再将 Mac Mini 清空重装。整个过程发生在他读到相关漏洞报道之前，说明持续驻留的 agent 除了引入访问风险，也能提供主动发现异常的能力。

攻击利用的是 macOS 屏幕共享漏洞 CVE-2026-65400，严重性评分为 7.1，涉及状态管理缺陷，可让没有凭据的攻击者取得访问权限。荷兰 NCSC 已发现多台向互联网开放 5900 端口的系统遭利用，攻击者取得 root 后植入 Monero 矿工。Apple 为 macOS Tahoe、Sequoia 和 Sonoma 发布了补丁。Thompson 承认，自己应该通过 VPN 访问远程桌面，此后会依赖 Tailscale；但他认为，必须不断连接远程桌面批准权限，本身就是 macOS 对无头 agent 主机支持不足的结果。

Mac 原本具备成为优秀 agent 主机的条件：长期积累的脚本、自动化与辅助功能 API，经过认证的 Unix 系统，以及出色的硬件，让 agent 既能操作图形界面，也能调用丰富的命令行工具。障碍来自 **Transparency, Consent, and Control（TCC）**：它逐应用管理摄像头、Desktop、Downloads、网络共享等资源的访问权限，确认框又位于普通软件无法观察的受保护空间。对有人坐在屏幕前的主力电脑，这套机制尚可应付；对依靠其他电脑和手机操作的常开主机，程序可能因权限受阻而无声失败，agent 却无法判断原因，只能等用户远程登录点击“允许”。

这种权限模型还与 agent 的工作方式错位。Agent 会不断生成新程序，按每个程序重新授权，就会反复遇到同类阻碍；Thompson 想要的是面向 agent 的授权层，让获得信任的助手能够统筹它生成的工具。保护确认框不被用户态软件读取有明确的反恶意软件理由，但在专为 agent 部署的机器上，这种保护也造成了新的操作负担。他几乎每次开启屏幕共享都是为了点击早已不再认真审视的确认框。这里的风险链条是：繁复的授权要求催生持续远程访问的需求，而未经 VPN 隔离的远程访问扩大了攻击面。

安全更新的表述进一步损害了他的信任。他已在所有电脑上勾选自动安装安全更新，却直到此次入侵才意识到，按文中所述，大多数 CVE 修复随 macOS 小版本更新分发，不在他以为已经开启的自动安装范围内，此次修复也如此。他承认没有及时安装小版本更新是自己的责任，但认为设置名称造成了诚实且可预见的误解：Apple 要求用户为访问一个网络共享明确授权，却没有按用户对“自动安装安全更新”的理解完成修补。随着系统要求用户交出更多控制权，这种承诺与实际行为之间的落差也更难接受。

Apple 随后宣布将为 Full Disk Access 增加更明确的用户操作要求，理由是一些开发者借此暴露文件、邮件、消息和浏览历史，甚至影响通信另一方的隐私，自治能力增强的 AI agents 会进一步放大风险。Thompson 接受这些风险确实存在，却担心 Apple 逐步取消用户主动承担风险、决定如何使用自己电脑的空间。有些用户恰恰希望 agent 读取 iMessages；对他们而言，把 Mac 管理得越来越像 iPhone，会削弱个人电脑作为可自主支配工具的价值。

同样的分歧延伸到了智能家居。Mark Gurman 报道，Apple 计划于 10 月 13 日推出代号 J490、约六英寸方形屏幕的家庭中枢，并更新 HomePod mini 和 Apple TV，以新版 Siri 控制温控器、门锁，承担视频通话、对讲、音乐和照片展示。Thompson 对这些产品缺乏兴趣，既因为多年 Siri 体验带来的失望，也因为他不愿把 Apple 的约束引入更多生活场景。即使 Siri 本身足够优秀，最终体验仍取决于第三方设备厂商的软件质量与集成意愿，容易受生态中最薄弱的环节限制。

他更期待自行掌握软件层，甚至正在搭建小型家庭电子实验室，制作由自己的 agent 控制的设备。AI 降低了编写、修改乃至逆向现有软件的门槛，文中提到的游戏反编译与跨平台移植潮就是例子。这使用户能够围绕自己的 agent 定制交互，无须等待 Apple 提供合适 API，再等待设备厂商完成支持。Apple 宣称有 30 万款 apps 能与 Siri 配合，仍意味着开发者必须逐一投入集成工作；能够直接使用浏览器的 agent，则可以绕过许多专门集成，操作已有的网络服务。

由此产生的竞争涉及整个交互范式。Apple 的“Intelligent Personal Hub”仍以现有 apps 为中心，让 AI 帮用户更新日历和提醒事项；Thompson 更希望把任务直接交给 agent，由它在需要时主动提醒，减少用户在不同界面间切换。对他而言，agent 是处理数字事务的 **Universal Interface**，继续围绕 apps 做集成会保留许多原本可以消失的摩擦。他因此看好 Meta 的 Muse Gadgets 开源计划：培育设备生态可以让 Muse 成为控制一切的入口，回报无需依赖设备销售。虽然他本人更愿意自建 agent，这种围绕统一入口组织硬件的方向仍比 Apple 的应用整合更有吸引力。

Paul Graham 在 2005 年的《Return of the Mac》中认为，优秀 hackers 转向 Mac 的意义远超这个小群体的购买力，因为他们今天的计算方式可能在十年后成为大众习惯。Thompson 在 2004 年转用 Mac，最初看重设计、界面和 GarageBand，后来受益于其稳定性与 Apple Silicon 的性能；如今 AI agents 让缺乏传统编程能力的人也能成为 hacker，只要有想法和行动意愿，就能为自己构建工具。获得这种能力之后，封闭生态的限制会变得更加突出。

Thompson 没有预测 Apple 衰落，也没有立即更换电脑和手机，但他第一次能想象自己不再默认购买 Apple 产品；在入侵发生前，他已经买好下一台运行 Linux 的服务器，并决定不再把 Mac 放进机架。真正的战略问题是，当 agent 抽象掉传统界面，又让个人定制软件变得普及时，Apple 为大规模统一体验建立的产品体系，能否容纳用户按自己的想象构建计算环境。
