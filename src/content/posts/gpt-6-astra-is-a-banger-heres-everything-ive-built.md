## 嘉宾背景

Claire 是 How I AI 的主持人。本期她以获得 GPT-6 Astra 提前测试权限的使用者身份，展示自己在软件开发、业务运营和个人项目中的实际体验。她与合伙人 Zack 分工跟进新业务的客户线索，同时开发产品情报功能，也为自己的孩子制作家庭应用。节目图片与缩略图通常由设计师 Naomi 制作。

## TL;DR

Claire 对 Astra 最兴奋的地方，不是它替她更快写出同样的代码，而是她终于能完成那些目标早已明确、却反复被旧模型卡住的项目：从产品情报系统，到没有公开 API 的小设备，再到给孩子使用的 3D 世界。与此同时，她发现复杂图形界面未必需要被 CLI 或 MCP 取代，因为模型已经能直接操作其中的节点、字段和布局。她展示的成果仍有需要修正的错误，但这没有妨碍她开始尝试过去自己做不出来的东西。

## 可靠的计算机操作能力让现有软件界面从自动化障碍变成了通用执行层

Claire 认为，Astra 最明显的进步之一，是终于能较好地处理复杂网页中的节点和交互。她与 Zack 用 CRM 工作流分配客户线索：大型企业主要由她负责，技术型初创公司主要交给 Zack，分配结果再进入不同的 Slack 通知和 CRM 属性。她自己曾在节点编辑器里折腾一个小时，仍被 AI 返回对象与后续字段的衔接卡住；于是，她直接要求 Codex 操作 Chrome，在现有流程中增加按负责人署名的个性化邮件，包含预约链接和希望与对方交流的原因。演示中，模型开始修改生成对象、补充收件人与邮件内容等字段，并处理节点连接，而不再需要她逐项拖拽和输入。

同样的能力也出现在创意工具里。她把三张新照片交给 Codex，让它参考 Flora 中已有、但组织得相当凌乱的缩略图流程准备素材。模型导入照片、创建节点、选择图像模型和宽高比，并依据原有提示词生成图片。节目后段，设计师要去开会，她又让模型直接操作 Figma，把素材排成当期节目的缩略图；她表示，过去一直没能让 computer use 很好地使用 Figma，这次却做出了可以继续打磨的结果。

她还把浏览器操作用于软件 QA。在一次处理聊天体验、流式输出持久化及竞态条件的改动后，她要求 Astra 打开预览分支测试。模型发送聊天、刷新页面、查看控制台和错误日志，持续运行约一小时四十五分钟，并发现和修复了一些导航及竞态相关问题。对她而言，这些案例改变了此前围绕"下一代交互不需要 UI"的想象：如果产品本来就适合通过图形界面表达，AI 如今也可以替人操作按钮，不一定非得另走 CLI 或 MCP。

## 自动化正在把人的职责从机械执行推向目标设定、监督与审美判断

Claire 对人机分工最具体的描述，来自缩略图制作。Naomi 原本需要反复拖动节点、设置参数、输入提示词，再把普通录制照片处理成节目惯用的发光视觉风格。Claire 认为，这些工具仍然受益于图形界面，但不必由人亲手完成每一次输入和拖拽。她说，原本需要大约一小时的缩略图相关工作，如今可以在几分钟内免手动推进；设计师仍需判断图片是否好看，脸是否变得奇怪，有没有多余手指或令人不适的失真。

CRM 场景则保留了另一种人工检查：她设想先把以自己或 Zack 名义生成的邮件草稿送到 Slack，由他们审阅、复制并发送，而不是立即让智能体自动联系客户。直接发信是她打算在确认效果足够好之后再开放的下一步。自动化已经开始承担流程配置和内容准备，但是否可以进一步放手，仍由她根据结果决定。

她把这些变化放在 token 支出与实际回报的关系中理解：在使用模型不断花钱的情况下，她认为厂商会越来越强调节省时间、完成实际工作的价值。她自己的例子不是让设计师不再参与，而是在设计师暂时离开、节目又需要尽快发布时，先把素材和版式推进出来，再由人检查和润色。

## 真正的模型跃迁体现在它能跨过长期存在的质量瓶颈，而不只是提高基准分数

比起官方成绩，Claire 更看重 Astra 是否能解决她反复尝试却始终没做好的具体工程问题。其中最重要的是产品情报系统：从 Intercom、Granola、Linear、GitHub 等来源收集信息，识别趋势和机会，并自动形成描述产品当前状态的 wiki。困难不仅是把数据接进来，还包括决定哪些内容应持久保存、怎样处理与去重洞察，以及如何生成 wiki 并对照外部来源验证。

她强调，自己并不是无法说明想要什么，也不是完全不知道系统应如何组织；问题是，旧模型作出的架构和实现决策，最终总会导致不理想的结果。有的模型在架构上走偏，有的则卡在洞察质量上。她已经把这类任务交给多个模型反复尝试了很长时间，这次才让 Astra 接手已有分支修复。

按她的描述，Astra 第一轮就完成了约九成，之后又经过两三次提示和少量界面打磨，系统终于运行起来。它能够列出产品负责人应优先处理的问题，例如聊天停滞、自助取消失效，以及客户对本地部署 JIRA 集成的需求，还能展示趋势与机会。她尤其满意自动 wiki：系统读取 GitHub 和文档，整理现有功能、近期变化、客户背景和待修复事项，并通过 MCP 暴露这些信息。她认为，真正的突破不是又生成了一批代码，而是终于从同一组复杂数据中得到了此前模型始终没能达到的洞察与整理质量。

## 更强的编码能力首先扩大的不是产量，而是使用者愿意尝试的项目边界

Claire 用 Divoom Mini 2 形容自己长期攻克不了的"Everest"。这台小型蓝牙设备带有专有软件，没有公开 API；她此前费了很大力气，才借助旧模型实现最基础的显示操作，逆向像素处理也并不容易。Astra 则为它建立了可实时连接的应用，让她通过鼠标绘图、输入文字并把内容传到设备上，还制作了供智能体调用的 CLI。演示中，Codex 查找最新一期 How I AI 的内容，将节目介绍和动画传到设备；她还把设备接入 Codex hooks，让它在 Codex 需要她处理事情时发出提示。她说，下一步才是尝试 root 设备。

另一个项目是把正在运行的 Codex threads 包装成 AIM 风格的 Mac 应用。不同线程成为好友列表中的不同"联系人"，她可以打开对话、查看消息，并设置自己的昵称与离开状态。她很喜欢这种把 Codex 当作 AIM 好友来聊天的方式，也鼓励观众不只生成普通网站，而是尝试制作自己过去没有能力实现的桌面软件和交互方式。

她的个人测试还包括复刻 Barbie Fashion Designer 式的换装体验。她早在 GPT-5 之前就反复尝试过，但对旧模型的结果很不满意；这次用 Astra 和 Blender 做出了能够更换服装、配饰、发型与肤色，并让角色走秀的版本。更令她满意的是家庭应用：她只要求把原来的作业奖励应用改成可探索的 3D 旅程，模型就生成了能用键盘移动的世界，孩子可以去图书馆登记阅读二十分钟、领取奖励，也可以到 Moonwater Pond 表达当天的情绪。她表示自己没有编写这些代码，也无法独立做出这样的体验；这让她尤其期待为孩子和个人需求制作软件的可能性。

## 一次生成的原型已经足以开启新产品空间，但离无需人类修正的成品仍有明显距离

Claire 多次用"one-shot"表达惊喜，但她也展示了这些成果尚未完成的部分。AIM 风格应用在演示中因为线程已有 active writer，没能接受她的新消息；她当场称这是一次生成版本中的小错误。Barbie 换装游戏虽然比旧结果进步明显，裤子的造型仍未做好，鞋子也不理想。她认为人体 3D 渲染更难，并承认其他人会做出比这个更好的游戏。

这些限制也贯穿业务和内容制作：Flora 生成的图片仍需要人检查脸部、手指和整体观感，Figma 排出的缩略图可能还要润色，产品情报系统则并非严格意义上一轮完成，而是首轮达到约九成，再靠追加提示和界面调整变得可用。她在总结时仍把 Astra 选为日常主力，因为它已经能完成那些此前一直做不好的任务；她的兴奋与这些未解决的细节同时存在，而不是认为每个演示都已经是无需修改的成品。

## 提到但未深入展开的话题

Claire 简要转述了 OpenAI 对 Astra 的定位，以及 Frontier Math、Automation Bench 和编码基准上的成绩；介绍了先向具有 Daybreak 权限的企业客户开放、随后向 Plus、Pro、Enterprise、API 与 AWS 推出的安排，并提到每百万输入 token 10 美元、每百万输出 token 50 美元的价格。她也提到团队已从 Nano Banana 转向 GPT Image 2、YouTube 缩略图偏好的视觉风格，以及 AIM 和 Barbie Fashion Designer 的怀旧背景。对于模型的整体交互体验，她觉得它不烦人，速度有些慢但可以接受，并计划后续进行模型横向比较和盲测。
