## 压缩率下限与 LLM 训练损失是同一个公式

压缩器和 LLM 的核心任务相同：**对下一个符号给出尽可能准确的概率分布**。Google DeepMind 2023 年论文明确指出，language modeling 与 compression 是"同一件事的两种视角"。两者共享的核心公式是香农熵 `−log2(P)`：它既是表示一个符号所需的最少比特数，也是 LLM 的 cross-entropy loss。训练 LLM 时降低 cross-entropy，等价于提升压缩模型的预测质量、降低每符号平均比特数。

### 压缩器的三层结构

真正的压缩依赖**冗余**而非丢弃信息（minification 移除人类可读元素，不属于此范畴）。现代压缩工具的三个核心组件：

- **变换（Transform）**：预处理，增加后续可利用的冗余（如 run-length encoding）
- **模型（Model）**：为每个符号生成概率表；模型质量直接决定压缩质量
- **熵编码器（Entropy Coder）**：以概率为输入，产出最终比特流；本身是固定算法，无可调旋钮

### 算术编码与香农熵下限

算术编码将整个数据集编码为 `[0,1)` 内的单个小数——每编码一个符号，就按其概率缩小当前区间，区间越小所需精度越高、比特数越多。公式 `−log2(P)` 给出该符号理论最小编码成本：

- 字母 U 在英文中单独出现的概率 ≈ 0.028，需 5.16 bits
- Q 之后的 U 概率 ≈ 0.999，仅需 0.001 bits

香农熵 = 所有符号 `−log2(P)` 的加权平均，是无损压缩不可突破的理论下限；概率分布越偏斜（最高概率越集中），熵越低，可压缩空间越大。

### 上下文模型显著降低熵

仅依赖符号频率的零阶模型概率分布平缓；引入前一个符号作上下文（order-1 模型）后，条件概率大幅偏斜。对 "TO BE OR NOT TO BE" 实测：无上下文压缩为 ~47 bits，order-1 模型压缩为 ~21 bits，节省超过一半。order-N 中 N 越大，上下文越丰富，预测越准，熵越低。

### LLM 就是压缩的模型层

LLM 接受已有 tokens（上下文），输出下一 token 的概率分布——这正是压缩器"模型"层的功能。差别只在：压缩时已知真实下一符号，只需查询其被赋予的概率并编码；而生成时才需要从概率中采样。

实证：GPT-2 将狄更斯引语压缩至原始大小的 **10%**（176 bits），而 order-1 模型仅能做到 **24%**（434 bits）。模型越强，概率预测越准，每符号所需比特越少。

### LLM 为何未被实用于日常压缩

压缩要求编解码两端持有**相同模型**：gzip 的内置模型极小，浏览器与服务器开销可忽略不计。LLM 动辄数十亿参数、多 GB 存储，每次 HTTP 响应都需两端各持 LLM 并耗费大量算力做推理——即便对远超 LLM 体积的数据集，天文级计算成本仍使其不现实。LLM 的压缩率优势被模型本身的传输与计算代价彻底抵消。

### 背后的同一件事

算术编码在 1970 年代末已能逼近香农熵下限，现代熵编码器的竞争已转向速度与内存，而非压缩率。压缩领域真正的开放问题是：**如何让模型更好地预测，从而降低熵本身**。LLM 的训练目标（最小化 cross-entropy）就是在做这件事。两者——压缩算法和语言模型——都是预测器，是同一套底层数学的两种工程表达。
