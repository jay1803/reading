MKT1 的三人团队把 AI 工作流从各自电脑和 Claude 账户里的个人配置，改造成同事能接手、电脑关机后仍能运行的共享系统。Emily Kramer 用两个问题检验这套系统：一个人或一台电脑离线时，工作能否继续、别人能否修改流程；换一台新电脑时，个人技能、例行任务和工作资料能否迅速恢复。夏天的休假与换机暴露了原有流程过度依赖个人设备的问题，促使团队在八月把技能迁入共享仓库、将重要例行任务尽量移到云端，并把工作所需的数据放进团队本来就在使用的工具。她给改造后的"休假测试"打 A−，给"新电脑测试"打 B+。

这套投入支撑着一个全职、两个半职的 Gen Marketer 团队：Kramer 主要负责构建、写作和决策，Halley 负责多数内部系统与订阅者工具，Katie 负责合作、后台运营及招聘。她们通常每月发布两期 newsletter、20 多条社交帖、10 多张图片、5 个以上视频、10 多项新增或大幅更新的 MCP 技能，并为招聘板核验约 200 个职位，同时处理合作、活动、网站与订阅者支持。Claude 承担研究、基础编辑和重复流程；内容主体仍由人写。Kramer 的判断是，AI 更适合接管琐碎、重复的工作，写作与设计等需要手艺判断的环节仍要有人把关。

团队统一在 Claude Code 中构建技能，但三人日常各自混用 Claude Chat、Cowork 和 Code，也各有独立的 Claude Max 账户。她们通过两个 GitHub 仓库共享能力：内部仓库 Team-Dino 存团队流程，另一个存面向订阅者的工具和 MKT1 MCP；每人还有个人仓库用于换机恢复。仓库以插件形式装在三人的机器上，使技能有共同的存放和修改位置。不过，**推送代码不等于插件已经刷新**：Claude 会保留本地副本，因此她们安排至少每日刷新的例行任务，发布者也会在发布后同步自己的插件。30 多项定时任务分布在三人的账户中，重要任务优先放到云端；本地任务虽能访问电脑上的文件和工具，电脑休眠后却无法继续运行。

她们起初把大量业务资料写进技能，每次运行再通过 MCP 从各工具抓取数据，后来发现长技能增加读取成本、其中的数字难以及时维护，反复抓取大量无关数据也容易耗尽使用额度。现在，**技能主要记录操作指令，业务数据留在可由团队维护的原工具中**：Airtable 和 Attio 保存订阅者、招聘板及研究数据，Asana 管路线图、日历和成员请求，Google Docs 与 Drive 存对外文档，Obsidian 存 newsletter 等内部草稿。技能需要某项数据时才通过 MCP 读取对应资料库。一项"sources-of-truth"技能说明每类数据在哪里、应使用什么工具，避免 Claude 自行猜测；跨技能都要遵守的语气、设计、技能编写和敏感数据规则，则由技能及 CLAUDE.md 引用。

她们在两个仓库中已有 100 多项内部技能，另向订阅者发布了 40 多项 MCP 技能。Newsletter 流程里，Kramer 在 Obsidian 起草，Claude 按写作规范编辑同一文件，发送前检查链接、赞助文案和 SEO 描述，发布后再更新 MCP 索引、网站横幅并通知相关人员。招聘板更能体现技能之间的交接：每周从 Airtable 中的公司名单检查招聘页，将职位分为 Approved、Not Approved 或 Flagged，有疑点的先通知人审核；每两天复查上线职位的链接并撤下已关闭岗位；付费订阅者提交的岗位每隔数小时核验链接、标题和地区，进入同一资料库；每周三个早晨生成职位推广草稿，最后由 Katie 发到 LinkedIn。这样，一个对外产品的大量日常运转可以自动完成，例外情况仍留给人处理。

共享技能越多，维护本身越需要流程。MKT1 用构建技能询问需求、生成文件，并检查本机、两个仓库及 MCP 中是否已有重复能力；发布前用真实输入做三次评估，对照理想结果修改。统一的发布技能再按去向执行不同检查：内部发布要更新版本、同步插件并清理旧缓存；面向订阅者的发布还要清除内部信息、排除订阅者无法访问的依赖，并在 Claude Code、Chat、Cowork 中测试。使用中发现的错误和新规则会先提出修改，经人同意后写回原技能；每周的会话、重复技能与仓库审计，以及每月的 CLAUDE.md 审计，则用来发现遗漏和过时规则。定时任务也只负责按计划调用共享技能，不把完整指令锁在某个人的账户里，以便别人重建或接手。

Kramer 是这套系统的负责人，但三个人都能构建和改进技能；待建项目同时记在共享仓库与 Asana，技能进入面向订阅者的 MCP 前，还会由没有参与构建的同事试用。技能更新、招聘板审核结果、日历日期变更和支持工单状态会进入 Slack，让团队能看到自动流程做了什么。对于需要跨模型使用、避免插件副本过时、访问成员未分别连接的数据源，或统计技能使用情况的团队，MKT1 认为 MCP 比仓库插件更合适。她们的 MCP 由 Cloudflare 持续运行，GitHub 推送触发重新部署；连接时依据 Airtable 订阅者资料判断免费或付费权限，每小时与 Substack 付费状态核对，并记录活跃用户、安装、调用量和热门技能。面向近 2,000 名订阅者发布技能，也使内部流程经过改造后成为可以交付给外部用户的产品。

MKT1 从二月的少数技能发展到 100 多项技能、30 多项例行任务，关键变化是把个人会用 AI 做事，推进到团队能共同维护 AI 工作系统。Kramer 建议先检查团队最依赖的三个流程：创建者休假、电脑关闭时，它们是否仍能运行；其他人是否找得到数据和指令，并有能力修改它们。能通过这项检验，自动化才真正成为团队能力，而非某个人电脑上的积累。
