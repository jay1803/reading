## TL;DR
AI 把客户端—服务器关系从“本地计算+远端数据”的厚客户端时代，重新拉回“终端只负责连接，核心能力都在数据中心”的薄客户端时代。聊天和 agent 的意义不只是交互更自然，而是把大量曾经依赖本地 UI、设备性能和用户工作流熟练度的价值，转移到云端推理、上下文记忆和共享基础设施上；这会削弱传统软件 UI 的护城河，也让个人设备在继续涨价的同时变得更不重要。

## 关键洞察
厚客户端曾长期胜出，因为 PC、手机和 SaaS 浏览器都把交互和大量计算留在本地，服务器主要提供数据与同步；Sun 当年的 network computer 失败，也是因为本地设备足够便宜、足够强，而且 Windows 已经形成压倒性标准。AI 改变的是界面与计算的分工：对聊天式 AI 来说，决定体验的关键变量是远端模型质量，而不是本地 UI 复杂度；自然语言接口还会抹平专业软件靠界面训练、路径依赖和肌肉记忆建立的高切换成本。再往前走，agent 把“使用软件”推进成“委托任务”：用户只提交目标，中间步骤理想状态下全在服务器端消化。

要让这种模式成立，瓶颈也很清楚：更大的模型、更长的上下文、更稳定的 agent 编排，都在把需求推向拥有最多算力、HBM/DRAM/闪存层级内存和最高利用率的大型数据中心。技术规律与经济规律在这里同向：最强推理集中在云端，昂贵算力也只有被数百万用户共享时才最划算。作者因此把内存短缺视为决定性的现实约束：AI 正在抽走供应链、资本开支和硬件路线图中的优先级，结果是 PC、手机、主机等个人设备都会因内存涨价而更贵，甚至推迟换代；与此同时，这些厚客户端的性能提升已经越来越接近边际递减，对多数任务来说现有设备早已够用。于是 AI 一边抬高个人设备成本，一边削弱个人设备的重要性。本地推理未来仍可能回潮，但短期内受模型规模、上下文管理和内存成本限制，很难与云端竞争；等本地方案成熟，很多工作流可能已经沿着云端 agent 的路径固化下来。真正值得观察的，是哪些业务流程会从 UI 迁移到 AI，哪些地方仍需要精心设计的界面来约束动作、降低错误并承载企业流程。

## 一句话总结
AI 的基础设施效应，不是让每台设备都更聪明，而是把智能重新集中到数据中心，让“连接到最强计算”比“拥有更强终端”更重要。
