## TL;DR
用 LLM 替你写作，比抄袭还糟——抄袭至少传达了另一个人的真实想法；LLM 没有想法，发布它的输出相当于把你的 prompt 稀释成废话后再端给读者。作者的核心挑衅：**我宁愿直接看 prompt**，因为 prompt 才是你真正想说的那件事，生成物只是它变薄后的影子。

## 核心主张拆解
写作的唯一目的是传达**原创想法**。用 LLM 写的人有三类：①认为这件事不值得认真对待（学生应付作业、研究者敷衍审稿）；②认为 LLM 能写得比自己好（多见于非母语者和初级程序员）；③纯粹出于商业目的（客服机器人、食谱博客开场白）。①②都指向同一个错误：把写作当成要交付的产物，而不是思考本身的载体。

编程是最具体的反例。Peter Naur 的"Programming as Theory Building"指出，有效的程序要求程序员对代码背后逻辑有完整理解——不只是代码本身。Vibe coding（全靠 LLM 生成代码）产生的程序是死的：没有 theory，没有人真正理解它，安全漏洞必然涌现。泄露 OpenAI key 的 vibe-coded recipe app 不是意外，是结构性必然。

## 反驳或薄弱处
**证据薄弱处**：作者让 Gemini 续写自己的论文导语，用 234 词回声作为"LLM 很无聊"的证明——但这个示例是他自己设计的，选取了最容易失败的任务（续写已有论点）。对辅助校对、翻译、格式化、或"帮非母语者让语法更地道"这类更弱的主张，他完全没有正面回应，而是直接把批评泛化到"没有任何好理由使用 LLM 进行创意表达"。

## 留下的那个想法
如果你把 prompt 保留、把 LLM 的输出扔掉，你实际上什么都没损失——有价值的那部分从来都在 prompt 里。这个逻辑意味着：**一篇文章值得写，它在你脑子里就已经存在了；你需要的是把它取出来，而不是让机器替你猜它长什么样。**
