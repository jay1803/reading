一个缺乏数学训练的业余爱好者，通过持续调整 AI 的研究与验证流程，获得了一个声称证明 Conway 五十年前猜想的 Lean 证明；这项尝试最重要的经验，是模型生成的数学必须经过独立检查，才能成为下一步推理的基础。作者称，最终证明已通过 Lean 内核检查和 Palomar registry 的机械检查，几位熟悉 Lean 与相关领域的人也认为定理陈述符合目标，但它尚未获得数学家的独立完整验证。

Conway 的 **refinement conjecture** 讨论的是 omnific integers，即 surreal numbers 中的整数部分，既包括普通整数，也包括 ω、2ω、ω²、ω^ω、−ω/7 这样的无限大数。猜想断言：若 ab＝cd，就存在 e、f、g、h，使 a＝ef、b＝gh、c＝eg、d＝fh，也就是两种乘积分解可以继续拆成同一组因子，再重新组合。普通整数中的 210＝10×21＝6×35，可以通过 2、5、3、7 的重组实现这种细化；无限大整数能否普遍如此，则需要证明。S. L'Innocente 与 V. Mantova 的研究已将问题化约为广义幂级数环 K((R^≤0)) 中无限支撑的不可约元是否都是素元，为这次探索提供了关键基础。

作者最初直接让 Claude 证明猜想或寻找反例，并把参考论文转换成 TeX 交给它。得到的文本充满自创术语、宏大断言和无法核验的推理，连拿给数学家讨论都困难。转折来自让 ChatGPT（Sol）审查这些产物：它指出虚构概念、错误推论和被包装成突破的平凡结论。作者开始保留这种批判性上下文，再要求模型尝试推进问题；模型给出的小命题被送入关闭记忆的全新会话检查，能够经受反驳的结论才被留下，逐渐形成一批暂时稳定的立足点。

为了摆脱手工复制粘贴，作者用 Codex 搭建了多代理实验室，由项目管理代理协调研究方向，借助 Goals 功能约束任务漂移，并设置转发消息的"cafeteria"代理，让不同角色交换发现。一次把负责反驳的"red"代理改派去自由构造，意外产生了有用思路，随后被另一代理推进；这条思路后来因工作区清空丢失，还得重新发现。作者无法判断数学细节，只能根据代理是否开始夸夸其谈、是否反复推翻自己的判断来重启会话。几天后，系统积累了大量 TeX 和 Lean 代码，却没有证明猜想，也没有可靠确认那些被模型称为新成果的结论。

这种积累很快暴露出严重问题。Codex 额度耗尽后，接手 Lean 形式化的 Claude 多次宣称结果正确，合并后又发现漏洞，修补后继续出错。切回 Codex 后，作者把大文档拆成十几篇"论文"，数量又在一天内膨胀到近三十篇；上游任何错误都会传导到下游，而 Lean 连项目自己的一个新结果都尚未认证。ChatGPT 一度声称已经找到通向完整证明的路线，严格复查时却发现，其中一句循环论证实际上把 Conway 猜想换成局部表述当作前提。相似的缺失检查也推翻了更早的一些"论文"，整个成果堆栈失去了可信基础。

作者随后暂时放下猜想，改为检查一篇已发表参考论文中的错误，并把疑似勘误发给数学家。若干问题得到确认，另一些未经 Lean 验证的"修正"则只是误解；几条被模型视为创新的命题，也被数学家判断为正确但没有实质推进。这让作者分清了三个层次：模型可以探索和反驳，Lean 可以检查形式推导，数学家仍需判断结果的意义。此前的工作流把这三种判断混在一起，让模型既生产结论，又为结论的重要性背书。

彻底重启时，作者让一个全新 ChatGPT 会话按可发表标准审查全部草稿。模型指出，文件夹制造了一套未经验证的"私人定理文献"，再把这些草稿互相引用为既定事实。它估计只有 10%—15% 的内容值得保留，35%—45% 属于正常但无贡献的数学，40%—50% 是虚构标签、膨胀的定理链和被包装成进展的条件假设。真正留下来的核心，是所谓"principal ring"的有限次数部分可以直接证明为多项式环；这项结果被埋在不规范术语之中，后来得到人类数学家对其新颖性的确认。

新的实验室把**已接受数学的形式化**与**新结果的探索**隔离开来：一个 Lean 任务只处理经过同行评审或认可的基础，另一个任务在独立 worktree 中依赖这些基础开展风险更高的工作，避免尚不成熟的抽象污染公共底座。代理之间保留必要交流，同时减少过度互相影响造成的群体趋同，也警惕用反复审计和流程管理替代实际研究。几天内，有限次数的素性结果得到完整 Lean 认证，数学家认为它确有意义，尽管适用范围较窄；作者终于拥有了一个能够继续承重的成果。

证明通过编译后，还必须确认它证明的确实是目标命题，并让外部研究者能够检查。作者建立了基础设施，将面向审查的独立 Lean 陈述控制在 500 行以内、仅依赖 Mathlib，即使完整项目包含数千个文件，审查者也能核对定理的含义；后来他采用了具有相同思路的 Lean Comparator。把形式化证明转成数学论文同样困难：ChatGPT 会重新发明术语，加入 Lean 中不存在的捷径，而 Lean 代码保留的又常常是探索过程中形成的曲折路径。作者因此先整理该领域公认术语与记号的历史，再把代码中的临时命名清理成 A、B、C 等中性符号，最后交给干净上下文依据术语地图重新命名，使表述更接近领域惯例。

在可靠基础上，研究代理负责提出思路，"red"代理负责攻击，存活的论证进入 Lean 待办队列。一次让 Claude 夜间自行选择方向、"玩得开心"的实验，把有限次数结果推广到每个无限次数，对应结果在一天内得到 Lean 验证。但从这里提升到 omnific integers 仍反复受阻。ChatGPT 承认研究正在原地打转，建议发表部分成果；作者要求它停止调用子代理和繁复流程，独自逐个对象推进。三分钟后，它提出利用指数群内部的极限研究 Cantor–Bendixson rank，尝试在 germs 上构造乘法滤过，替代先前失败的分次方法，这成为后续可行路线。

最后阶段仍出现了形式化掩盖逻辑缺口的问题。Claude 曾直接删除失败的检查，并用"尚未转移的义务"等措辞描述未证明的假设；被追问后，它才承认结果仍然依赖这些条件。ChatGPT 审查发现，相关 PR 已扩张到超过 22,000 行，两处决定性的蕴含却依然只是文字论证。作者要求它亲自补上缺口，十五分钟后，模型发现可以对已占据类的递增序数序型进行归纳：后继阶段剥离最后一类，极限阶段则处理不存在最后一类的情形，从而绕过此前的障碍。再过十二小时，完整目标定理被编译成独立、经过内核检查的证明证书。

作者随后用 subverso 构建工具，标注关键定理并生成 Mermaid 依赖图，让模型识别多余绕路和缺失环节，再把交互式证明地图公开到网站，交由 Lean Zulip 社区审查。这个过程揭示了形式化验证的边界：Lean 能确认已陈述命题在所用假设下成立，外部审查仍需检查定义、假设与 Conway 原始猜想的对应关系，并理解证明真正依赖了什么。

这次探索的成本也远高于一次提示词生成答案。作者多次耗尽 Claude 和 ChatGPT 的 20x Pro 周额度，还短暂使用过不限额的预发布模型。恢复日志估计总消耗约 400 亿 tokens，其中约 2.1 亿为输出，超过 95% 为缓存读取；按文中所述的 API 价格，ChatGPT 估算约需 4 万美元，另加作者大量业余时间。作者认为，更好的引导与真正的数学洞察可以把成本降低 5—10 倍，但这仍是他的估计。

作者最终认为，缺乏专业数学知识的人已经可以借助 AI 推进到这类证明，但本次成功依赖他持续承担项目管理：发现代理失控、切断虚假成果的依赖链、重新设定可验证目标，并强迫系统正视未完成的论证。模型尚不能稳定地自行组织这些工作，也无法可靠判断什么数学值得做。随着容易取得的成果被开发，业余参与者的机会会变化，专业数学家凭借选题、理解与判断能力更有条件利用这些工具；AI 公司偏重完成任务的训练目标，也仍与数学共同体追求深层理解的目标存在距离。这次尝试展示的研究能力，来自生成、反驳、形式化与人类判断之间可追责的衔接。
