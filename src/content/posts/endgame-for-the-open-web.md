## TL;DR
2026 年对开放 web 的攻击不是单一战线——大型科技公司正在用瓦解优步经济的同一套剧本，同时拆解开放 web 的每一根支柱（内容、代码、标准、社区基础设施），且资源不对等到无需协调就能同时推进。这一年是决定开放 web 能否存活的拐点。

## 核心主张拆解
文章列出 8 条并发攻击路径，本质都是「无限资源对无偿劳动的系统性剥削」：

- **出版商**：AI 爬虫每送来 1 个用户就抓取 500,000 次页面；科技媒体流量已暴跌 50% 以上，部分超过 90%。出版商防御性加锁墙反而让公开资源（Internet Archive、维基百科）成为顺带受害者。
- **开放 API**：Musk 关闭 Twitter API 后，60% 以上平台研究项目陷入停滞或终止；开发者生态被消灭，舆论监督工具随之失效。
- **播客**：Apple 转为闭合基础设施要求签约授权合作，Spotify/Netflix 通过市场支配力将创作者从开放 RSS 驱向专有格式——「enshittification」飞轮已启动。
- **开源软件**：AI 代码 agent 批量提交垃圾 PR 淹没大多义务维护者，数十个头部项目已关闭新贡献者通道，顺带封堵了新人入行路径。
- **维基百科**：Grokipedia 分流流量与捐款，同时 AI 平台大量消化其内容却几乎不回送访问；人工流量已显著下降，威胁到维持其运作的志愿贡献与捐款循环。
- **开放标准**：robots.txt 实际死亡；Creative Commons 等社区协议被单方面无视；开源许可证可被 LLM 绕过重写，原始贡献者既无署名也无补偿。

内在机制：这是同一个剧本——在尽可能多的战线同时出击，以无限资金压垮靠志愿劳动维系的开放生态；不需要协调，因为目标一致。

## 反驳或薄弱处
文章最后寄望于「good AI」（引用 Masnick：AI 也许反而能拯救开放 web），但论据一笔带过，未解释社区构建的 AI 为何能抵抗同类技术的攻击；行动号召（捐款给 EFF/Wikipedia/Internet Archive）与"虚无限资源"规模之间的不对称也未被正面处理。

## 真正危险的不是单次攻击
而是防御性收缩构成的正反馈：出版商加锁墙 → 开放资源缩水 → AI 训练数据质量下降 → 下一轮攻击更强——开放 web 的边界正在从内部开始塌缩。
