LLM 对特定词汇的偏好正在 GitHub 的代码协作记录中留下可量化的痕迹：**spine** 等词在公开 PR 中的激增，远远超过了 PR 总量增长所能解释的范围。Hillel Wayne 最初注意到，自己今年接触的几份 AI 生成的 TLA+ specifications 都使用了 "spine"；随后，他在其他公开项目中也看到了这个词，于是开始检验它是否已经成为一种 LLM 特有的语言习惯。

这个判断的检验标准是，相关词汇的使用量是否出现了突跃。完整研究可以使用 GH Archive 的数据，但 Wayne 为控制工作量，选择了 GitHub Search：代码搜索无法按日期筛选，PR 搜索可以，因此他用标题含有 "spine" 的公开 PR 数量作为替代指标。按文中截至 2026 年 9 月 1 日的统计，2026 年的数量已达到 2025 年全年的 20 倍；同期公开 PR 总量的增长只能支持约 1.5 倍的增加。这个差距支持了"词汇偏好发生变化"的解释，不过分析没有排除少数仓库或贡献者集中使用该词、拉高整体计数的可能。

月度变化仍不足以把这种偏好归因于某一个模型。5 月出现的明显增长，难以用当月较晚发布的 Opus 4.8 解释；4 月发布的 GPT 5.5 在时间上更接近，却也无法解释此前的趋势：在 4 月之前，"spine" 的数量已经逐月增长约 1.5 倍，Wayne 至少从 2 月就记得见过这种用法。他抽查的许多相关 PR 还将 Claude 或 Cursor 列为共同作者。因此，他倾向于认为这是跨模型的现象，现有数据没有建立具体模型与词频变化之间的因果关系。

相似的增长也出现在 **gate** 上：每 300 个公开 PR 中，就有一个标题包含这个词；如果把搜索范围扩大到 PR 正文，则每 26 个就有一个命中。但扩大范围会引入与开发者实际措辞偏好无关的噪声。"ladder" 在 2022 年曾出现在超过 30,000 个 PR 中，抽样后发现，几乎全部来自 boto3 的自动升级，升级说明反复包含 "ABR package ladders"。这一案例说明，自动化工具复制同一段文本，也能制造出看似显著的词频异常，因此 Wayne 把主要比较限定在 PR 标题。一个没有接触过他分析过程的 LLM，在被要求解释这次异常时，也更快找到了同样的 boto3 原因。

限制到标题后，"ladder" 仍呈现增长，"lane" 也有类似变化，但文章没有验证后者是否与 "CPU lanes" 等既有术语有关。与 AI 领域对 formal verification 的关注相呼应，"proof" 的使用也增加了，不过增幅较小；Wayne 提出的解释是，"proof of work" 等既有用法已经提供了较高基数。"truth" 的增长更明显，而同事观察到 "seam" 越来越常见后，他追加查询，也看到了相应的增长。作为对照，"lamp" 没有表现出超出普通开发者的使用偏好，说明这类异常并非对任意词汇都成立。

这些结果提供了识别 LLM 用词习惯的线索，距离可靠的模型指纹还有一步：既要剔除自动升级、固定模板和集中贡献造成的重复，也要区分技术话题热度变化与模型自身的词汇偏好。Wayne 将用于分析的工具发布为 gist，让其他人能够复现数据并检查方法错误。文章所展示的更广泛现象是，AI 生成文本的影响已经延伸到软件协作的日常语言中，而这种影响可以通过公共记录被观察和检验。
