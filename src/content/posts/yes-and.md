AI 时代依然值得成为程序员，但越是能轻易生成代码，初学者越需要亲手编程，才能获得理解系统、判断代码质量和控制复杂度的能力。Montana State University 的计算机科学教师 Carson Gross 将编程的核心归结为两件事：用计算机解决问题，以及控制解决过程中产生的复杂度。他认为，这两种能力会持续具有职业价值；AI 会改变程序员的工作重心，却没有消除这些基本要求。

亲手写代码是形成代码阅读能力的必要训练。初学者在具体实现、犯错和修改中，才能建立对代码运行方式的切身理解；把作业直接交给 AI，会跳过这一过程。即使未来工作更多围绕审查 AI 生成的代码展开，阅读能力仍然依赖这种实践基础。缺少它，程序员就容易落入 **The Sorcerer's Apprentice Trap**：不断制造自己无法理解、也无法控制的系统。

这也是 Gross 反对把"从编程转向 prompting"类比为"从 Assembly 转向高级语言"的原因。编译器基本具有确定性：对特定计算机架构，高级语言中的 for loop 或 if statement 在优化前会对应怎样的 Assembly，通常可以合理预测；同一条 prompt 经 LLM 生成的实现则缺少这样的确定性。高级语言以更少文本精确表达解决方案，消除了大量 **accidental complexity**，让开发者主要面对问题本身的必要复杂度。LLM 却可能选错方案、走捷径，额外引入偶然复杂度；不能读懂实现的人，也就无法判断这些成本是否已经进入系统。

AI 对初学者最有价值的用途，是担任帮助理解概念、技术和工具的 TA。学习编程时，人经常因为找不到解题切入点而停滞，也可能卡在 toolchain、构建环境等与当前学习目标无关的障碍上。这类无谓阻塞会消耗真正学习的时间，甚至使人离开计算机科学。Gross 自己在 Berkeley 尝试自学 Unix 时就曾陷入困境，这也是他退出当地计算机科学项目的原因之一。他为学生提供了一份 AGENTS.md，将 coding agent 配置成助教，帮助他们越过障碍、理解问题，同时保留必须亲手完成的代码实践。

随着纯粹代码写作能力的相对价值下降，清晰思考、写作和沟通的重要性会上升，因为程序员需要同时向人和 LLM 准确表达意图。Gross 建议通过读书、写 essay 和 blog post 训练这些能力，并把更多精力投入业务及其他现实问题。企业人员看到 AI，可能认为可以省掉程序员；程序员也可能反过来认为可以省掉业务人员。Gross 认为两种想法都短视：AI 更有价值的作用，是让程序员在继续从事技术工作的同时，更深入理解自己究竟在解决什么问题，而沟通能力正好连接这两端。

组织大型系统、控制系统复杂度的 **software architecture** 能力也会更加重要，但它的成长路径恰恰依赖小规模编码经验。开发者通常先把系统的局部做坏，再逐渐学会做得更好，才积累出组织更大系统所需的直觉。Gross 遇到的糟糕 architect，往往本身编码能力不足，或缺乏足够实践；只会提出脱离实现的宏大架构，容易给项目带来痛苦。如果初学者把所有"简单部分"都交给 AI，他们也会失去建立架构判断力的训练机会。因此，架构能力越受重视，亲手编码的学习价值越不能被忽略。

已有丰富经验的 senior programmer 更容易有效使用 LLM，因为他们知道好代码是什么样，也有判断大型系统中哪些事情重要的经验。Gross 自己会让 LLM 分析已有代码、寻找问题和不一致，整理大型项目的思路，生成小段实现、不喜欢写的 regular expressions 和 CSS，以及可以丢弃的 demo 或探索性代码，也会让它建议测试。在手写代码时，他还会借助 LLM 理解外部 API 和可选方案，但尽量避免让它生成自己需要长期维护的完整解决方案，并且从不让它设计自己系统的 API。资深开发者的风险是彻底停止编程，让已有能力逐渐退化；发出 prompt 后等待结果，顺势陷入无休止的信息流浏览，就是他亲身遇到的陷阱。

Junior programmer 面临的压力更直接：同事通过 vibe coding 快速交付，自己坚持理解和手写，可能显得缓慢，甚至受到批评。Gross 承认，若公司优先奖励速度，初级程序员必须适应现实，不能因此丢掉工作；但他判断，这种局面会改变，因为高速 vibe coding 比经过充分理解、审慎完成的代码更容易造成复杂度爆炸。他预期，企业最终会认可 AI 辅助下更稳健的开发方式。对 junior 而言，AI 可以加速理解 codebase、API、构建系统和语言机制，缩短成长为 senior 的道路，但前提是把它当作有时过分热心的助手，同时继续自己写代码；企业也必须为新人保留这种实践空间。

职业是否值得选择，还取决于眼下能否找到工作。Gross 看到优秀的 CS 学生求职受挫，但将当前低迷判断为程序员就业市场繁荣与萧条周期中的一段，并不认为它会永久持续。对正在求职的人，他更具体的建议是减少对在线招聘平台的时间投入：这些平台对 junior 很像彩票，免费投递仍可尝试，却不值得押上大部分精力。更有优势的路径是借助他所说的 four F's——Family、Friends 和 Family of Friends——寻找自己在公司内部有人际连接的机会，而且不必把范围限于 Google 等大型科技企业。

这种求职策略建立在一个更宽的职业入口上：几乎所有超过 100 人的公司都有某种开发团队，即使它不使用这个名称，也存在需要计算机解决的问题。Gross 曾遇到一名找工作困难的学生，得知其家长在 Costco corporate 工作后，指出这正是进入优质公司的重要机会。学生最初可以担任 analyst 或其他岗位，再用编程能力扩大贡献和发展空间，无须把第一份工作的头衔限定为"程序员"。贯穿这些建议的判断是：AI 降低了产出代码的门槛，而长期职业价值仍取决于能否理解现实问题、看懂实现并约束复杂度；亲手写代码，正是培养这些判断力的基础。
